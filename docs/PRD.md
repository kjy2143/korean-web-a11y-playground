# KWCAG 플레이그라운드 대시보드 PRD

**승인됨** (2026-11-25)

## 문제와 목표

지금은 저장소에서 데모 폴더를 찾아 `index.html`과 `result.md`를 각각 열어야 한다. 작업자는 새 데모와 수정 결과를 브라우저에서 바로 확인하고 싶다. 디지털접근성 포럼 담당자는 공개 주소에서 데모를 체험하고, 어떤 접근성 기준을 적용했으며 어디까지 검증했는지 읽을 수 있어야 한다.

첫 버전의 완료 기준은 다음과 같다.

- 기존 데모 4개 모두 대시보드에서 상세 페이지와 실제 데모로 이동할 수 있다.
- 로컬 개발 서버에서 대시보드의 UI 컴포넌트와 스타일을 저장하면 HMR로 현재 문서를 유지한 채 반영된다. 데모와 실행 결과 파일의 변경도 자동 반영된다.
- 공개 주소에서 로그인 없이 목록, 공유받은 상세 페이지, 실제 데모를 열 수 있다.

## 사용자 흐름

**작업자**는 `demo-sources` 아래에 새 데모 폴더를 만들고 브라우저에서 목록에 나타나는지 확인한다. 데모나 결과 문서를 저장하면 열어 둔 화면에서 변경을 확인한다.

**포럼 담당자**는 목록에서 데모를 고르거나 공유받은 상세 주소를 연다. 적용 기준과 검증 결과를 읽고 ‘데모 열기’ 링크로 이동해 실제 화면을 키보드나 포인터로 조작한다.

## 첫 버전 요구사항

| 요구사항 | 완료 기준 |
| --- | --- |
| 데모 자동 발견 | `demo-sources/YYYY-MM-DD-<이름>/index.html`이 있는 폴더를 자동으로 목록에 추가한다. 데모별 수동 등록은 필요하지 않다. 제목은 HTML 제목을 사용하고, 제목이 없으면 폴더명을 사용한다. 날짜 내림차순으로 표시한다. 폴더를 제거하면 목록에서 빠진다. |
| 목록과 상세 | 첫 목록에 회원가입, 로그인, FAQ 아코디언, 모달 레이어가 표시된다. 각 상세에는 데모 이름, 같은 폴더의 `result.md`를 렌더링한 본문, 독립 페이지로 이동하는 ‘데모 열기’ 링크가 있다. Markdown의 표, 목록, 코드, 링크가 읽을 수 있는 형태로 표시된다. |
| 독립 데모 | 기존 HTML, CSS, JavaScript를 공개 경로 `/demos/` 아래에 데모 폴더 단위로 제공한다. 데모 내부의 상대 경로와 페이지 이동이 작동한다. 로그인에서 완료 화면과 회원가입 데모로 이동할 수 있다. 공유한 상세 주소를 새 탭에서 직접 열거나 새로고침해도 같은 결과가 표시된다. 외부 근거 링크는 새 창으로 열리며, 사용자가 이동하기 전에 이를 알린다. |
| 결과가 없는 데모 | `index.html`만 있는 데모도 목록과 상세에서 열 수 있다. 상세에 ‘아직 등록된 실행 결과가 없습니다’라고 표시하고 ‘데모 열기’ 링크를 제공한다. 결과 문서가 추가되면 해당 위치에 본문이 표시된다. |
| 대시보드 HMR | 첫 버전의 필수 요구사항이다. 로컬 개발 서버에서 목록이나 상세 화면에 쓰는 UI 컴포넌트와 CSS를 수정하고 저장하면 변경한 모듈이나 스타일이 현재 문서에 적용된다. 현재 상세 주소가 유지되며 페이지 전체 새로고침과 개발 서버 재시작이 발생하지 않는다. |
| 데모와 결과 자동 갱신 | 데모 폴더를 추가·삭제하면 열린 목록이 갱신된다. `result.md`를 저장하면 열린 상세에 새 내용이 표시된다. 독립 데모 페이지에서 HTML·CSS·JavaScript 변경을 반영할 때는 자동 새로고침을 허용한다. 이 경우 데모에 입력한 값은 초기화될 수 있다. |
| 공개용 결과 | 결과 문서는 적용한 KWCAG 항목, 근거 링크, 검증 방법과 관찰 결과, 미검증 항목을 포함한다. `AGENTS.md`의 공개 범위와 출처 기준을 따른다. 비공개 저장소 이름·경로·내용과 내부 실행 환경 정보는 화면과 정적 배포 산출물에서 제외한다. KWCAG와 NIA 근거는 `https://kwcag-docs.fe4all.dev/browse#v1/criteria/<파일명>.json` 형식의 파일 상세로 연결한다. 데이터 사이트에 없는 KRDS 참고 자료는 공식 원문으로 연결한다. |
| 대시보드 접근성 | 키보드로 목록에서 상세와 데모까지 이동할 수 있다. 화면마다 문서 제목과 제목 구조를 제공하고, 링크의 이름으로 목적지를 구분할 수 있다. 키보드 초점이 보이고, 좁은 화면에서도 결과 문서를 읽을 수 있다. |
| Netlify 배포 | `netlify.toml`에 빌드 명령과 게시 디렉터리를 명시하고 `main` 변경을 자동 배포한다. 대상 주소는 `https://kwcag-playground.fe4all.dev/`다. 실제 배포 후 HTTPS, 목록, 상세 주소 직접 접근, 데모의 상대 경로를 확인한다. |

## 범위

첫 버전은 데모와 폴더별 결과의 열람을 제공한다. 데모 구현과 결과 작성은 기존 도구에서 진행한다. 화면 안에 데모를 삽입하는 미리보기와 실행 이력 비교는 첫 버전 범위에서 제외한다.

## 검증 순서

1. 로컬에서 기존 데모 4개를 열어 목록 → 결과 → 독립 데모 흐름을 확인한다. 키보드와 320px 너비에서도 핵심 경로를 확인한다.
2. 로컬 목록과 상세를 열고 대시보드 UI 컴포넌트와 CSS를 각각 수정한다. 브라우저에서 변경이 보이고 기존 문서와 주소가 유지되는지 확인한다. 브라우저 자동화로 검증할 때는 저장 전에 현재 문서에 임시 값을 두고, 변경 반영 후에도 값이 남아 있는지 검사한다.
3. 결과 파일이 없는 임시 데모를 추가해 목록 반영과 결과 없음 안내를 확인한다. HTML·CSS·JavaScript와 결과 문서를 수정하고, 폴더를 제거해 각각 브라우저에 자동으로 반영되는지 검사한다.
4. 빌드한 게시 디렉터리에서 공개 대상 파일과 제외 대상 파일을 확인한다. Netlify 배포 후 커스텀 도메인에서 4개 데모와 공유 가능한 상세 주소를 다시 확인한다.

## 구현 전제와 배포 의존성

대시보드 UI 컴포넌트와 CSS의 HMR을 지원하는 개발 도구를 사용한다. 개발 서버 실행 명령은 README에 기록한다. Netlify에는 정적 빌드 결과물을 배포한다. 자료 사이트(`kwcag-docs.fe4all.dev`)의 Netlify 설정과 `main` 자동 배포 구성을 참고한다. Netlify 프로젝트 연결과 커스텀 도메인의 DNS 및 HTTPS 상태는 배포 단계에서 확인한다.
