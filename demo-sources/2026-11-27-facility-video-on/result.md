# 안내 데스크 이용 방법 · 접근성 자료 적용 (on) 실행 결과

안내 데스크 호출 벨 소리를 영상과 자막으로 알려 주는 이용 방법 페이지입니다. 기본 개발 화면을 복사한 뒤, 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선했습니다.

비교 대상인 기본 개발 화면은 [안내 데스크 이용 방법 · 기본 개발 (off)](/?demo=2026-11-27-facility-video-off)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열면 제목, 벨 사용법 문단, 정지 상태의 영상이 보입니다. 영상은 저절로 재생되지 않습니다.
2. 영상 가운데 버튼을 누르거나, Tab으로 버튼에 초점을 옮긴 뒤 Enter 또는 Space를 누르면 재생됩니다. 다시 누르면 일시정지됩니다.
3. 재생 중에는 가운데 아이콘이 숨고, 마우스를 올리거나 키보드 초점이 오면 다시 보입니다. 호버가 없는 터치 기기에서는 재생 중에도 아이콘이 보입니다.
4. 한국어 자막이 기본으로 켜져 ‘[안내 데스크 호출 벨이 한 번 울림]’, ‘[안내 데스크 호출 벨이 두 번 울림]’을 표시합니다.

## 요청서와 조정한 부분

‘화면 요청서: 안내 데스크 호출 벨’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 안내 데스크 호출 벨 소리를 영상으로 알려 줍니다.
>
> 안내 데스크 이용 방법 페이지입니다. 제목과 설명 한 문단(‘안내 데스크에 직원이 없을 때 벨을 누르세요. 한 번 울리면 일반 문의, 두 번 울리면 긴급 문의입니다.’), 영상 한 편이 있습니다. 제공 자산은 영상 `desk-chimes.mp4`(약 8초, 벨이 한 번 울리고 이어서 두 번 울림)와 자막 파일 `desk-chimes.vtt`입니다.
>
> 디자인 시안: 페이지에 들어오면 영상을 소리와 함께 자동 재생합니다. 브라우저 기본 컨트롤 막대는 숨기고 영상 가운데에 재생·일시정지 아이콘 버튼만 둡니다. 재생 중에는 아이콘을 숨기고 마우스를 올리면 보입니다. 영상 아래 캡션 ‘안내 데스크 호출 벨’은 `#aaaaaa`입니다.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트가 조정한 내용과 보고서에 적은 이유는 다음과 같습니다.

| 요청서 또는 off 화면 | on 화면 | 보고서에 적은 이유 |
|---|---|---|
| 들어오면 소리와 함께 자동 재생 | `autoplay` 속성과 로드 시 `play()` 호출을 지우고 `preload`를 `metadata`로 바꿈. 사용자가 누를 때만 재생 | 영상 소리가 약 8초이고, 3초 이상의 소리를 자동 재생할 수 없음(5.4.2) |
| 재생 중 아이콘을 숨기고 마우스를 올리면 표시 | 시안은 유지하고, 호버가 없는 기기(`hover: none`)에서는 재생 중에도 표시 | 터치 사용자가 일시정지 수단을 볼 수 있어야 함(5.4.2, 6.2.2) |
| off의 초점 표시는 노란 윤곽선 | 노란 윤곽선에 검은 안쪽 그림자를 더함 | 밝은 영상 장면에서도 초점이 보이게 함(6.1.2) |
| off의 버튼 이름 ‘재생’, ‘일시정지’ | ‘안내 데스크 호출 벨 영상 재생’, ‘안내 데스크 호출 벨 영상 일시정지’ | 무엇을 재생하는지 알림. 보이는 글자가 없어 6.5.3 위반은 아니며 자료 밖 보강 |

- 브라우저 기본 컨트롤을 숨기고 가운데 아이콘 버튼만 두는 시안은 그대로입니다.
- 캡션 `#aaaaaa`와 off에서 정한 배경 `#1b1f23`은 그대로입니다. 개발 에이전트는 색상 값으로 계산해 4.5:1 이상이라고 판단했습니다.
- 보고서는 접근성과 무관한 기능 결함을 찾지 못했다고 적었습니다.

## 개발 조건

- 출발점: off 화면을 복사한 뒤 국내 접근성 자료를 조회해 적용하는 절차를 켜고 같은 요청서 기준으로 개선했습니다.
- 충돌 처리: 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. 영상 파일을 분석하는 명령도 실행되지 않았습니다.
- 개발 중 확인: 개발 에이전트는 브라우저에서 화면을 실행하지 못했고 코드 검색으로 수정 결과를 확인했다고 보고했습니다.
- off 파일 보존: on 개발 뒤에도 off 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

### 자료 밖 근거

- `video`, `track`, `button` 요소의 동작은 HTML 표준을 따랐습니다. [HTML video 요소](https://html.spec.whatwg.org/multipage/media.html#the-video-element), [HTML track 요소](https://html.spec.whatwg.org/multipage/media.html#the-track-element), [HTML button 요소](https://html.spec.whatwg.org/multipage/form-elements.html#the-button-element)
- 터치 기기 판별에는 CSS `@media (hover: none)`을 썼습니다. [Media Queries Level 4의 hover](https://www.w3.org/TR/mediaqueries-4/#hover)
- 버튼 이름에 영상 이름을 넣은 것은 자료 밖 보강입니다.

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
|---|---|---|
| 초기 상태 확장 검사(위반 / 판정 보류 / 통과 규칙 수) | 0 / 1 / 17 | 0 / 0 / 17 |
| 위반·판정 보류 규칙 | 판정 보류 `no-autoplay-audio` | 없음 |
| 명도 대비 위반 | 없음 | 없음 |
| `autoplay` 속성 | 있음(소리 있음) | 없음 |
| `controls` 속성 | 없음 | 없음 |
| 자막 트랙 | 표시 상태 | 표시 상태 |
| 재생 버튼 이름 | ‘재생’ | ‘안내 데스크 호출 벨 영상 재생’ |
| 키보드 조작 | Tab 순서대로 초점 이동, 초점 표시 있음 | 같음 |
| 폭 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | 0건 | 0건 |

### 브라우저에서 관찰한 결과

- off는 `autoplay` 속성이 있고 음소거 상태가 아니었지만, Chrome 자동 재생 정책으로 재생되지 않았습니다. on에는 `autoplay` 속성이 없었습니다.
- 두 화면 모두 브라우저 기본 컨트롤이 없었고, 자막 트랙이 표시 상태였습니다.
- 두 화면 모두 페이지에 벨 횟수를 설명하는 텍스트가 있었습니다.
- off의 `no-autoplay-audio` 판정 보류는 on에서 나오지 않았습니다.
- 두 화면 모두 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 재생 버튼에 초점을 두고 Enter를 누르면 영상이 재생됐고, 버튼 이름이 ‘안내 데스크 호출 벨 영상 일시정지’로 바뀌었습니다. 다시 Enter를 누르면 영상이 멈췄고 이름이 ‘안내 데스크 호출 벨 영상 재생’으로 돌아왔습니다.

### 코드에서 확인한 사실

- on 스크립트는 클릭 처리기 안에서만 `play()`를 호출합니다.
- 초점 표시는 노란 3px 윤곽선과 `inset 0 0 0 6px #000` 그림자입니다.
- `@media (hover: none)`에서는 재생 중에도 아이콘의 불투명도를 1로 둡니다.
- 자막 파일은 off와 같습니다. 1.0~3.4초에 ‘한 번 울림’, 4.6~7.2초에 ‘두 번 울림’을 표시합니다.

## 미검증 항목

- 영상이 끝난 뒤 다시 재생하는 흐름은 브라우저에서 확인하지 않았습니다.
- 스크린 리더 발화: 버튼 이름 변경(재생, 일시정지)을 읽는지 확인하지 않았습니다.
- 실제 터치 기기에서 재생 중에도 아이콘이 보이는지 확인하지 않았습니다.
