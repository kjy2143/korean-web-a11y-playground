# 안내 데스크 호출 벨 · 접근성 자료 적용 (on) 실행 결과

안내 데스크 호출 벨 소리를 영상과 자막으로 알려 주는 이용 방법 페이지입니다. 기본 개발 화면을 복사한 뒤, 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선했습니다. 페이지를 열 때 재생을 시도하던 코드를 없앴고, 재생 중에도 가운데 버튼이 반투명하게 보이도록 바꿨습니다. 재생 중 버튼의 불투명도는 off가 0, on이 0.6이었습니다. 확장 검사는 off와 같이 위반 규칙과 판정 보류 규칙이 없었습니다.

비교 대상인 기본 개발 화면은 [기본 개발 (off)](/?demo=2026-11-27-facility-video-off)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열면 제목, 벨 사용법 문단, 정지 상태의 영상이 보입니다. 영상은 저절로 재생되지 않습니다.
2. 영상 가운데 버튼이나 영상을 누르면 재생됩니다. 다시 누르면 일시정지됩니다.
3. 키보드에서는 Tab으로 버튼에 초점을 옮긴 뒤 Enter나 Space를 누릅니다.
4. 재생 중에는 가운데 버튼이 반투명해집니다. 영상 영역에 마우스를 올리거나 버튼에 키보드 초점이 오면 불투명해집니다.
5. 한국어 자막이 기본으로 켜져 ‘[안내 데스크 호출 벨이 한 번 울림]’, ‘[안내 데스크 호출 벨이 두 번 울림]’을 표시합니다.

## 요청서와 조정한 부분

‘화면 요청서: 안내 데스크 호출 벨’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 안내 데스크 호출 벨 소리를 영상으로 알려 줍니다.
>
> 안내 데스크 이용 방법 페이지입니다. 제목과 설명 한 문단(‘안내 데스크에 직원이 없을 때 벨을 누르세요. 한 번 울리면 일반 문의, 두 번 울리면 긴급 문의입니다.’), 영상 한 편이 있습니다. 제공 자산은 영상 `desk-chimes.mp4`(약 8초, 벨이 한 번 울리고 이어서 두 번 울림)와 자막 파일 `desk-chimes.vtt`입니다.
>
> 디자인 시안: 페이지에 들어오면 영상을 소리와 함께 자동 재생합니다. 브라우저 기본 컨트롤 막대는 숨기고 영상 가운데에 재생·일시정지 아이콘 버튼만 둡니다. 재생 중에는 아이콘을 숨기고 마우스를 올리면 보입니다. 영상 아래 캡션 ‘안내 데스크 호출 벨’은 `#aaaaaa`입니다.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트가 조정한 내용과 보고서에 적은 이유는 다음과 같습니다. 보고서는 요청서 조정이 이 두 가지라고 적었습니다.

| 요청서 또는 off 화면 | on 화면 | 보고서에 적은 이유 |
|---|---|---|
| 들어오면 소리와 함께 자동 재생. off는 스크립트가 페이지를 열 때 `play()`를 호출 | 정지 상태로 시작. 재생 시도, 실패 안내 문구, 숨긴 `role="status"` 문단을 지우고 `preload`를 `auto`에서 `metadata`로 바꿈 | 영상이 약 8초이고 소리가 3초 넘게 남. 5.4.2는 3초 이상의 자동 소리를 허용하지 않음 |
| 재생 중에는 아이콘을 숨기고 마우스를 올리면 표시. off는 불투명도 0 | 재생 중에도 표시. 불투명도를 0.6으로 낮추고, 마우스 올림이나 키보드 초점에서 1로 올림 | 숨긴 상태에서는 마우스 올림이 없는 터치 사용자가 일시정지 수단을 찾을 수 없음(5.4.2, 6.1.1) |

- 브라우저 기본 컨트롤을 숨기고 가운데 아이콘 버튼만 두는 시안은 그대로 두었습니다.
- 캡션 `#aaaaaa`와 off에서 정한 배경 `#111`은 그대로 두었습니다. 개발 에이전트는 손으로 계산해 대비가 약 8:1이라고 적었습니다.
- 보고서는 접근성 개선과 따로 적을 기능 결함 수정이 없다고 적었습니다. 영상이 끝난 뒤의 재생과 버튼·영상 클릭 처리가 코드에서 정상이었다고 적었습니다.
- 보고서는 영상 아래에 대본을 두는 방법(5.2.1 권장 사항)을 제안으로 남겼습니다. 요청서에 없어서 더하지 않았습니다.

## 개발 조건

- 출발점: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켜고 같은 요청서 기준으로 개선하게 했습니다. 질문하지 말고 개선까지 마치게 했습니다.
- 충돌 처리: 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다.
- 모델과 실행 방식: off와 같이 Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 이 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다. 개발 에이전트는 코드와 명령으로만 확인했습니다.
- 셸 명령: 허용한 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 3건이고, 종류는 `ffmpeg`, `ffprobe`, `which`입니다. 개발 에이전트는 영상 분석 명령을 실행하지 못해 영상의 실제 길이, 오디오 트랙 유무, 벨 소리 시점과 자막의 일치를 확인하지 못했다고 보고했습니다.
- 자료 조회: 설정 확인, 절차 문서, 자료 목록, 레코드 순서로 읽었습니다. 화면 종류와 관계없이 고르는 12개 항목(5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1)의 레코드를 모두 받았습니다. 여기에 5.2.1과 5.4.2를 더해 KWCAG 레코드 14개를 읽었습니다. NIA 사례 레코드는 1.2.1과 1.4.2의 적용 사례와 개선 필요 사례 4개를 읽었습니다. 자료 조회 명령 19회는 모두 주소 하나에 명령 하나인 같은 형태였고, 실패한 조회는 없었습니다.
- 개발 중 확인: 개발 에이전트는 실제 렌더링과 재생은 실행하지 못했고, 코드 검색으로 수정 결과를 확인했다고 보고했습니다.
- 수정 요청: 이 화면에는 검증 뒤 수정 요청을 보내지 않았습니다.
- off 파일 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 첫 실행에서는 on 화면을 만들지 않았습니다. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. 이때 off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준과 참고 자료

적용 항목과 근거 구분은 개발 에이전트의 보고서를 따릅니다. 보고서는 KWCAG 본문을 요구사항, NIA 기본 규칙과 사례를 권장 사항으로 구분했고, 아래 항목의 본문과 기본 규칙을 모두 읽었다고 적었습니다.

### KWCAG 2.2 요구사항

- 자동 재생을 없애고 재생·일시정지 버튼을 제공했습니다. 보고서는 근거를 ‘요구사항 + 권장 사항(사례 4건)’으로 적었습니다. [5.4.2 자동 재생 금지](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.2.json)
- `track kind="captions"` 자막을 기본으로 표시하고, 음향 효과를 설명하는 자막을 유지했습니다. 보고서는 근거를 ‘요구사항 + 권장 사항(사례 2건)’으로 적었습니다. [5.2.1 자막 제공](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.2.1.json)
- 기본 `button`을 쓰고, 버튼이 항상 보이도록 바꿨습니다. [6.1.1 키보드 사용 보장](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.1.json)
- `:focus-visible` 윤곽선을 유지했습니다. 초점 순서는 버튼 하나입니다. [6.1.2 초점 이동과 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.2.json)
- 버튼은 64px이고 폭 320px 화면에서는 56px입니다. 보고서는 근거를 ‘요구사항 + 권장 사항’으로 적고, 이 크기가 권장 크기 이상이라고 적었습니다. [6.1.3 조작 가능](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.3.json)

- 캡션 `#aaaaaa`와 `#111` 배경의 대비를 손으로 계산해 약 8:1로 확인했습니다. [5.4.3 텍스트 콘텐츠의 명도 대비](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.3.json)

[HTML video 요소](https://html.spec.whatwg.org/multipage/media.html#the-video-element), [HTML track 요소](https://html.spec.whatwg.org/multipage/media.html#the-track-element), [HTML button 요소](https://html.spec.whatwg.org/multipage/form-elements.html#the-button-element)

## 검증 결과

확장 검사는 Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에서 했습니다. KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다. 재생과 정지 조작을 확인할 때는 브라우저를 사용자 조작이 있어야 재생을 허용하는 자동 재생 정책으로 실행했습니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
|---|---|---|
| 초기 상태 확장 검사(위반 / 판정 보류 / 통과 규칙 수) | 0 / 0 / 20 | 0 / 0 / 17 |

### 브라우저에서 관찰한 결과

- 두 화면 모두 확장 검사에서 위반 규칙과 판정 보류 규칙이 없었습니다. 통과 규칙 수는 off 20개, on 17개입니다. 어떤 규칙이 달라졌는지는 기록하지 않았습니다.
- 두 화면 모두 페이지를 연 직후 영상이 정지 상태였습니다. 확인에 쓴 브라우저는 사용자 조작이 있어야 재생을 허용하는 설정이어서, 이 관찰만으로는 두 화면의 차이가 드러나지 않습니다. 차이는 아래 코드 사실과 안내 문구에서 확인됩니다.
- off는 상태 영역에 ‘브라우저 정책으로 자동 재생되지 않았습니다. 재생 버튼을 눌러 주세요.’가 들어 있었습니다. on에는 이 문구가 없었습니다.
- on에서 버튼을 클릭하자 영상이 재생됐고 버튼 이름이 ‘일시정지’로 바뀌었습니다. 버튼에 초점을 두고 Enter를 누르자 영상이 멈췄고 이름이 ‘재생’으로 돌아왔습니다. 초점은 버튼에 남았습니다. off도 같았습니다.
- 재생을 시작하고 0.9초 뒤 버튼의 계산된 `opacity`는 off가 0, on이 0.6이었습니다. 마우스를 올리지 않고 버튼에 초점도 두지 않은 상태에서 잰 값입니다.
- 두 화면 모두 영상은 음소거 상태가 아니었고, 한국어 자막 트랙(`captions`)이 표시 상태였습니다.
- 두 화면 모두 초기 상태의 콘솔 오류와 조작 중 페이지 오류가 0건이었습니다.

### 코드에서 확인한 사실

- off와 on의 차이는 네 곳입니다. `video`의 `preload` 값, off에만 있는 `role="status"` 문단, 페이지를 열 때 `play()`를 호출하고 실패하면 문구를 넣는 스크립트 부분, 재생 중 버튼의 `opacity` 값입니다.
- on 스크립트는 버튼이나 영상을 눌렀을 때만 `play()`를 호출합니다. `video`에 `autoplay` 속성은 두 화면 모두 없습니다.
- 재생 중 버튼의 `opacity`는 0.6이고, 영상 영역에 마우스를 올리거나 버튼이 `:focus-visible` 상태이면 1입니다.
- 영상이 끝나면 버튼 이름을 ‘다시 재생’으로 바꿉니다. 이 처리는 off와 같습니다.
- 버튼은 64×64px이고, 폭 360px 이하에서는 56×56px입니다.
- 자막 파일과 영상 파일은 off와 같습니다. 자막은 1.0~3.4초에 ‘[안내 데스크 호출 벨이 한 번 울림]’, 4.6~7.2초에 ‘[안내 데스크 호출 벨이 두 번 울림]’을 표시합니다.
- 캡션 `figcaption`은 `#111` 배경 위 `#aaaaaa` 글자입니다.
- 이번 실행에서 만든 페이지의 제목(`title`)은 ‘안내 데스크 호출 벨 - 한국 웹 접근성 플레이그라운드’이고 `h1`은 ‘안내 데스크 호출 벨’입니다.

## 미검증 항목

- 자동 재생을 허용하는 브라우저 설정에서 두 화면이 어떻게 시작하는지 확인하지 않았습니다. on이 소리 없이 정지 상태로 시작한다는 것은 코드와, 사용자 조작이 필요한 설정의 브라우저에서만 확인했습니다.
- Space 키 조작, Enter로 재생을 시작하는 조작, 영상 영역을 눌러 재생과 일시정지를 바꾸는 조작은 확인하지 않았습니다.
- 재생 중 영상에 마우스를 올리거나 버튼에 키보드 초점을 두었을 때 버튼이 불투명해지는지 브라우저에서 확인하지 않았습니다.
- 불투명도 0.6인 버튼이 영상의 밝은 장면 위에서 잘 보이는지 눈으로 확인하지 않았습니다.
- 영상이 끝나면 버튼 이름이 ‘다시 재생’으로 바뀌고 다시 재생되는지 확인하지 않았습니다.
- 실제 터치 기기에서 재생 중 버튼이 보이고 일시정지가 되는지 확인하지 않았습니다.
- 스크린 리더 발화: 버튼 이름 변경(‘재생’, ‘일시정지’)을 읽는지 확인하지 않았습니다.
- 자막 시간이 실제 벨 소리 시점과 맞는지, 영상에 깜빡임이 없는지 확인하지 않았습니다.
- 캡션 글자의 측정 대비는 기록에 없습니다. 약 8:1은 개발 에이전트가 손으로 계산한 값입니다. 확장 검사에서 `color-contrast` 위반은 없었습니다.
- Chrome 외 브라우저와 화면 확대 상태는 확인하지 않았습니다.
- 개발 중 읽지 못한 자료: 보고서는 읽지 못한 KWCAG 레코드가 없다고 적었습니다. 5.2.1과 5.4.2에 딸린 목적·배경·용어 레코드는 읽지 않았다고 적었습니다. 6.3.1(깜빡임)은 영상 화면 내용을 확인하지 못해 해당 여부를 판단하지 못했고 레코드도 읽지 않았다고 적었습니다.
- 영상 파일: 개발 에이전트는 영상 분석 명령을 실행하지 못해 영상의 실제 길이, 오디오 트랙 유무, 벨 소리 시점과 자막의 일치를 확인하지 못했습니다. 조정 이유에 쓴 ‘약 8초’는 요청서에 적힌 길이와 같은 값입니다.
