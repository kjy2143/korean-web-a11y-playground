# 안내 데스크 이용 방법 · 기본 개발 (off) 실행 결과

안내 데스크 호출 벨 소리를 영상과 자막으로 알려 주는 이용 방법 페이지입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다.

같은 요청서로 접근성 자료를 적용해 개선한 화면은 [안내 데스크 이용 방법 · 접근성 자료 적용 (on)](/?demo=2026-11-27-facility-video-on)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열면 제목, 벨 사용법 문단, 영상이 보입니다. 영상은 페이지에 들어오면 소리와 함께 재생을 시도합니다.
2. 브라우저가 소리 있는 자동 재생을 막으면 영상 가운데에 재생 아이콘이 남습니다.
3. 영상 위 어디를 눌러도 재생과 일시정지가 바뀝니다. 재생·일시정지 버튼이 영상 전체를 덮고 있습니다.
4. 재생 중에는 가운데 아이콘이 숨고, 마우스를 올리거나 키보드 초점이 오면 다시 보입니다.
5. 한국어 자막이 기본으로 켜져 ‘[안내 데스크 호출 벨이 한 번 울림]’, ‘[안내 데스크 호출 벨이 두 번 울림]’을 표시합니다.

## 요청서

‘화면 요청서: 안내 데스크 호출 벨’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 안내 데스크 호출 벨 소리를 영상으로 알려 줍니다.
>
> 안내 데스크 이용 방법 페이지입니다. 제목과 설명 한 문단(‘안내 데스크에 직원이 없을 때 벨을 누르세요. 한 번 울리면 일반 문의, 두 번 울리면 긴급 문의입니다.’), 영상 한 편이 있습니다. 제공 자산은 영상 `desk-chimes.mp4`(약 8초, 벨이 한 번 울리고 이어서 두 번 울림)와 자막 파일 `desk-chimes.vtt`입니다.
>
> 디자인 시안: 페이지에 들어오면 영상을 소리와 함께 자동 재생합니다. 브라우저 기본 컨트롤 막대는 숨기고 영상 가운데에 재생·일시정지 아이콘 버튼만 둡니다. 재생 중에는 아이콘을 숨기고 마우스를 올리면 보입니다. 영상 아래 캡션 ‘안내 데스크 호출 벨’은 `#aaaaaa`입니다.

## 개발 조건

- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 끄고 요청서대로 만들었습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 개발 중 확인: 개발 에이전트는 브라우저에서 동작을 확인하지 못했다고 보고했습니다.
- 제공 자산: 영상 `desk-chimes.mp4`와 자막 `desk-chimes.vtt`를 그대로 썼습니다.
- 수정 요청: 화면에 기능 결함이 없어 수정 요청을 보내지 않았습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 아래 목록은 개발 에이전트가 일반 지식으로 넣은 처리를 코드에서 확인한 것입니다.

### 자료 밖 근거(HTML, WAI-ARIA)

- 자막 파일을 `track kind="captions"`로 연결하고 `default`로 기본 표시했습니다. [HTML track 요소](https://html.spec.whatwg.org/multipage/media.html#the-track-element)
- 재생·일시정지는 영상 전체를 덮는 `button` 하나로 만들었습니다. 버튼 이름은 `aria-label`로 주고, 재생 상태에 따라 ‘재생’과 ‘일시정지’로 바꿉니다. [HTML button 요소](https://html.spec.whatwg.org/multipage/form-elements.html#the-button-element), [WAI-ARIA 1.2 aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label)
- 버튼 안의 아이콘은 `aria-hidden="true"`로 숨겼습니다. [WAI-ARIA 1.2 aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden)
- 재생 중 숨긴 아이콘은 마우스 올림뿐 아니라 `:focus-visible` 상태에서도 보입니다. 초점 윤곽선은 노란색 3px입니다. [Selectors Level 4의 :focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo)
- 영상과 캡션을 `figure`와 `figcaption`으로 묶었습니다. [HTML figure 요소](https://html.spec.whatwg.org/multipage/grouping-content.html#the-figure-element)
- 동작 줄이기 설정에서는 아이콘의 전환 효과를 끕니다. [Media Queries Level 5의 prefers-reduced-motion](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion)

### 요청서와 다르게 판단한 부분

- 소리 있는 자동 재생은 요청대로 구현했습니다. 개발 에이전트는 대부분의 브라우저가 이를 막고, 자동 재생 금지 항목(5.4.2)과 충돌할 수 있어 시안 확정 전에 확인이 필요하다고 보고했습니다. 보고에 쓴 항목 번호는 개발 에이전트가 앞서 받은 자료 목록에 있는 번호입니다. 검사항목 레코드는 조회하지 않았습니다.
- 시안의 마우스 올림 외에 키보드 초점이 올 때도 재생 중 아이콘을 보이게 했습니다.
- 호버가 없는 터치 화면을 고려해 버튼이 영상 전체를 덮게 했습니다.
- 시안에 언급이 없는 자막을 기본 켜짐으로 연결했습니다.
- 캡션 `#aaaaaa`가 흰 배경에서 대비가 부족하다고 보고 페이지 배경을 어두운 색(`#1b1f23`)으로 정했습니다.
- 요청서에 없는 기관명 머리글 ‘푸른숲도서관’을 넣었습니다.
- 페이지 제목의 화면 이름은 요청 내용의 ‘안내 데스크 이용 방법’으로 정했습니다.

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

### 확장 검사

초기 상태에서 위반 규칙은 0개, 판정 보류 규칙은 1개, 통과 규칙은 17개였습니다. 판정 보류 규칙은 `no-autoplay-audio`입니다.

### 브라우저에서 관찰한 결과

- 영상에 `autoplay` 속성이 있고 음소거 상태가 아니었지만, Chrome 자동 재생 정책으로 재생되지 않았습니다.
- 재생 버튼을 누르자 영상이 재생됐고, 자막 트랙이 표시 상태였습니다.
- 재생 버튼의 이름은 ‘재생’이었습니다.
- 영상에 `controls` 속성이 없었고, 페이지에 벨 횟수를 설명하는 텍스트가 있었습니다.
- 폭 1280px에서 Tab 순서대로 초점이 이동했습니다. 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 폭 320px에서 페이지 가로 스크롤이 없었습니다.
- 마크업 검사 오류는 0건이었습니다.
- 초기 상태에서 콘솔 오류(pageerror)는 0건이었습니다.

### 코드에서 확인한 사실

- `video`에 `autoplay`와 `preload="auto"`가 있고, 스크립트도 로드 직후 `play()`를 호출합니다. 재생이 거부되면 버튼 상태만 다시 맞춥니다.
- 자막 파일은 1.0~3.4초에 ‘한 번 울림’, 4.6~7.2초에 ‘두 번 울림’을 표시합니다.
- 캡션 `figcaption`은 `#1b1f23` 배경 위 `#aaaaaa` 글자입니다.

## 미검증 항목

- 자동 재생을 허용한 브라우저 설정에서 소리가 바로 재생되는지 확인하지 않았습니다.
- 스크린 리더 발화: 버튼 이름 변경(‘재생’, ‘일시정지’)을 읽는지 확인하지 않았습니다.
- 실제 터치 기기에서 재생 중 숨은 아이콘과 일시정지 조작을 확인하지 않았습니다.
- 영상의 깜빡임 여부와 자막 시간이 실제 벨 소리와 맞는지 확인하지 않았습니다.
- Chrome 외 브라우저와 화면 확대 상태는 확인하지 않았습니다.
