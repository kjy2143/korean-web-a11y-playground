# 임시 휴관 안내 · 기본 개발 (off) 실행 결과

‘12월 임시 휴관 안내’ 공지를 포스터 이미지 한 장으로 게시하는 공지 상세 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-closure-notice-on)에 있습니다.

확장 검사에서 위반과 판정 보류 규칙이 없었습니다(0 / 0 / 12). 개발 에이전트는 작성일 색 `#aaaaaa`를 요청서대로 두고, 요청서에 없는 짙은 녹색 페이지 배경(`#1a2e22`)을 골라 작성일의 대비를 맞췄다고 보고했습니다. 포스터 이미지에는 포스터 문구를 모두 담은 대체 텍스트가 있고, 장식 아이콘은 빈 대체 텍스트입니다.

## 사용 방법

- 화면을 열어 공지 제목, 작성일, 포스터를 읽습니다.
- 포스터 아래 ‘목록으로’ 링크는 요청서대로 주소가 `#`입니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 임시 휴관 안내’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 임시 휴관 안내 포스터를 게시합니다.
>
> 공지 상세 화면입니다. 제목 ‘12월 임시 휴관 안내’, 작성일 2026.11.27, 본문 포스터 이미지 한 장(`closure-notice.png`)과 아래 ‘목록으로’ 링크(주소 `#`)가 있습니다. 포스터 문구는 ‘푸른숲도서관 / 임시 휴관 / 12월 7일 월요일 / 전기 설비 점검’입니다. 제목 왼쪽에 장식 아이콘 이미지(`decoration.png`)를 32px로 둡니다.
>
> 디자인 시안: 공지 내용은 포스터 이미지로만 게시하고 같은 내용의 텍스트 본문은 두지 않습니다. 작성일은 `#aaaaaa`입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다. 개발 에이전트는 포스터와 장식 아이콘 이미지를 제공받은 그대로 썼다고 보고했습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값만 읽었습니다. 자료 목록과 검사항목 레코드는 한 번도 받지 않았습니다(실행 기록에서 자료 조회 0회 확인).
- 지시: 화면 요청서만 주었습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 이 세션에서는 셸 호출 3건이 거부됐습니다(`ls`와 다른 명령을 묶은 복합 명령, 이미지 크기를 읽는 `sips`, `cat`으로 파일을 쓰는 명령). 개발 에이전트는 화면을 브라우저에서 열어 확인하지 않았고 320px 레이아웃도 직접 보지 못했다고 보고했습니다.
- 수정 요청: 이 화면에는 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행: 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후): 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(2026-11-27 밤): 개발 절차를 ‘설정 확인’ 문서와 ‘절차’ 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본입니다. 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 포스터 대체 텍스트 | 포스터 `img`의 `alt`는 ‘푸른숲도서관 임시 휴관. 12월 7일 월요일. 전기 설비 점검.’입니다. | [HTML 대체 텍스트](https://html.spec.whatwg.org/multipage/images.html#alt) |
| 장식 아이콘 | 제목 앞 장식 아이콘은 `alt=""`, `width="32" height="32"`입니다. | [HTML 대체 텍스트](https://html.spec.whatwg.org/multipage/images.html#alt) |
| 작성일 | 날짜를 `<time datetime="2026-11-27">`로 표시했습니다. | [HTML time 요소](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-time-element) |
| 문서 구조 | `main` 안에 `article`, `header`, `h1`을 두었습니다. | [HTML main 요소](https://html.spec.whatwg.org/multipage/grouping-content.html#the-main-element), [HTML article 요소](https://html.spec.whatwg.org/multipage/sections.html#the-article-element) |
| 초점 표시와 언어 | ‘목록으로’ 링크의 `:focus-visible`에 `outline:3px solid #ffd54a`를 그립니다. `<html lang="ko">`입니다. | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo), [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |
| 링크 크기 | ‘목록으로’ 링크는 `display:inline-block; min-height:44px; padding:10px 20px`입니다. | 개발 에이전트는 근거로 삼은 표준을 적지 않았습니다. |

### 요청서와 다르게 판단한 부분

- 페이지 배경을 짙은 녹색(`#1a2e22`)으로, 기본 글자를 흰색으로 정했습니다. 배경색은 요청서에 없습니다. 개발 에이전트는 `#aaaaaa`를 흰 배경에 쓰면 대비가 약 2.3:1이라 읽기 어렵다고 보고했습니다. 그래서 작성일 색은 그대로 두고 배경을 바꿔 대비를 약 6.6:1로 맞췄다고 보고했습니다.
- 제목 영역 아래 구분선(`1px solid #aaaaaa`), 테두리가 있는 ‘목록으로’ 링크 모양, 초점 윤곽 색은 요청서에 없는 선택입니다.
- 포스터는 `width:100%; height:auto`로 화면 폭에 맞춰 줄어들게 했습니다.

텍스트 본문 없이 포스터 이미지로만 게시하는 시안과 작성일 색 `#aaaaaa`는 요청서대로 두었습니다. 개발 에이전트는 포스터 문구 전체를 `alt`에 넣은 이유로, 텍스트 본문이 없어 `alt`가 시각장애 사용자에게 공지 내용이 전달되는 유일한 경로라는 점을 들었습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 0 / 0 / 12 |
| 위반·판정 보류 규칙 | 없음 |
| 키보드 조작 | Tab 정지점은 ‘목록으로’ 링크 한 곳이고 초점 표시가 있었습니다. |
| ‘목록으로’ 링크 크기 | 97×46px |

| 마크업 오류 | `index.html` 0건 |
| 콘솔 | 초기 상태에 404 기록 1건(데모 폴더의 자원 요청 실패는 없음) |

### 브라우저에서 관찰한 결과

- 확장 검사에서 위반과 판정 보류로 나온 규칙이 없었습니다. 작성일의 명도 대비도 위반이나 판정 보류로 나오지 않았습니다.
- 포스터와 장식 아이콘 이미지가 모두 불러와졌습니다.
- 포스터의 `alt`는 ‘푸른숲도서관 임시 휴관. 12월 7일 월요일. 전기 설비 점검.’이었고, 장식 아이콘의 `alt`는 빈 값이었습니다.
- `main` 안에서 화면에 보이는 문단과 `time` 요소의 글자는 작성일 ‘2026.11.27’과 ‘목록으로’뿐이었습니다. 공지 내용을 담은 텍스트 본문은 없었습니다.
- Tab을 누르면 ‘목록으로’ 링크가 초점을 받았고, 그다음은 `body`였습니다. 초점 표시가 없는 정지점은 없었습니다.
- ‘목록으로’ 링크의 크기는 97×46px이었습니다.
- 폭 320px에서 가로 넘침은 0px이었습니다.
- 초기 상태 콘솔에 404 응답이 1건 기록됐습니다. 응답 상태가 400 이상인 데모 폴더의 자원 요청은 없었습니다. 이 화면은 브라우저를 새로 띄운 뒤 처음 연 화면이었습니다. 브라우저의 파비콘 요청으로 추정하며 따로 확인하지 않았습니다.

### 코드에서 확인한 사실

- 작성일은 `.date{color:#aaaaaa}`이고 배경은 `body{background:#1a2e22}`입니다. 이 두 색으로 WCAG 상대 휘도 공식을 계산하면 대비는 6.20:1입니다. 개발 에이전트가 보고한 약 6.6:1과 다릅니다. 같은 글자색을 흰 배경에 두면 2.32:1입니다.
- 작성일은 날짜만 있고 ‘작성일’ 같은 이름표 글자가 없습니다.
- 포스터 `img`에는 `width`와 `height` 속성이 없습니다.
- 화면에 JavaScript 파일이 없습니다.

## 미검증 항목

- 스크린 리더 발화: 포스터 대체 텍스트와 작성일을 어떻게 읽는지 확인하지 않았습니다.
- 작성일의 측정 대비 값은 기록에 없습니다. 확장 검사 기록에는 위반과 판정 보류 요소의 대비만 남습니다.
- 포스터 이미지 안 글자의 명도 대비는 재지 않았습니다.
- 폭 320px에서 제목이 줄바꿈되는 모양과 포스터가 줄어드는 모양은 확인하지 않았습니다. 기록은 가로 넘침 값뿐입니다.
- ‘목록으로’ 링크를 눌렀을 때의 동작은 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 화면 확대나 글자 크기 키우기, 고대비 모드는 확인하지 않았습니다. 포스터 글자는 이미지라 글자 크기 설정을 따르지 않습니다.
