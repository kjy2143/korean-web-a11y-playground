# 회원가입 · 기본 개발 (off) 실행 결과

푸른숲도서관 회원가입 화면입니다. 입력 오류를 고치고 필수 약관에 동의하면 같은 페이지가 가입 완료 화면으로 바뀝니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-signup-page-on)에 있습니다.

확장 검사에서 위반은 없었고, 건너뛰기 링크 규칙(audit-skip-link) 하나가 판정 보류로 남았습니다. 개발 에이전트는 검사항목 레코드를 조회하지 않았지만, 요청서의 보조 안내 색 `#b0b0b0`을 대비가 낮다고 보고 `#6b6b6b`로 바꿨습니다.

## 사용 방법

- 아이디(영문 소문자·숫자 4~12자), 비밀번호(8자 이상), 비밀번호 확인, 이메일을 입력합니다.
- ‘[필수] 이용약관 동의’와 ‘[필수] 개인정보 수집·이용 동의’를 선택하고 ‘가입하기’를 누르면 가입 완료 화면으로 바뀝니다.
- 빈 칸이나 틀린 값으로 제출하면 화면 위쪽에 오류 요약이 나타나고 초점이 요약으로 이동합니다. 요약의 항목을 누르면 해당 입력란으로 이동합니다.
- ‘전체 동의’를 선택하면 약관 세 개가 함께 선택되고, 세 개를 모두 선택하면 ‘전체 동의’도 선택됩니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 회원가입’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 입력 오류를 고치고 필수 약관에 동의해 가입을 완료합니다.
>
> 아이디(영문 소문자·숫자 4~12자), 비밀번호(8자 이상), 비밀번호 확인, 이메일을 입력받습니다. 약관은 ‘[필수] 이용약관 동의’, ‘[필수] 개인정보 수집·이용 동의’, ‘[선택] 소식 메일 받기’와 ‘전체 동의’입니다. ‘가입하기’를 누르면 입력값을 검사해 틀린 항목을 알려 주고, 모두 맞으면 같은 페이지를 가입 완료 화면으로 바꿉니다.
>
> 디자인 시안: 입력란 위에 제목 없이 안내 문구만 표시합니다(예: ‘아이디 (영문 소문자·숫자 4~12자)’). 필수 입력란은 오른쪽 위에 작은 빨간 점을 찍습니다. 약관 동의는 디자인한 원형 체크 아이콘을 쓰고 기본 체크박스 모양은 보이지 않게 합니다. 입력 규칙 같은 보조 안내 글씨는 `#b0b0b0`입니다. 오류가 나면 입력란 테두리를 빨간색으로 바꿉니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다.
- 지시: 요청서 전문을 주고, 질문하지 말고 구현을 마친 뒤 만든 파일과 판단이 필요했던 점을 보고하게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. 개발 에이전트는 화면을 브라우저로 열어 보지 않았고 JavaScript 문법 검사만 했다고 보고했습니다.
- 수정 요청: 이 화면에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 보이는 레이블 | 입력란 네 개 위에 `label for`를 두고, 입력 규칙 안내를 레이블 안의 `span`으로 넣었습니다. placeholder는 쓰지 않았습니다. | [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element) |
| 필수 입력 | 입력란 네 개와 필수 약관 두 개에 `required`와 `aria-required="true"`를 달았습니다. 빨간 점은 CSS 장식이고, 본문 위에 ‘빨간 점이 있는 칸은 꼭 입력해야 합니다.’를 넣었습니다. | [HTML required](https://html.spec.whatwg.org/multipage/input.html#attr-input-required), [aria-required](https://www.w3.org/TR/wai-aria-1.2/#aria-required) |
| 오류 문구 연결 | 입력란마다 `aria-describedby`로 오류 문구를 연결하고, 오류가 나면 `aria-invalid="true"`를 붙입니다. 문구 앞에는 CSS로 ‘!’ 기호를 붙입니다. | [aria-describedby](https://www.w3.org/TR/wai-aria-1.2/#aria-describedby), [aria-invalid](https://www.w3.org/TR/wai-aria-1.2/#aria-invalid) |
| 오류 요약 | 제출 때 오류가 있으면 `role="group"`, `tabindex="-1"`인 요약 영역을 보여 주고 초점을 옮깁니다. 요약의 각 항목은 해당 입력란으로 초점을 옮기는 링크입니다. | [group 역할](https://www.w3.org/TR/wai-aria-1.2/#group), [HTML tabindex](https://html.spec.whatwg.org/multipage/interaction.html#attr-tabindex) |
| 본문 바로가기 | 페이지 맨 앞에 `#main`으로 가는 ‘본문 바로가기’ 링크를 두고, 초점을 받을 때만 보이게 했습니다. | [HTML 조각 식별자 이동](https://html.spec.whatwg.org/multipage/browsing-the-web.html#scroll-to-fragid) |
| 약관 체크 상자 | 기본 체크 상자를 `opacity:0`으로 투명하게 남겨 키보드 조작을 유지하고, 레이블 앞에 원형 아이콘을 그렸습니다. 약관 세 개는 숨긴 `legend`(‘약관 동의’)가 있는 `fieldset`으로 묶었습니다. | [HTML fieldset 요소](https://html.spec.whatwg.org/multipage/form-elements.html#the-fieldset-element) |
| 고대비 모드 | `forced-colors: active`에서 원형 아이콘의 테두리와 선택 색을 시스템 색으로 바꿉니다. | [forced-colors](https://www.w3.org/TR/mediaqueries-5/#forced-colors) |
| 완료 화면 초점 | 가입이 끝나면 완료 화면의 제목(`tabindex="-1"`)으로 초점을 옮깁니다. | [HTML tabindex](https://html.spec.whatwg.org/multipage/interaction.html#attr-tabindex) |
| 자동 완성과 언어 | `autocomplete`(`username`, `new-password`, `email`)와 `<html lang="ko">`를 지정했습니다. | [HTML 자동 완성](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill), [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |
| 초점 표시 | `:focus-visible`에 3px 윤곽선을 그리고, 약관은 원형 아이콘에 윤곽선을 그립니다. | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo) |

### 요청서와 다르게 판단한 부분

- 보조 안내 글씨 색: 요청서의 `#b0b0b0` 대신 `#6b6b6b`를 썼습니다. 개발 에이전트는 `#b0b0b0`이 흰 배경에서 읽기 어렵다고 보고했습니다.
- 필수 입력란: 요청서가 필수 칸을 정하지 않아 입력란 네 개를 모두 필수로 보고 빨간 점을 찍었습니다.
- 안내 문구: 빨간 점의 뜻을 알리는 문장을 본문 위에 더했습니다.
- 오류 표시: 요청서의 빨간 테두리에 더해 입력란 아래 오류 문구와 오류 요약을 넣었습니다. 개발 에이전트는 색만으로 알리지 않으려는 판단이라고 보고했습니다.
- 가입 완료: 서버 전송과 저장은 하지 않습니다. 완료 화면에 비밀번호를 표시하지 않습니다.

입력란 위에 제목 없이 안내 문구만 두는 시안은 안내 문구를 보이는 레이블로 만드는 방식으로 지켰습니다.

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 0 / 1 / 23 |
| 확장 검사: 빈 값 제출 | 0 / 1 / 28 |
| 위반·판정 보류 규칙 | 위반 없음. 두 상태 모두 audit-skip-link 판정 보류 |
| 키보드 조작 | Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 초점 표시가 있었습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html` 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- 빈 값으로 제출하면 화면에 머물렀고, 초점이 오류 요약(`#error-summary`)으로 이동했으며, `aria-invalid`가 붙은 요소가 6개였습니다.
- 올바른 값을 넣고 필수 약관에 동의한 뒤 제출하면 완료 화면으로 바뀌었습니다. 이 흐름은 마우스로 확인했습니다.

### 코드에서 확인한 사실

- 본문 바로가기의 대상인 `main`에 `tabindex`가 없습니다.
- 본문 위 안내 문장은 ‘빨간 점’이라는 색과 모양으로 필수 칸을 설명합니다. 입력란 레이블에는 필수라는 글자가 없습니다.
- 오류를 고쳐도 오류 요약 목록은 다음 제출 때까지 바뀌지 않습니다. 입력란 아래 문구만 입력할 때마다 갱신됩니다.

## 미검증 항목

- 스크린 리더 발화: 오류 요약, 필수 표시, 약관 체크 상자의 상태를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 약관 체크 상자의 Space 키 선택과 ‘전체 동의’ 연동, ‘본문 바로가기’를 눌렀을 때의 초점 위치는 기록하지 않았습니다.
- 가입 완료 뒤 초점이 완료 화면 제목으로 가는지, 고대비 모드에서 원형 아이콘이 보이는지 확인하지 않았습니다.
