# 회원가입 · 기본 개발 (off) 실행 결과

푸른숲도서관 회원가입 화면입니다. 입력 오류를 고치고 필수 약관에 동의하면 같은 페이지가 가입 완료 화면으로 바뀝니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 화면 요청서만 주고 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-signup-page-on)에 있습니다.

확장 검사에서 레이블 안의 보조 안내 글씨 네 곳이 명도 대비 위반(2.16:1)으로 나왔습니다. 빈 값으로 제출한 상태에서는 오류 요약의 링크 네 개가 조작 대상 크기 위반(target-size)으로 더 나왔습니다. ‘전체 동의’를 켤 때 콘솔에 `TypeError`가 1건 기록됐습니다. 체크 상자 연동과 가입 흐름은 정상이어서 수정 요청은 보내지 않았습니다.

## 사용 방법

- 아이디(영문 소문자·숫자 4~12자), 비밀번호(8자 이상), 비밀번호 확인, 이메일을 입력합니다.
- ‘[필수] 이용약관 동의’와 ‘[필수] 개인정보 수집·이용 동의’를 선택합니다. ‘전체 동의’를 누르면 약관 세 개가 함께 선택됩니다.
- ‘가입하기’를 누르면 입력값을 검사합니다. 틀린 항목이 있으면 화면 위쪽에 오류 요약이 나타나고 각 입력란 아래에 오류 문구가 표시됩니다. 요약의 항목을 누르면 해당 입력란으로 초점이 갑니다.
- 모두 맞으면 같은 페이지가 가입 완료 화면으로 바뀝니다. 서버로 보내는 값은 없습니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 회원가입’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 입력 오류를 고치고 필수 약관에 동의해 가입을 완료합니다.
>
> 아이디(영문 소문자·숫자 4~12자), 비밀번호(8자 이상), 비밀번호 확인, 이메일을 입력받습니다. 약관은 ‘[필수] 이용약관 동의’, ‘[필수] 개인정보 수집·이용 동의’, ‘[선택] 소식 메일 받기’와 ‘전체 동의’입니다. ‘가입하기’를 누르면 입력값을 검사해 틀린 항목을 알려 주고, 모두 맞으면 같은 페이지를 가입 완료 화면으로 바꿉니다.
>
> 디자인 시안: 입력란 위에 제목 없이 안내 문구만 표시합니다(예: ‘아이디 (영문 소문자·숫자 4~12자)’). 필수 입력란은 오른쪽 위에 작은 빨간 점을 찍습니다. 약관 동의는 디자인한 원형 체크 아이콘을 쓰고 기본 체크박스 모양은 보이지 않게 합니다. 입력 규칙 같은 보조 안내 글씨는 `#b0b0b0`입니다. 오류가 나면 입력란 테두리를 빨간색으로 바꿉니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행). 개발 세션은 대화 턴 9회, 65초였습니다.
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 꺼 두었습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값(off)만 읽었습니다. 절차 본문, 자료 목록, 검사항목 레코드는 한 번도 받지 않았습니다. 실행 기록에서 자료 조회가 0회임을 확인했고, 이번 실행의 off 세션 13개가 모두 같았습니다.
- 지시: 화면 요청서만 주었습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 폴더를 옮긴 뒤 다른 명령을 잇는 복합 명령 1건이 거부됐고, 그 뒤에도 파일 세 개는 모두 만들어졌습니다. 개발 에이전트는 화면을 브라우저에서 열어 동작을 확인하지 않았다고 보고했습니다.
- 수정 요청: 보내지 않았습니다. ‘전체 동의’를 켤 때 콘솔에 `TypeError`가 1건 기록됐지만, 체크 상자 연동과 가입 흐름이 정상이어서 그대로 두었습니다.
- 보존: on 화면을 개발하고 on 결함을 수정한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 보이는 레이블 | 입력란 네 개 위에 `label for`를 두고, 항목 이름과 입력 규칙 안내를 레이블 안의 `span`으로 넣었습니다. placeholder는 쓰지 않았습니다(`index.html`). | [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element) |
| 필수 표시 | 빨간 점은 `aria-hidden="true"`인 `span`입니다. 레이블 끝에 화면에서 숨긴 ‘필수’ 글자를 넣었고, 입력란 네 개와 필수 약관 두 개에 `aria-required="true"`를 달았습니다(`index.html`). | [aria-required](https://www.w3.org/TR/wai-aria-1.2/#aria-required), [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 오류 문구 연결 | 입력란과 필수 약관마다 `aria-describedby`로 오류 문구를 연결하고, 오류가 나면 `aria-invalid="true"`를 붙입니다. 문구 앞에는 CSS로 ‘⚠’ 기호를 붙입니다(`index.html`, `script.js`, `style.css`). | [aria-describedby](https://www.w3.org/TR/wai-aria-1.2/#aria-describedby), [aria-invalid](https://www.w3.org/TR/wai-aria-1.2/#aria-invalid) |
| 오류 요약 | 제출 때 오류가 있으면 `role="alert"`, `tabindex="-1"`인 요약 영역을 보여 주고 그 영역으로 초점을 옮깁니다. 요약의 각 항목은 해당 입력란으로 초점을 옮기는 링크입니다(`index.html`, `script.js`). | [alert 역할](https://www.w3.org/TR/wai-aria-1.2/#alert), [HTML tabindex](https://html.spec.whatwg.org/multipage/interaction.html#attr-tabindex) |
| 본문 바로가기 | 페이지 맨 앞에 `#main`으로 가는 ‘본문 바로가기’ 링크를 두고 초점을 받을 때만 보이게 했습니다. 대상인 `main`에는 `tabindex="-1"`이 있습니다(`index.html`, `style.css`). | [HTML tabindex](https://html.spec.whatwg.org/multipage/interaction.html#attr-tabindex) |
| 약관 체크 상자 | 기본 체크 상자를 `opacity:0`으로 투명하게 겹쳐 두고 레이블 앞에 원형 아이콘을 그렸습니다. 약관 네 개는 `legend`(‘약관 동의’)가 있는 `fieldset`으로 묶었습니다. 초점 윤곽선은 원형 아이콘에 그립니다(`index.html`, `style.css`). | [HTML fieldset 요소](https://html.spec.whatwg.org/multipage/form-elements.html#the-fieldset-element) |
| 완료 화면 초점 | 가입이 끝나면 완료 화면의 제목(`tabindex="-1"`)으로 초점을 옮기고 페이지 제목을 ‘가입 완료 - 한국 웹 접근성 플레이그라운드’로 바꿉니다(`script.js`). | [HTML tabindex](https://html.spec.whatwg.org/multipage/interaction.html#attr-tabindex) |
| 자동 완성과 언어 | `autocomplete`(`username`, `new-password`, `email`)와 `<html lang="ko">`를 지정했습니다(`index.html`). | [HTML 자동 완성](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill), [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |
| 초점 표시와 조작 크기 | 입력란, 버튼, 오류 요약 영역의 `:focus-visible`에 3px 윤곽선을 그립니다. 입력란 높이는 46px, 약관 한 줄의 최소 높이는 44px입니다(`style.css`). | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo) |

### 요청서와 다르게 판단한 부분

- 보조 안내 글씨는 시안대로 `#b0b0b0`을 썼습니다. 개발 에이전트는 흰 배경에서 대비가 약 2.1:1이라 기준에 못 미친다고 보고했지만 색을 바꾸지 않았고, 항목 이름(‘아이디’ 등)만 어두운 색으로 두었습니다.
- 필수 표시: 빨간 점은 색과 위치로만 전달된다고 보고, 레이블에 화면에는 보이지 않는 ‘필수’ 문구를 넣었습니다. 입력란 네 개에 모두 빨간 점을 찍었습니다.
- 오류 표시: 요청서의 빨간 테두리에 더해 ‘⚠’가 붙은 오류 문구를 입력란 아래에 넣고, 화면 위쪽에 오류 요약을 두었습니다. 개발 에이전트는 빨간 테두리만으로는 구분이 어렵다고 보고했습니다.
- 입력 규칙: 요청서에 없는 비밀번호 확인 안내 문구(‘비밀번호를 한 번 더 입력’)와 이메일 예시를 더했습니다. 이메일은 `@`와 `.`이 있는 형태인지만 검사합니다.
- 전체 동의: 개별 항목과 양방향으로 연동하게 했습니다. 선택 항목인 ‘소식 메일 받기’도 함께 켜지고 꺼집니다.
- 가입 완료: 같은 페이지에서 폼을 숨기고 완료 영역을 보여 줍니다. 서버 전송은 없습니다.

입력란 위에 제목 없이 안내 문구만 두는 시안은 안내 문구를 보이는 레이블로 만드는 방식으로 지켰습니다. 원형 체크 아이콘도 시안대로 두었습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다. KWCAG 검사 0.1.17은 건너뛰기 링크가 예상 Tab 순서의 첫 항목이고 연결 대상이 있으면 통과로 처리합니다(0.1.16은 판정 보류로 남겼습니다).

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 23 |
| 확장 검사: 빈 값 제출 | 2 / 0 / 27 |
| 위반 규칙과 측정 대비 | color-contrast 4개 요소(레이블 안의 보조 안내 `.hint`, `#b0b0b0` 14px, 2.16:1). 두 상태에서 같습니다. |
| 빈 값 제출 상태에서 더해진 위반 | target-size 4개 요소(오류 요약에서 `#userid`, `#pw`, `#email`, `#agree-terms`로 가는 링크) |
| 오류 요약 링크의 크기 | 6개 모두 높이 19px, 폭 143~217px |
| 키보드 조작 | Tab 정지점은 본문 바로가기, 입력란 네 개, 약관 체크 상자 네 개, 가입하기 순서였습니다. 초점 표시가 없는 정지점은 없었습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html` 0건 |
| 콘솔 오류 | 초기 상태 0건. ‘전체 동의’를 켤 때 `TypeError` 1건 |

### 브라우저에서 관찰한 결과

- 빈 값으로 ‘가입하기’를 누르면 화면에 머물렀고 초점이 오류 요약(`#error-summary`)으로 갔습니다. `aria-invalid`가 붙은 요소는 6개였습니다. 요약에는 ‘입력 내용을 확인해 주세요. (6건)’과 항목별 문구 여섯 개가 표시됐습니다.
- 입력란의 이름은 ‘아이디 (영문 소문자·숫자 4~12자) 필수’처럼 ‘필수’ 글자를 포함했습니다. 이 글자는 숨김 클래스(`vh`) 요소에 들어 있었습니다.
- ‘전체 동의’에 초점을 두고 Space를 누르면 체크 상자 네 개가 모두 선택됐습니다. 이때 콘솔에 `TypeError: Cannot set properties of null (setting 'textContent')`가 기록됐습니다.
- 이어서 올바른 값(아이디 `reader01`, 비밀번호와 비밀번호 확인 `green1234`, 이메일 `reader@example.com`)을 넣고 ‘가입하기’를 누르면 ‘가입이 완료되었습니다’가 표시됐고 초점이 그 제목으로 갔습니다.

### 코드에서 확인한 사실

- `TypeError`의 원인: ‘전체 동의’를 켜면 약관 세 개를 차례로 선택하면서 각 약관의 오류 문구를 지웁니다. ‘소식 메일 받기’에는 오류 문구 요소가 없어 없는 요소의 `textContent`를 바꾸려다 오류가 납니다. 세 약관을 모두 선택한 뒤에 오류가 나므로 선택 상태는 바뀝니다(`script.js`).
- 같은 처리가 개별 체크 상자에도 있습니다. ‘소식 메일 받기’를 직접 켜면 ‘전체 동의’ 상태를 맞춘 뒤 같은 호출을 합니다.
- 입력란에는 `input` 이벤트 처리가 없습니다. 오류가 표시된 뒤 값을 고쳐도 입력란의 오류 문구와 빨간 테두리, 오류 요약은 다음 제출 때까지 그대로입니다. 필수 약관은 선택하면 그 약관의 오류 문구만 지우고 요약은 바꾸지 않습니다.
- 오류 요약의 링크는 크기를 따로 지정하지 않은 인라인 요소입니다. `:focus-visible` 윤곽선 규칙에는 요약 영역은 들어 있고 요약 안의 링크는 들어 있지 않습니다(`style.css`).
- 보조 안내 글씨 색은 `--hint:#b0b0b0` 변수 하나로 지정합니다.
- 레이블의 ‘필수’ 글자는 `.vh`로 화면에서 숨깁니다.

## 미검증 항목

- 스크린 리더 발화: 오류 요약(`role="alert"`), 숨긴 ‘필수’ 글자, 원형 체크 아이콘의 상태를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- ‘본문 바로가기’를 실행한 뒤의 초점 위치는 기록하지 않았습니다.
- ‘전체 동의’를 끄는 동작, 개별 약관을 눌렀을 때 ‘전체 동의’가 바뀌는 동작, ‘소식 메일 받기’를 직접 켤 때의 콘솔 오류 여부는 브라우저에서 확인하지 않았습니다.
- 오류 요약의 링크를 눌러 입력란으로 이동하는 동작과 형식이 틀린 값(짧은 아이디, 서로 다른 비밀번호, 잘못된 이메일)의 오류 문구는 브라우저에서 기록하지 않았습니다.
- 가입 완료 뒤 페이지 제목이 바뀌는지와 ‘처음으로’ 링크는 브라우저에서 기록하지 않았습니다.
- 빈 값 제출 상태의 320px 화면, 화면 확대, 고대비 모드는 확인하지 않았습니다.
