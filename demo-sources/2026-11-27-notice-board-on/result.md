# 공지사항 · 접근성 자료 적용 (on) 실행 결과

강조 공지 한 건과 공지 다섯 건의 목록을 보여 주는 공지사항 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-notice-board-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사에서 off의 명도 대비 위반(20개 요소)이 사라졌습니다. 바뀐 파일은 `style.css` 하나이고, 글자색 네 곳과 강조 공지 상자의 테두리가 바뀌었습니다. 폭 480px 이하에서 CSS `order`로 날짜와 제목의 화면 순서를 바꾸는 배치는 on에도 그대로 남아 있습니다. Tab 순서, 320px 화면의 페이지 가로 스크롤, 마크업 검사 결과는 off와 같았습니다.

## 사용 방법

1. 페이지 위쪽에 테두리가 있는 강조 공지 상자가 있습니다. ‘12월 7일 임시 휴관’은 링크(주소 `#`)입니다.
2. 아래 목록에 공지 다섯 건이 있습니다. 공지마다 분류 배지(안내·행사·모집), 제목 링크(주소 `#`), 날짜가 있습니다.
3. Tab 키로 강조 공지 링크와 제목 링크 다섯 개를 차례로 이동합니다.
4. 폭 480px 이하에서는 배지와 날짜가 윗줄에, 제목이 아랫줄에 놓이도록 작성돼 있습니다.
5. off 화면과 나란히 열어 글자색과 강조 공지 상자의 테두리를 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 공지사항’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 공지사항 목록과 강조 공지를 확인합니다.
>
> 위쪽에 강조 공지 상자(‘12월 7일 임시 휴관’) 하나, 아래에 공지 다섯 건의 목록이 있습니다. 목록은 분류(안내·행사·모집), 제목, 날짜를 보여 주고 제목은 링크입니다(주소 `#`).
>
> 디자인 시안: 브랜드 톤에 맞춰 본문 글자는 `#999999`, 날짜는 `#bbbbbb`입니다. 분류 배지는 연두 배경 `#c8e6a0`에 흰 글씨 12px입니다. 강조 공지 상자는 연한 노랑 배경 `#fff7d6`에 글씨 `#c9a227`입니다.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트는 시안의 글자색이 5.4.3의 명도 대비 기준을 충족하지 못한다고 판단해 아래처럼 바꿨습니다. 대비 값은 개발 에이전트가 색상 값으로 손으로 계산한 것입니다.

| 대상 | 요청서 시안 | on 화면 | 개발 에이전트가 계산한 대비(시안 → 조정 후) |
| --- | --- | --- | --- |
| 본문 글자(흰 배경) | `#999999` | `#6b6b6b` | 약 2.8:1 → 약 5.3:1 |
| 날짜(흰 배경) | `#bbbbbb` | `#6b6b6b` | 약 1.9:1 → 약 5.3:1 |
| 분류 배지 글씨(배경 `#c8e6a0`) | 흰색 | `#2d4a12` | 약 1.3:1 → 약 7.3:1 |
| 강조 공지 글씨(배경 `#fff7d6`) | `#c9a227` | `#6b5200` | 약 2.2:1 → 약 6.9:1 |

- 보고서는 시안 대비 가운데 `#999999`만 값으로 확인한 근사치이고 나머지는 어림한 값이라고 적었습니다. 확장 검사가 off에서 측정한 값은 본문 색 2.84:1, 강조 공지 색 2.24:1입니다.
- 배지는 배경 `#c8e6a0`과 12px 크기를 시안대로 두고 글자색만 바꿨습니다.
- 강조 공지 상자에 `1px solid #6b5200` 테두리를 더하고 왼쪽 테두리만 6px로 했습니다. 보고서는 배경 `#fff7d6`이 흰색과 거의 구분되지 않아서라고 적었습니다(5.4.4).
- 폭 480px 이하의 `order` 배치는 바꾸지 않았습니다. 보고서는 날짜가 초점을 받지 않고 읽기 순서(배지, 제목, 날짜)가 그대로여서 유지했다고 적었습니다(5.3.2).
- 보고서는 접근성과 무관한 기능 결함을 찾지 못했고, 요청서에 없는 기능은 덧붙이지 않았다고 적었습니다.
- 개발 에이전트는 건너뛰기 링크를 제안으로만 남겼습니다. 지금은 머리글에 반복 링크가 없어 필요하지 않고, 사이트 메뉴가 생기면 필요하다고 적었습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치게 했습니다.
- 자료 조회: 설정 확인, 절차 문서, 자료 목록, 레코드 순서로 읽었습니다. 자료 조회 명령은 19회였고 모두 주소 하나에 명령 하나인 같은 형태였습니다. 조회에 실패한 주소는 없었습니다. KWCAG 레코드 14개와 NIA 사례 레코드 4개를 받았습니다. KWCAG 14개는 화면 종류와 관계없이 고르는 12개 항목(5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1)과 6.4.1, 6.4.3입니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 2건(`cat`, `python3`)입니다. 개발 에이전트는 대비 계산 스크립트의 실행이 승인되지 않아 대비를 손으로 계산했다고 보고했습니다.
- 수정 요청: 검증에서 기능 결함이 나오지 않아 수정 요청을 보내지 않았습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행: 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었습니다. 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후): 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(이 문서, 2026-11-27 밤): 개발 절차를 ‘설정 확인’ 문서와 ‘절차’ 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했습니다. 자료 조회 명령은 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본입니다. 화면은 처음부터 다시 만들었습니다.

| 마크업 오류 | 0건 | 0건 |
| 콘솔 오류(초기 상태) | 0건 | 0건 |

### 브라우저에서 관찰한 결과

- on에서는 `color-contrast` 위반이 없었습니다. 통과 규칙은 17개에서 18개로 늘었습니다.
- 계산된 글자색은 아래와 같았습니다. 배지 배경은 두 화면 모두 `rgb(200, 230, 160)`이었습니다.

| 대상 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 본문과 제목 링크 | `rgb(153, 153, 153)` | `rgb(107, 107, 107)` |
| 날짜 | `rgb(187, 187, 187)` | `rgb(107, 107, 107)` |
| 분류 배지 글씨 | `rgb(255, 255, 255)` | `rgb(45, 74, 18)` |
| 강조 공지 | `rgb(201, 162, 39)` | `rgb(107, 82, 0)` |

- 두 화면의 Tab 순서는 같았습니다. 강조 공지 링크 다음에 제목 링크 다섯 개가 목록 순서대로 초점을 받았고, 정지점마다 초점 표시가 있었습니다.
- 두 화면 모두 링크는 6개였고 목록의 공지 다섯 건은 같았습니다.
- 두 화면 모두 창 폭 1280px에서는 목록 안에 `order`가 0이 아닌 요소가 없었습니다. 폭 320px에서는 공지 5건 모두 제목의 `order`가 2, 날짜의 `order`가 1이었습니다.

### 코드에서 확인한 사실

- off와 on의 `index.html`은 같습니다.
- `style.css`는 네 줄이 다릅니다. `body`의 색이 `#999999`에서 `#6b6b6b`로, `.date`의 색이 `#bbbbbb`에서 `#6b6b6b`로, `.badge`의 색이 `#ffffff`에서 `#2d4a12`로 바뀌었습니다. `.highlight`는 색이 `#c9a227`에서 `#6b5200`으로 바뀌고 `border: 1px solid #6b5200; border-left-width: 6px`가 더해졌습니다.
- `@media (max-width: 480px)`의 규칙은 off와 같습니다. 제목은 `flex-basis: 100%; order: 2`, 날짜는 `order: 1; margin-left: auto`입니다. 그래서 문서 순서는 배지, 제목, 날짜이고 화면 배치 순서는 배지, 날짜, 제목입니다.
- 본문의 글자 크기는 16px, 줄 높이는 1.6입니다. 둘을 곱하면 25.6px로, 보고서가 적은 링크 줄 높이와 같습니다.
- 본문 바로가기 링크는 없습니다. 스크립트도 없습니다.

## 미검증 항목

on 보고서가 브라우저에서 확인하라고 남긴 동작 가운데 기록이 없는 항목입니다.

- 링크 6개가 Tab 순서대로 초점을 받고 초점 표시가 있는 것은 확인했습니다. 윤곽선이 잘리지 않는지는 기록하지 않았습니다.
- 320px에서 페이지 가로 스크롤이 없고 `order` 값이 적용된 것은 확인했습니다. 날짜가 배지 줄 오른쪽에 놓이고 제목이 아랫줄로 내려가는지는 기록하지 않았습니다.
- 조정한 색은 확장 검사에서 `color-contrast` 위반과 판정 보류가 없었습니다. 색 조합별 측정 대비 값은 기록하지 않았습니다.
- 스크린 리더 발화: 읽는 순서가 배지, 제목, 날짜인지 확인하지 않았습니다.
- 고대비 모드에서 강조 공지 테두리가 보이는지 확인하지 않았습니다.

그 밖에 확인하지 않은 항목입니다.

- 화면 순서와 문서 순서가 다른 점이 보조기술 사용자에게 주는 영향은 확인하지 않았습니다.
- 링크의 실제 크기는 브라우저에서 재지 않았습니다.
- 실제 터치 기기, Chrome 이외의 브라우저, 화면 확대 상태는 확인하지 않았습니다.

### 개발 중 읽지 못한 자료

- 보고서는 읽으려다 실패한 주소가 없다고 적었습니다.
- KWCAG 원문의 표지·머리말 레코드와 자료 전체 목록 파일은 읽지 않았습니다.
- 각 항목의 목적·배경·용어 레코드는 읽지 않았습니다.
- 5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1의 적용 사례와 개선 필요 사례는 읽지 않았습니다. 이 항목들은 본문과 기본 규칙만 읽었습니다.
- 대비 계산 스크립트는 실행하지 못했습니다. 보고서의 대비 수치는 손으로 계산한 값입니다.
