# 공지사항 · 접근성 자료 적용 (on) 실행 결과

강조 공지 한 건과 공지 다섯 건의 목록을 보여 주는 공지사항 화면입니다. 기본 개발 화면을 복사한 뒤, 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선했습니다.

비교 대상인 기본 개발 화면은 [공지사항 · 기본 개발 (off)](/?demo=2026-11-27-notice-board-off)에서 볼 수 있습니다.

## 사용 방법

1. 페이지 위쪽에 테두리가 있는 강조 공지 상자 ‘12월 7일 임시 휴관’이 있습니다.
2. 아래 목록에 공지 다섯 건이 있습니다. 공지마다 분류 배지(안내·행사·모집), 제목 링크(주소 `#`), 날짜가 있습니다.
3. Tab 키로 제목 링크 다섯 개를 차례로 이동합니다.
4. 폭 480px 이하에서는 배지, 제목, 날짜가 문서 순서대로 세로로 쌓입니다.

## 요청서와 조정한 부분

‘화면 요청서: 공지사항’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 공지사항 목록과 강조 공지를 확인합니다.
>
> 위쪽에 강조 공지 상자(‘12월 7일 임시 휴관’) 하나, 아래에 공지 다섯 건의 목록이 있습니다. 목록은 분류(안내·행사·모집), 제목, 날짜를 보여 주고 제목은 링크입니다(주소 `#`).
>
> 디자인 시안: 브랜드 톤에 맞춰 본문 글자는 `#999999`, 날짜는 `#bbbbbb`입니다. 분류 배지는 연두 배경 `#c8e6a0`에 흰 글씨 12px입니다. 강조 공지 상자는 연한 노랑 배경 `#fff7d6`에 글씨 `#c9a227`입니다.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트는 시안의 글자색이 모두 5.4.3의 명도 대비 4.5:1에 못 미친다고 판단해 아래처럼 바꿨습니다. 판단에 쓴 대비 값은 개발 에이전트가 WCAG 상대 휘도 공식으로 계산했습니다.

| 대상 | 요청서 | on 화면 |
|---|---|---|
| 본문과 제목 링크 | `#999999` | `#595959` |
| 날짜 | `#bbbbbb` | `#6b6b6b` |
| 분류 배지 글씨(배경 `#c8e6a0`) | 흰색 | `#2f4a12` |
| 강조 공지 글씨(배경 `#fff7d6`) | `#c9a227` | `#6b5200` |

- 배지 배경 `#c8e6a0`, 강조 공지 배경 `#fff7d6`, 배지 글자 크기 12px은 그대로 두었습니다. 보고서는 12px 글씨에는 큰 글씨 예외(3:1)를 쓸 수 없어 4.5:1을 적용했다고 적었습니다.
- 강조 공지 상자에 `2px solid #6b5200` 테두리를 더했습니다. 상자 배경과 페이지 흰 배경의 차이가 작아 색만으로는 상자가 구분되지 않는다고 판단했습니다(5.4.4).
- 폭 480px 이하에서 `order`로 제목을 날짜 뒤로 보내던 배치를 없앴습니다. 이제 문서 순서(분류, 제목, 날짜)와 화면 순서가 같습니다(5.3.2).
- 보고서는 접근성과 무관한 기능 결함을 찾지 못했다고 적었습니다. 이번 개선에서 바뀐 파일은 `style.css` 하나입니다.

## 개발 조건

- 출발점: off 화면을 복사한 뒤 국내 접근성 자료를 조회해 적용하는 절차를 켜고 같은 요청서 기준으로 개선했습니다.
- 충돌 처리: 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 개발 중 확인: 개발 에이전트는 브라우저 도구가 없어 화면을 실행하지 못했다고 보고했습니다.
- off 파일 보존: on 개발 뒤에도 off 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준과 참고 자료

근거 구분은 개발 에이전트의 보고서를 따릅니다. 보고서는 읽은 레코드의 KWCAG 본문과 NIA 기본 규칙에 따라 판단했다고 적었습니다.

### KWCAG 2.2 요구사항

- 폭 480px 이하의 `order` 배치를 없앴습니다. [5.3.2 콘텐츠의 선형구조](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.3.2.json)
- 분류를 글자(안내·행사·모집)로 표시하고, 제목 링크에 밑줄이 있어 색에만 의존하지 않습니다. [5.4.1 색에 무관한 콘텐츠 인식](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.1.json)
- 위 표처럼 글자색을 조정했습니다. [5.4.3 텍스트 콘텐츠의 명도 대비](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.3.json)
- 강조 공지에 테두리를 더하고, 목록 구분선과 간격은 유지했습니다. [5.4.4 콘텐츠 간의 구분](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.4.json)
- 링크는 기본 `a` 요소라 Tab과 Enter로 쓸 수 있습니다. [6.1.1 키보드 사용 보장](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.1.json)
- 기존 `:focus-visible` 3px 윤곽선을 유지했고, 초점 순서는 문서 순서와 같습니다. [6.1.2 초점 이동과 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.2.json)
- 페이지 제목과 `h1`, `h2` 구조를 확인했습니다. [6.4.2 제목 제공](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.4.2.json)
- 링크 텍스트가 서로 다른 공지 제목이라 목적을 알 수 있습니다. [6.4.3 적절한 링크 텍스트](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.4.3.json)
- 링크 이름이 보이는 텍스트와 같습니다. [6.5.3 레이블과 네임](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.3.json)
- `<html lang="ko">`를 확인했습니다. [7.1.1 기본 언어 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-7.1.1.json)
- 링크 줄 높이와 항목 간 구분선, 안쪽 여백을 유지했습니다. 보고서는 6.1.3의 KWCAG 본문을 ‘바람직하다’ 수준으로 적었습니다. [6.1.3 조작 가능](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.3.json)

보고서는 [6.4.1 반복 영역 건너뛰기](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.4.1.json)도 읽었지만 적용 항목에 넣지 않았습니다. 반복 영역이 기관명 한 줄뿐이라 건너뛰기 링크가 필요한지 판단하기 어려웠다고 적었습니다.

### NIA 제작기법 권장 사항

- 6.1.3 조작 가능의 크기 수치는 NIA 기본 규칙을 근거로 적었습니다. [NIA 2.1.3 기본 규칙](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-2.1.3-s3.json)
- 초점이나 마우스 올림만으로 실행되는 기능이 없음을 확인했습니다(7.2.1). [NIA 3.2.1 기본 규칙](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-3.2.1-s3.json)
- `id` 중복이 없고 태그 짝이 맞음을 확인했습니다(8.1.1). [NIA 4.1.1 기본 규칙](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-4.1.1-s3.json)

### 자료 밖 근거

- 보고서는 자료 밖 근거가 없다고 적었습니다.
- 다만 명도 대비 계산에 쓴 WCAG 상대 휘도 공식은 KWCAG 레코드 밖의 표준 지식이라고 밝혔습니다. [WCAG 2.2 상대 휘도 정의](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance)

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
|---|---|---|
| 초기 상태 확장 검사(위반 / 판정 보류 / 통과 규칙 수) | 1 / 0 / 17 | 0 / 0 / 18 |
| 위반 규칙과 측정 대비 | `color-contrast` 18개 요소(`p`, `h1` 등 2.84:1) | 없음 |
| 키보드 조작 | Tab 순서대로 초점 이동, 초점 표시 있음 | off와 같은 순서 |
| 폭 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | 0건 | 0건 |

### 브라우저에서 관찰한 결과

- 두 화면의 Tab 순서는 같았습니다.
- 두 화면의 차이는 본문, 날짜, 배지의 대비였습니다. off에서 18개 요소가 `color-contrast` 위반이었고, on에서는 위반이 없었습니다.
- 두 화면 모두 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- off와 on의 `index.html`은 같습니다.
- `style.css`에서 요청서의 `#999999`, `#bbbbbb`, `#c9a227`, 흰 배지 글씨가 모두 위 표의 색으로 바뀌었습니다.
- 폭 480px 이하에서 `.notice`가 `flex-direction: column`으로 바뀌어 배지, 제목, 날짜가 세로로 쌓입니다.
- 본문 바로가기 링크는 없습니다.

## 미검증 항목

- 스크린 리더 발화: 숨긴 목록 제목, 분류 배지, 날짜를 어떻게 읽는지 확인하지 않았습니다.
- 고대비 모드에서 강조 공지 상자가 테두리로 구분되는지 확인하지 않았습니다.
- 어두워진 글자색이 브랜드 톤으로 받아들여지는지는 디자인 판단으로 남겼습니다.
- 실제 터치 기기, Chrome 외 브라우저, 화면 확대 상태는 확인하지 않았습니다.
- 개발 중 읽지 못한 자료: 보고서는 읽지 못한 주소가 없고 레코드 13개를 받았다고 적었습니다. 5.4.1, 5.4.3, 5.4.4는 레코드 전체를 읽었고, 나머지는 본문과 기본 규칙만 읽었습니다. 보고서는 나머지를 일부만 읽은 이유를 적지 않았습니다. 개발 중에는 여러 레코드를 한 번에 내려받거나 읽는 복합 명령 일부가 셸 명령 제한으로 거부됐습니다. 사례 레코드는 화면에 모달이나 표 같은 중심 요소가 없어 읽지 않았다고 적었습니다. 이미지나 움직이는 콘텐츠가 없어 5.1.1, 6.2.2 등의 항목은 고르지 않았습니다.
