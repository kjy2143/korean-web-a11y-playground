# 자료실 링크 · 접근성 자료 적용 (on) 실행 결과

푸른숲도서관 자료실 링크 카드 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-resource-links-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사에서 off의 명도 대비 위반(카드 설명, 2.84:1)이 사라졌습니다. 링크 이름은 화면 글자 순서대로 제목과 설명이 이어지고 끝에 ‘새 탭에서 열림’이 붙도록 바뀌었습니다. 카드 목록 위에는 링크가 새 탭으로 열린다는 문장이 보이게 생겼습니다.

## 사용 방법

- 카드 세 개(‘도서관 이용 규정’, ‘전자책 서비스’, ‘지역 도서관 연합’) 중 하나를 누르면 대상 페이지(`rules.html`, `ebook.html`, `network.html`)가 새 탭으로 열립니다.
- 대상 페이지에는 제목과 한 문단만 있습니다.
- off 화면과 나란히 열어 카드 설명 색과 목록 위 안내 문장을 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 자료실 링크’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 자료실의 문서와 서비스 링크를 엽니다.
>
> 자료 링크 카드 세 개를 보여 줍니다. ‘도서관 이용 규정’(`rules.html`), ‘전자책 서비스’(`ebook.html`), ‘지역 도서관 연합’(`network.html`)이고, 세 대상 페이지도 같은 폴더에 제목과 한 문단으로 만듭니다.
>
> 디자인 시안: 모든 링크는 새 탭으로 엽니다. 카드 전체가 링크이고 카드 오른쪽에 ↗ 아이콘만 둡니다. 카드 제목은 18px 굵게, 카드 설명은 14px `#999999`입니다.

요청서 시안과 다르게 구현한 부분은 아래와 같습니다.

| 요청서 시안 | 조정한 내용 | 이유 |
| --- | --- | --- |
| 카드 설명 14px `#999999` | 색을 `#595959`로 바꿨습니다. 14px과 카드 제목 18px 굵게는 그대로입니다. | off의 카드 설명은 흰 배경 대비가 2.84:1(확장 측정)이라 4.5:1에 못 미칩니다(5.4.3). |
| 카드 오른쪽에 ↗ 아이콘만 | 카드 디자인은 지키고, 카드 목록 위에 ‘아래 링크는 모두 새 탭으로 열립니다. ↗ 표시가 있는 카드가 해당합니다.’를 보이게 넣었습니다. | 새 탭으로 열린다는 사실을 미리 알립니다(7.2.1). |

요청서와 관계없는 접근성 개선은 아래와 같습니다.

- 링크 이름이 화면 글자를 순서대로 포함하도록 고쳤습니다. off는 숨김 문구 ‘(새 탭)’이 제목 바로 뒤에 끼어 있었고, on은 제목, 설명, ‘새 탭에서 열림’ 순서입니다.
- 목록에 `role="list"`를 더했습니다. 개발 에이전트는 Safari에서 `list-style:none`이 목록 의미를 없애는 것을 막기 위해서라고 보고했습니다.
- 카드에 `position:relative`를 넣어 숨김 문구의 기준 위치를 카드로 잡았습니다.
- 카드 글자 묶음에 `min-width:0`, 카드 설명에 `overflow-wrap:anywhere`를 줘서 320px 폭에서 긴 글자가 카드 밖으로 나가지 않게 했습니다.

접근성과 무관한 기능 결함은 찾지 못했다고 보고했습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치고, 접근성과 무관한 기능 결함을 고쳤으면 따로 구분해 적게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

### NIA 제작기법 권장 사항

개발 에이전트는 각 레코드에 함께 실린 NIA 기본 규칙만 읽었고, 기본 규칙을 근거로 적용한 항목은 보고하지 않았습니다. 적용 사례와 개선 필요 사례는 읽지 않았습니다.

### 자료 밖 근거

- 새 탭 열기: HTML 표준의 `target="_blank"`와 `rel="noopener"`를 썼습니다. [HTML target 속성](https://html.spec.whatwg.org/multipage/links.html#attr-hyperlink-target) · [noopener](https://html.spec.whatwg.org/multipage/links.html#link-type-noopener)
- 목록 의미: `role="list"`를 썼습니다. [list 역할](https://www.w3.org/TR/wai-aria-1.2/#list)
- 새 탭 안내: 화면에서 숨긴 텍스트 기법을 썼습니다.

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 위반 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 12 | 0 / 0 / 16 |
| 주요 위반 규칙과 측정 대비 | color-contrast 3개 요소(`.card-desc`, 2.84:1) | 없음 |
| 키보드 조작 | Tab 이동과 초점 표시 있음 | Tab 이동과 초점 표시 있음 |
| 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | HTML 4개 모두 0건 | HTML 4개 모두 0건 |
| 첫 카드 링크 이름 | ‘도서관 이용 규정 (새 탭) …’ | ‘도서관 이용 규정 … 새 탭에서 열림’ |
| 새 탭 열림 | 열림 | 열림 |

### 브라우저에서 관찰한 결과

- on에서는 color-contrast 위반이 없었고, 통과 규칙이 12개에서 16개로 늘었습니다.
- 첫 카드 링크의 이름은 off가 ‘도서관 이용 규정 (새 탭) …’, on이 ‘도서관 이용 규정 … 새 탭에서 열림’이었습니다.
- 두 화면 모두 카드 링크가 새 탭으로 열렸습니다.
- 1280px에서 Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- 대상 페이지 세 개(`rules.html`, `ebook.html`, `network.html`)는 off와 같습니다.
- 카드 목록 위 안내 문장은 ‘아래 링크는 모두 새 탭으로 열립니다. ↗ 표시가 있는 카드가 해당합니다.’입니다.
- 카드 링크 안의 글자는 `card-title`, `card-desc`, 숨김 문구 ‘새 탭에서 열림’ 순서입니다.

## 미검증 항목

- 스크린 리더 발화: 링크가 ‘제목, 설명, 새 탭에서 열림’ 순서로 읽히는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다. Safari에서 `role="list"`의 효과도 확인하지 않았습니다.
- 음성 명령으로 카드 제목을 말해 링크를 고를 수 있는지 확인하지 않았습니다.
- 키보드 Enter로 연 경우를 따로 기록하지 않았습니다. 화면 확대에서 카드가 겹치지 않는지, 고대비 모드는 확인하지 않았습니다.

### 개발 중 읽지 못한 자료

- NIA 적용 사례와 개선 필요 사례는 읽지 않았습니다.
- 5.3.2, 6.1.1, 8.1.1은 검색 결과에서 본문이 길이 때문에 잘려 제목과 구조만 확인했습니다. 개발 에이전트는 이 항목들의 본문을 읽은 것으로 적지 않았습니다.
- 그 밖에 접근에 실패한 주소는 없었습니다.
