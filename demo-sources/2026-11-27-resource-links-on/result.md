# 자료실 링크 · 접근성 자료 적용 (on) 실행 결과

푸른숲도서관 자료실 링크 카드 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차로 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-resource-links-off) 화면을 복사한 뒤, 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

off와 달라진 코드는 카드 설명 글자색 한 줄입니다. `#999999`가 `#595959`로 바뀌었고, 확장 검사에서 off의 명도 대비 위반(카드 설명, 2.84:1)이 사라졌습니다. 새 탭 안내는 off와 같습니다. 화면에는 ↗ 아이콘만 보이고, 글자 ‘(새 탭 열림)’은 화면에서 숨긴 텍스트입니다.

## 사용 방법

- 카드 세 개(‘도서관 이용 규정’, ‘전자책 서비스’, ‘지역 도서관 연합’) 중 하나를 누르면 대상 페이지(`rules.html`, `ebook.html`, `network.html`)가 새 탭으로 열립니다.
- 대상 페이지에는 제목과 한 문단만 있습니다.
- off 화면과 나란히 열어 카드 설명의 글자색을 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 자료실 링크’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 자료실의 문서와 서비스 링크를 엽니다.
>
> 자료 링크 카드 세 개를 보여 줍니다. ‘도서관 이용 규정’(`rules.html`), ‘전자책 서비스’(`ebook.html`), ‘지역 도서관 연합’(`network.html`)이고, 세 대상 페이지도 같은 폴더에 제목과 한 문단으로 만듭니다.
>
> 디자인 시안: 모든 링크는 새 탭으로 엽니다. 카드 전체가 링크이고 카드 오른쪽에 ↗ 아이콘만 둡니다. 카드 제목은 18px 굵게, 카드 설명은 14px `#999999`입니다.

요청서 시안과 다르게 구현한 부분은 아래 한 가지입니다. 보고서는 이것이 시안과 다른 유일한 부분이라고 적었습니다.

| 요청서 시안 | 조정한 내용 | 보고서에 적은 이유 |
| --- | --- | --- |
| 카드 설명 14px `#999999` | 색을 `#595959`로 바꿨습니다. 14px과 카드 제목 18px 굵게는 그대로입니다. | 기존 색은 흰 카드 배경에서 대비가 약 2.85:1이라 4.5:1에 못 미칩니다(5.4.3). 14px 보통 굵기 글자는 3:1 완화 대상이 아닙니다. |

보고서가 off 구현을 그대로 두었다고 적은 부분은 아래와 같습니다.

- 카드 전체가 링크이고 오른쪽에 ↗ 아이콘이 있습니다.
- 새 탭 안내는 화면에서 숨긴 텍스트 ‘(새 탭 열림)’으로 제공하고, ↗는 `aria-hidden`입니다.
- 링크 이름은 화면에 보이는 제목과 설명 글자로 시작하고, 뒤에 새 탭 안내가 붙습니다.
- 건너뛰기 링크는 더하지 않았습니다. 메뉴나 반복되는 링크 목록이 없고 첫 Tab이 바로 첫 카드로 가서, 건너뛸 반복 영역이 없다고 판단했습니다.

보고서는 접근성과 무관한 기능 결함을 찾지 못했다고 적었습니다. 제안도 하나 남겼습니다. ↗ 아이콘의 뜻이 눈으로는 바로 드러나지 않으므로 아이콘 옆에 보이는 글자를 더하는 방법이 있다는 내용입니다. 요청서가 아이콘만 두라고 해서 적용하지는 않았습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 개발 에이전트는 실제 화면을 열어 보지 못하고 코드와 명령으로만 확인했다고 보고했습니다.
- 셸 명령: 허용한 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 2건이고, 종류는 `for` 반복 명령과 `python3`입니다. 개발 에이전트는 명도 대비 계산 스크립트를 실행하지 못해 상대 휘도 공식으로 직접 계산했다고 보고했습니다.
- 자료 조회: 설정 확인, 절차 문서, 자료 목록, 레코드 순서로 읽었습니다. 화면 종류와 관계없이 고르는 12개 항목(5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1)의 레코드를 모두 받았습니다. 여기에 6.4.1과 6.4.3을 더해 KWCAG 레코드 14개를 읽었습니다. NIA 사례 레코드는 2.4.1, 2.4.3, 3.2.1의 적용 사례와 개선 필요 사례 6개를 읽었습니다. 자료 조회 명령 21회는 모두 주소 하나에 명령 하나인 같은 형태였고, 실패한 조회는 없었습니다.
- 수정 요청: 이 화면에는 검증 뒤 수정 요청을 보내지 않았습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 첫 실행에서는 on 화면을 만들지 않았습니다. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. 이때 off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

### 자료 밖 근거

보고서는 자료 밖 근거가 없다고 적었습니다. off에서 넣은 `target="_blank"`, `rel="noopener"`, `aria-hidden` 처리는 on에서 바뀌지 않았습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다. 위반 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 12 | 0 / 0 / 13 |
| 주요 위반 규칙과 측정 대비 | color-contrast 3개 요소(`.desc`, 2.84:1) | 없음 |
| 카드 설명 글자색(코드) | `#999999` | `#595959` |
| 보이는 새 탭 표시 | ↗ 아이콘 | ↗ 아이콘 |
| 글자로 된 새 탭 안내 | 화면에서 숨긴 텍스트 ‘(새 탭 열림)’ | 화면에서 숨긴 텍스트 ‘(새 탭 열림)’ |
| 새 탭 열림 | 첫 카드 클릭으로 `rules.html`이 새 탭에 열림 | 같음 |
| 키보드 조작 | Tab으로 카드 링크 세 개에 차례로 이동, 초점 표시 있음 | 같음 |
| 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | HTML 4개 모두 0건 | HTML 4개 모두 0건 |
| 콘솔 오류 | 초기 상태 0건 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- on에서는 `color-contrast` 위반이 없었습니다. 위반 규칙이 1개에서 0개로, 통과 규칙이 12개에서 13개로 바뀌었습니다.
- 두 화면 모두 첫 카드를 클릭하면 `rules.html`이 새 탭으로 열렸습니다. 새 탭의 제목은 ‘도서관 이용 규정 - 한국 웹 접근성 플레이그라운드’였습니다.
- 두 화면의 링크 글자는 같았습니다. 첫 카드는 ‘도서관 이용 규정 대출·반납과 열람실 이용 규칙을 안내합니다. ↗ (새 탭 열림)’이었습니다. 이 값은 링크의 `innerText`이고, 화면에서 숨긴 텍스트와 ↗ 글자를 함께 담고 있습니다.
- 두 화면 모두 ‘(새 탭 열림)’ 세 개가 화면에서 숨기는 클래스(`sr-only`)의 요소 안에 있었고, 링크에 `aria-label`은 없었습니다.
- 두 화면 모두 `main` 영역에 새 탭으로 열린다고 알리는 보이는 문단은 없었습니다.

### 코드에서 확인한 사실

- off와 on의 차이는 `style.css`의 카드 설명 글자색 한 줄입니다. `index.html`과 대상 페이지 세 개(`rules.html`, `ebook.html`, `network.html`)는 off와 같습니다.
- 새 탭 안내는 두 화면이 같습니다. 화면에 보이는 것은 `aria-hidden="true"`인 ↗ 아이콘이고, 글자 ‘(새 탭 열림)’은 링크 끝의 숨긴 텍스트입니다.
- 링크 안의 글자는 카드 제목, 카드 설명, ↗ 아이콘, 숨긴 텍스트 순서입니다.
- 카드 초점 표시는 3px `#1a4fd6` 윤곽선이고, 카드 사이 간격은 12px입니다.

## 미검증 항목

- 스크린 리더 발화: 링크 이름 끝의 ‘(새 탭 열림)’을 읽는지 확인하지 않았습니다. 링크의 접근 가능한 이름도 따로 기록하지 않았습니다.
- 키보드 Enter로 링크를 열 때 새 탭이 열리는지 확인하지 않았습니다. 마우스 클릭은 첫 카드만 확인했습니다.
- 바꾼 글자색의 측정 대비는 기록에 없습니다. 확장 검사는 위반 요소의 대비만 남깁니다. 보고서의 약 7.0:1(흰 배경)과 약 6.5:1(마우스를 올린 배경 `#f0f7f2`)은 개발 에이전트가 손으로 계산한 어림값입니다.
- 폭 320px에서 긴 제목이 줄바꿈되는지 눈으로 확인하지 않았습니다. 가로 스크롤이 없다는 것만 확인했습니다.
- 실제 터치 기기, Chrome 이외의 브라우저, 화면 확대 상태에서는 확인하지 않았습니다.
