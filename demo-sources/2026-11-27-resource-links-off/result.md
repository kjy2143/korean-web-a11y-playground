# 자료실 링크 · 기본 개발 (off) 실행 결과

푸른숲도서관 자료실의 문서와 서비스 링크 카드 세 개를 보여 주는 화면입니다. 카드를 누르면 대상 페이지가 새 탭으로 열립니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-resource-links-on)에 있습니다.

확장 검사에서 카드 설명 세 개가 명도 대비 위반(2.84:1)으로 나왔습니다. 새 탭으로 열린다는 사실은 화면에서 ↗ 아이콘으로만 보이고, 보조기술에는 카드 제목 바로 뒤의 숨김 텍스트 ‘(새 탭)’으로 알립니다.

## 사용 방법

- 카드 세 개(‘도서관 이용 규정’, ‘전자책 서비스’, ‘지역 도서관 연합’) 중 하나를 누르면 대상 페이지(`rules.html`, `ebook.html`, `network.html`)가 새 탭으로 열립니다.
- 대상 페이지에는 제목과 한 문단만 있습니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 자료실 링크’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 자료실의 문서와 서비스 링크를 엽니다.
>
> 자료 링크 카드 세 개를 보여 줍니다. ‘도서관 이용 규정’(`rules.html`), ‘전자책 서비스’(`ebook.html`), ‘지역 도서관 연합’(`network.html`)이고, 세 대상 페이지도 같은 폴더에 제목과 한 문단으로 만듭니다.
>
> 디자인 시안: 모든 링크는 새 탭으로 엽니다. 카드 전체가 링크이고 카드 오른쪽에 ↗ 아이콘만 둡니다. 카드 제목은 18px 굵게, 카드 설명은 14px `#999999`입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다.
- 지시: 요청서 전문을 주고, 질문하지 말고 구현을 마친 뒤 만든 파일과 판단이 필요했던 점을 보고하게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. 개발 에이전트는 화면을 브라우저로 열어 보지 않았다고 보고했습니다.
- 수정 요청: 이 화면에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 새 탭 열기 | 카드 링크에 `target="_blank"`와 `rel="noopener"`를 달았습니다. | [HTML target 속성](https://html.spec.whatwg.org/multipage/links.html#attr-hyperlink-target), [noopener](https://html.spec.whatwg.org/multipage/links.html#link-type-noopener) |
| 새 탭 안내 | 카드 제목 바로 뒤에 화면에서 숨긴 텍스트 ‘ (새 탭)’을 넣었습니다. | 해당 없음 |
| ↗ 아이콘 | 아이콘 글자에 `aria-hidden="true"`를 달았습니다. | [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 초점 표시 | 카드의 `:focus-visible`에 3px 파란 윤곽선을 그립니다. | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo) |
| 기본 언어와 제목 | 네 페이지 모두 `<html lang="ko">`이고, 각자 `<title>`과 `h1`이 있습니다. | [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- 요청서에 카드 설명과 대상 페이지 문구가 없어 임의로 지어 썼습니다.
- 대상 페이지의 설명(meta description)은 본문 문단과 같은 문장입니다.
- ↗ 아이콘만 두는 시안은 지키고, 새 탭 안내를 숨김 텍스트로 더했습니다.

카드 설명 14px `#999999`는 요청서대로 두었습니다. 개발 에이전트는 흰 배경 대비가 기준에 못 미친다고 보고하고, 시안 변경을 검토해 달라고 남겼습니다.

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 위반 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 12 |
| 위반 규칙과 측정 대비 | color-contrast 3개 요소(`.card-desc`, 2.84:1) |
| 키보드 조작 | Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 초점 표시가 있었습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html`, `rules.html`, `ebook.html`, `network.html` 모두 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- 카드를 클릭하면 `rules.html`이 새 탭으로 열렸습니다.
- 첫 카드 링크의 접근 가능한 이름은 ‘도서관 이용 규정 (새 탭) …’으로 시작했습니다.

### 코드에서 확인한 사실

- 링크 이름은 카드 제목, 숨김 텍스트 ‘(새 탭)’, 카드 설명 순서로 이어집니다. 화면에 보이는 글자 순서(제목, 설명) 사이에 보이지 않는 글자가 끼어 있습니다.
- 목록은 `ul`에 `list-style:none`을 주었고 `role`은 따로 지정하지 않았습니다.
- 화면에는 모든 링크가 새 탭으로 열린다는 문장이 없습니다.

## 미검증 항목

- 스크린 리더 발화: 링크 이름과 새 탭 안내를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 음성 명령으로 카드 제목을 말해 링크를 고를 수 있는지 확인하지 않았습니다.
- 화면 확대와 고대비 모드는 확인하지 않았습니다.
