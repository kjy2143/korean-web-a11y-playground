# 자료실 링크 · 기본 개발 (off) 실행 결과

푸른숲도서관 자료실의 문서와 서비스 링크 카드 세 개를 보여 주는 화면입니다. 카드를 누르면 대상 페이지가 새 탭으로 열립니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 화면 요청서만으로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-resource-links-on)에 있습니다.

확장 검사에서 카드 설명 세 개가 명도 대비 위반(2.84:1)으로 나왔습니다. 새 탭으로 열린다는 사실은 화면에서 ↗ 아이콘으로만 보이고, 글자 ‘(새 탭 열림)’은 링크 끝에 화면에서 숨긴 텍스트로 들어 있습니다.

## 사용 방법

- 카드 세 개(‘도서관 이용 규정’, ‘전자책 서비스’, ‘지역 도서관 연합’) 중 하나를 누르면 대상 페이지(`rules.html`, `ebook.html`, `network.html`)가 새 탭으로 열립니다.
- 대상 페이지에는 제목과 한 문단만 있습니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 자료실 링크’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 자료실의 문서와 서비스 링크를 엽니다.
>
> 자료 링크 카드 세 개를 보여 줍니다. ‘도서관 이용 규정’(`rules.html`), ‘전자책 서비스’(`ebook.html`), ‘지역 도서관 연합’(`network.html`)이고, 세 대상 페이지도 같은 폴더에 제목과 한 문단으로 만듭니다.
>
> 디자인 시안: 모든 링크는 새 탭으로 엽니다. 카드 전체가 링크이고 카드 오른쪽에 ↗ 아이콘만 둡니다. 카드 제목은 18px 굵게, 카드 설명은 14px `#999999`입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 끄고 화면 요청서만 주었습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값만 읽었습니다. 자료 목록과 검사항목 레코드는 한 번도 받지 않았고, 실행 기록에서 자료 조회가 0회임을 확인했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 개발 에이전트는 화면을 브라우저에서 열어 보거나 폭 320px로 확인하지 않았다고 보고했습니다.
- 셸 명령: 허용한 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 1건이고, `cd` 뒤에 다른 명령을 이은 복합 명령이었습니다. 거부된 뒤에도 파일 다섯 개(`index.html`, `style.css`, 대상 페이지 세 개)는 모두 만들어졌습니다.
- 수정 요청: 브라우저 확인에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 첫 실행에서는 on 화면을 만들지 않았습니다. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. 이때 off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 새 탭 열기 | 카드 링크에 `target="_blank"`와 `rel="noopener"`를 달았습니다. | [HTML target 속성](https://html.spec.whatwg.org/multipage/links.html#attr-hyperlink-target), [noopener](https://html.spec.whatwg.org/multipage/links.html#link-type-noopener) |
| 새 탭 안내 | 링크 안의 맨 끝에 화면에서 숨긴 텍스트 ‘(새 탭 열림)’을 넣었습니다. | 해당 없음 |
| ↗ 아이콘 | 아이콘 글자에 `aria-hidden="true"`를 달았습니다. | [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 카드 묶음 | 카드 전체를 `a` 하나로 만들고 `ul` 목록의 `li` 안에 두었습니다. | [HTML ul 요소](https://html.spec.whatwg.org/multipage/grouping-content.html#the-ul-element) |
| 초점 표시 | 카드의 `:focus-visible`에 3px 파란(`#1a4fd6`) 윤곽선을 그립니다. | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo) |
| 기본 언어와 제목 | 네 페이지 모두 `<html lang="ko">`이고, 각자 `<title>`과 `h1`이 있습니다. | [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- 요청서에 카드 설명 문구와 대상 페이지 본문이 없어 임의로 썼습니다. 대상 페이지의 설명(meta description)도 같은 방식으로 정했습니다.
- ↗ 아이콘만 두는 시안은 지키고, 새 탭 안내를 화면에서 숨긴 텍스트로 더했습니다.

카드 설명 14px `#999999`는 요청서대로 두었습니다. 개발 에이전트는 흰 배경에서 대비가 약 2.8:1이라 일반 텍스트 기준(4.5:1)에 못 미친다고 보고했습니다. 시안을 바꿀 수 있다면 `#767676` 이상으로 어둡게 하는 편이 좋다고 덧붙였습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다. 위반 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 12 |
| 위반 규칙과 측정 대비 | color-contrast 3개 요소(`.desc`, 2.84:1, 전경색 `#999999`, 배경색 `#ffffff`, 14px 보통 굵기) |
| 키보드 조작 | Tab으로 카드 링크 세 개에 차례로 초점이 이동했고, 정지점마다 초점 표시가 있었습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html`, `rules.html`, `ebook.html`, `network.html` 모두 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- 첫 카드를 클릭하면 `rules.html`이 새 탭으로 열렸습니다. 새 탭의 제목은 ‘도서관 이용 규정 - 한국 웹 접근성 플레이그라운드’였습니다.
- 첫 카드 링크의 글자는 ‘도서관 이용 규정 대출·반납과 열람실 이용 규칙을 안내합니다. ↗ (새 탭 열림)’이었습니다. 이 값은 링크의 `innerText`이고, 화면에서 숨긴 텍스트와 ↗ 글자를 함께 담고 있습니다.
- ‘(새 탭 열림)’ 세 개는 모두 화면에서 숨기는 클래스(`sr-only`)의 요소 안에 있었습니다. 링크 세 개 모두 `aria-label`은 없었습니다.
- `main` 영역에 새 탭으로 열린다고 알리는 보이는 문단은 없었습니다.

### 코드에서 확인한 사실

- 링크 안의 글자는 카드 제목, 카드 설명, ↗ 아이콘, 숨긴 텍스트 ‘(새 탭 열림)’ 순서입니다. ↗는 `aria-hidden="true"`입니다.
- 화면에 보이는 새 탭 표시는 ↗ 아이콘뿐입니다. 머리글의 안내 문장은 ‘자료실의 문서와 서비스 링크를 엽니다.’이고 새 탭을 언급하지 않습니다.
- 카드 제목은 18px 굵게 `#222`, 카드 설명은 14px `#999999`, 카드 배경은 `#fff`입니다.
- 마우스를 올리면 카드 배경이 `#f0f7f2`로, 테두리가 `#2d6a4f`로 바뀝니다.
- 카드 제목과 설명에 `overflow-wrap: anywhere`를 주었습니다.
- 대상 페이지 세 개는 기관명, `h1`, 문단 하나로 되어 있습니다.

## 미검증 항목

- 스크린 리더 발화: 링크 이름과 ‘(새 탭 열림)’을 어떻게 읽는지 확인하지 않았습니다. 링크의 접근 가능한 이름도 따로 기록하지 않았습니다.
- 키보드 Enter로 링크를 열 때 새 탭이 열리는지 확인하지 않았습니다. 마우스 클릭은 첫 카드만 확인했습니다.
- 마우스를 올린 상태(`#f0f7f2` 배경)의 대비는 측정하지 않았습니다.
- 폭 320px에서 긴 제목이 줄바꿈되는지 눈으로 확인하지 않았습니다. 가로 스크롤이 없다는 것만 확인했습니다.
- 실제 터치 기기, Chrome 이외의 브라우저, 화면 확대 상태에서는 확인하지 않았습니다.
