# 이용 안내 창 · 접근성 자료 적용 (on) 실행 결과

자동으로 열리는 ‘12월 이용 안내’ 창을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-modal-layer-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사 결과는 off와 같았습니다. 두 화면 모두 창이 열린 상태와 닫힌 상태에서 위반과 판정 보류가 없었습니다. on 개발 에이전트는 창의 HTML 위치를 본문 앞으로 옮기고, 창을 닫는 처리를 한곳으로 모았습니다.

## 사용 방법

- 페이지에 들어오면 안내 창이 자동으로 열립니다.
- 창 오른쪽 위의 X 버튼, Esc 키, 창 바깥 누르기로 창을 닫습니다.
- ‘오늘 하루 보지 않기’를 선택하고 닫으면 그날은 창이 자동으로 열리지 않습니다.
- ‘이용 안내 보기’ 버튼으로 언제든 창을 다시 엽니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 이용 안내 창’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 안내 창을 열어 읽고 닫습니다.
>
> 도서관 소개 본문 두 문단과 ‘이용 안내 보기’ 버튼이 있는 페이지입니다. 페이지에 들어오면 ‘12월 이용 안내’ 창이 자동으로 열립니다. 창에는 제목, 안내 세 줄(연말 휴관, 대출 기간 연장, 무인 반납함 이용), ‘오늘 하루 보지 않기’ 체크, 닫기가 있습니다. ‘오늘 하루 보지 않기’를 체크하고 닫으면 그날은 자동으로 열리지 않습니다. ‘이용 안내 보기’ 버튼으로는 언제든 다시 엽니다.
>
> 디자인 시안: 닫기는 창 오른쪽 위의 X 아이콘만 둡니다. 뒤 화면은 반투명 검정으로 덮습니다. 창 바깥을 누르면 닫힙니다. ‘오늘 하루 보지 않기’ 글씨는 12px `#aaaaaa`입니다.

요청서 시안과 다르게 구현한 부분은 두 가지입니다.

| 요청서 시안 | 조정한 내용 | 이유 |
| --- | --- | --- |
| ‘오늘 하루 보지 않기’ 12px `#aaaaaa` | 12px은 두고 색을 `#666`으로 바꿨습니다. 이 조정은 off에 이미 있었고 on에서 유지했습니다. | `#aaaaaa`는 흰 배경에서 4.5:1에 못 미칩니다(5.4.3, KWCAG 요구사항). |
| 닫기는 X 아이콘만 | 아이콘만 두고, 보조기술이 읽도록 `aria-label="닫기"`를 유지했습니다. 조작 영역은 44×44px입니다. | 보이는 글자가 없어 6.5.3에는 해당하지 않는다고 판단했습니다. 크기는 6.1.3을 따랐습니다. |

반투명 검정 배경, 창 바깥 클릭으로 닫기, 페이지 진입 때 자동 열기는 시안대로 두었습니다. 개발 에이전트는 자동 열기가 7.2.1 본문의 ‘팝업창 등은 사용자가 인지하지 못한 상황에서 열리지 않아야 한다’와 부딪힐 수 있다고 적었습니다. 그러나 모달이 열리면 초점이 창 안으로 옮겨져 사용자가 알 수 있고, NIA 제작기법에 진입 때 모달을 여는 사례가 있어 유지했다고 보고했습니다. 이 판단은 개발 에이전트가 내린 것입니다.

요청서와 관계없이 고친 부분은 아래와 같습니다.

| 구분 | 내용 |
| --- | --- |
| 접근성 개선 | `dialog`를 `body`의 맨 앞으로 옮겼습니다. 자동으로 열리는 모달을 본문보다 앞에 두라는 NIA 적용 사례를 따랐습니다. |
| 접근성과 무관한 기능 수정 | 닫는 처리를 `close` 이벤트 한곳으로 모았습니다. 개발 에이전트는 off에서 Esc를 두 번 누르는 등 `cancel` 이벤트를 거치지 않고 닫히면 ‘오늘 하루 보지 않기’가 저장되지 않았다고 보고했습니다. |
| 접근성과 무관한 기능 수정 | 창 안에서 글자를 끌다가 바깥에서 놓으면 창이 닫히던 문제를 고쳤습니다. 이제 누른 곳과 뗀 곳이 모두 창 바깥일 때만 닫힙니다. |

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치고, 접근성과 무관한 기능 결함을 고쳤으면 따로 구분해 적게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

### 자료 밖 근거

- 모달 창: 네이티브 `dialog`와 `showModal()`을 썼습니다. 개발 에이전트는 이 방식이 창 안에 초점을 가두고, 뒤 화면을 비활성화하고, 창 역할을 자동으로 준다고 보고했습니다. [HTML dialog 요소](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)
- 닫기 처리: 닫는 경로를 `close` 이벤트로 통일했습니다. [close 이벤트](https://html.spec.whatwg.org/multipage/indices.html#event-close)
- 날짜 저장: 오늘 날짜를 `localStorage`에 저장합니다. [localStorage](https://html.spec.whatwg.org/multipage/webstorage.html#dom-localstorage)

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서입니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 확장 검사: 초기 상태(창 열림) | 0 / 0 / 20 | 0 / 0 / 20 |
| 확장 검사: 창 닫음 | 0 / 0 / 12 | 0 / 0 / 12 |
| 주요 위반 규칙과 측정 대비 | 없음 | 없음 |
| 키보드 조작 | 진입 시 초점이 닫기 버튼, Esc로 닫으면 ‘이용 안내 보기’ 버튼으로 복귀 | off와 같음 |
| 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | 0건 | 0건 |

### 브라우저에서 관찰한 결과

- 두 화면 모두 진입하면 창이 열렸고 초점은 닫기 버튼에 있었습니다.
- 두 화면 모두 Esc로 창을 닫으면 초점이 ‘이용 안내 보기’ 버튼으로 돌아왔습니다.
- 확장 검사의 규칙 수는 두 상태 모두 off와 같았습니다. 창의 HTML 위치를 옮긴 변화는 확장 검사 수치에 나타나지 않았습니다.
- 1280px에서 Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- on의 `dialog`는 `body`의 첫 요소이고, 머리글과 본문은 그 뒤에 있습니다.
- X 버튼은 `dlg.close()`만 부르고, Esc와 바깥 클릭도 창을 닫기만 합니다. ‘오늘 하루 보지 않기’ 저장과 초점 복귀는 `close` 이벤트 한곳에서 처리합니다.
- 바깥 클릭은 `pointerdown`에서 누른 위치가 창 밖인지 기록하고, `click`에서 뗀 위치도 창 밖일 때만 닫습니다.
- 창이 이미 열려 있으면 다시 열지 않습니다(`if (dlg.open) return`).

## 미검증 항목

- 스크린 리더 발화: 창이 열릴 때 대화상자 역할과 제목을 읽는지, 뒤 본문을 읽지 않는지, X 버튼을 ‘닫기’로 읽는지 확인하지 않았습니다. 창을 본문 앞으로 옮긴 효과도 보조기술로 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- ‘오늘 하루 보지 않기’를 선택하고 각 방법으로 닫은 뒤 새로고침했을 때의 동작은 두 화면 모두 확인하지 않았습니다. 개발 에이전트가 보고한 off의 저장 누락(Esc를 두 번 누르는 경우)도 브라우저에서 재현하지 않았습니다.
- on 화면의 X 버튼과 바깥 클릭으로 닫기, 창 안에서 끌어 바깥에서 놓는 동작, Tab과 Shift+Tab의 창 안 순환은 기록하지 않았습니다.
- 폭 320px에서 창 내용이 잘리지 않고 스크롤되는지, 화면 200% 확대와 고대비 모드는 확인하지 않았습니다.
