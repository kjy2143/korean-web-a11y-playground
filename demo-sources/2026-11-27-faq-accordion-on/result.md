# 자주 묻는 질문 · 접근성 자료 적용 (on) 실행 결과

푸른숲도서관 자주 묻는 질문 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-faq-accordion-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사에서 off에 남아 있던 명도 대비 판정 보류가 사라져, 두 상태 모두 위반과 판정 보류가 0이 됐습니다. 바꾼 곳은 `style.css`의 ‘Q’, ‘A’ 글자색과 ‘바로가기’ 링크 크기뿐입니다. 펼침 동작과 Tab 순서는 off와 같았습니다.

## 사용 방법

- 질문 줄을 누르면 답이 펼쳐지고, 다시 누르면 접힙니다. 키보드로는 Tab으로 질문에 초점을 두고 Enter나 Space를 누릅니다.
- 여러 질문을 동시에 펼칠 수 있습니다.
- 답 끝의 ‘바로가기’ 링크는 요청서대로 주소가 `#`입니다.
- off 화면과 나란히 열어 ‘Q’, ‘A’ 글자색을 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 자주 묻는 질문’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 질문을 눌러 답을 펼치고 안내 페이지로 이동합니다.
>
> 질문 다섯 개(회원증 발급, 대출 권수와 기간, 연체, 열람실 예약, 분실 도서)와 답을 보여 줍니다. 질문을 누르면 답이 펼쳐지고 다시 누르면 접힙니다. 여러 개를 동시에 펼쳐도 됩니다. 답마다 관련 안내 페이지 링크가 하나씩 있습니다(주소는 `#`).
>
> 디자인 시안: 질문 줄 전체가 누르는 영역이고 오른쪽 끝에 +/− 아이콘이 있습니다(펼치면 −). 답 안의 링크는 문장 끝의 ‘바로가기’입니다. 질문 앞 ‘Q’는 연한 초록 `#9ccc9c` 굵은 글씨, 답 앞 ‘A’는 `#cccccc`입니다.

요청서 시안과 다르게 구현한 부분은 아래와 같습니다. 근거 구분은 on 개발 에이전트의 보고를 따랐습니다.

| 요청서 시안 | 조정한 내용 | 이유 |
| --- | --- | --- |
| 질문 앞 ‘Q’ 연한 초록 `#9ccc9c` 굵은 글씨 | 초록 계열의 `#2e7d32`로 바꿨습니다. | 시안 색은 큰 글씨 기준 3:1에도 못 미친다고 판단했습니다(5.4.3, KWCAG 요구사항). |
| 답 앞 ‘A’ `#cccccc` | `#6b6b6b`로 바꿨습니다. | 답 배경 `#f7f7f7` 위에서 대비를 확보했습니다(5.4.3, KWCAG 요구사항). |
| 문장 끝의 ‘바로가기’ 링크 | 링크에 `display:inline-block`, `min-height:24px`, 좌우 2px 안쪽 여백을 줬습니다. | 최소 조작 크기 24px를 맞췄습니다(6.1.3, NIA 권장 사항). |

질문 줄 전체를 누르는 영역, 오른쪽 +/− 아이콘, 문장 끝 ‘바로가기’ 위치, 질문 다섯 개와 답은 시안대로입니다. `index.html`과 `script.js`는 바꾸지 않았습니다. 접근성과 무관한 기능 결함은 찾지 못했다고 보고했습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치고, 접근성과 무관한 기능 결함을 고쳤으면 따로 구분해 적게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

### NIA 제작기법 권장 사항

- 링크 조작 크기: ‘바로가기’ 링크의 최소 높이를 24px로 맞췄습니다. 개발 에이전트는 [6.1.3 조작 가능](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.3.json)을 권장 사항으로 분류했습니다. 24px 기준은 [NIA 2.1.3 기본 규칙](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-2.1.3-s3.json)에 있습니다.

### 자료 밖 근거

- 펼침 구조: 제목 안의 버튼(`h2 > button`), `aria-expanded`, `aria-controls`, 답 영역의 `hidden` 속성은 웹 표준 지식에 근거합니다. off에 이미 있었고 이번에 바꾸지 않았습니다. [aria-expanded](https://www.w3.org/TR/wai-aria-1.2/#aria-expanded) · [aria-controls](https://www.w3.org/TR/wai-aria-1.2/#aria-controls) · [HTML hidden 속성](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute)
- 답 영역: `role="region"`과 `aria-labelledby`도 같은 근거이고 바꾸지 않았습니다. [region 역할](https://www.w3.org/TR/wai-aria-1.2/#region) · [aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby)

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 판정 보류 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 확장 검사: 초기 상태 | 0 / 1 / 19 | 0 / 0 / 20 |
| 확장 검사: 첫 질문 펼침 | 0 / 1 / 24 | 0 / 0 / 24 |
| 주요 위반·판정 보류 규칙 | 위반 없음. color-contrast 판정 보류(초기 5개 요소, 펼침 6개 요소) | 없음 |
| 키보드 조작 | Tab 이동과 초점 표시 있음. Enter로 `aria-expanded="true"` | off와 같음. Tab 순서도 같음 |
| 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | 0건 | 0건 |

### 브라우저에서 관찰한 결과

- on의 초기 상태에서는 off에서 판정 보류였던 color-contrast가 통과로 바뀌어 통과 규칙이 19개에서 20개로 늘었습니다.
- 첫 질문을 펼친 상태에서는 off의 판정 보류가 사라졌고, 통과 규칙 수는 두 화면 모두 24개였습니다.
- 두 화면 모두 질문에서 Enter를 누르면 `aria-expanded`가 `true`가 됐습니다. Tab 순서는 같았습니다.
- 1280px에서 Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- off와 on의 차이는 `style.css`의 세 줄입니다. ‘Q’는 `#9ccc9c`에서 `#2e7d32`로, ‘A’는 `#ccc`에서 `#6b6b6b`로 바뀌었고, ‘바로가기’ 링크에 `display:inline-block; min-height:24px; padding:0 2px`가 더해졌습니다.
- ‘Q’, ‘A’ 글자는 두 화면 모두 `aria-hidden="true"`입니다.

## 미검증 항목

- 스크린 리더 발화: 링크가 ‘바로가기: 회원증 발급 안내’처럼 읽히는지, 펼침 상태를 어떻게 알리는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- on 화면의 마우스 클릭 펼침·접힘, Space 키 동작, 여러 질문 동시 펼침은 브라우저에서 따로 기록하지 않았습니다.
- `inline-block`으로 바꾼 링크가 줄바꿈 위치에서 어색하지 않은지, 고대비 모드에서 +/− 아이콘이 보이는지 확인하지 않았습니다.

### 개발 중 읽지 못한 자료

- NIA 제작기법의 적용 사례와 개선 필요 사례는 읽지 않았습니다.
- 자료 목록과 위 14개 항목의 레코드는 모두 읽었고, 읽지 못한 주소는 없었습니다.
- 명도 대비는 스크립트와 `sed` 실행이 셸 명령 제한으로 거부돼 손으로 계산했습니다. `style.css`를 고친 뒤 파일을 다시 열어 확인하지 않았다고 보고했습니다.
