# 전시 일정 · 접근성 자료 적용 (on) 실행 결과

푸른숲미술관 전시 네 건을 전시 이름과 관람 요일로 찾는 화면입니다. 기본 개발 화면을 복사한 뒤, 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선했습니다.

비교 대상인 기본 개발 화면은 [전시 일정 · 기본 개발 (off)](/?demo=2026-11-27-exhibition-filter-off)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열면 전시 네 건과 결과 건수 ‘총 4건’이 보입니다.
2. ‘전시 이름 검색’ 입력란에 이름 일부를 쓰거나 요일 선택에서 수·토·일 중 하나를 고릅니다. 첫 항목 ‘요일’은 전체를 뜻합니다.
3. 돋보기 버튼을 누르거나 입력란에서 Enter를 누르면 결과와 건수가 바뀝니다.
4. 결과가 없으면 ‘총 0건’과 ‘조건에 맞는 전시가 없습니다’가 나옵니다.
5. ↺ 버튼을 누르면 조건을 비우고 네 건을 다시 보여 준 뒤 이름 입력란으로 초점을 옮깁니다.

## 요청서와 조정한 부분

‘화면 요청서: 전시 일정’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 전시 이름과 관람 요일로 전시 일정을 찾습니다.
>
> 전시 네 개를 보여 주고 이름과 요일로 찾습니다. 전시는 ‘종이로 만든 풍경’(수 14:00, 제1전시실), ‘색으로 읽는 도시’(토 11:00, 제2전시실), ‘종이 위의 정원’(토 15:00, 열린 작업실), ‘주말에 만나는 판화’(일 13:00, 제1전시실)입니다. 이름 검색란, 요일 선택(전체·수·토·일), 검색 버튼, 초기화 버튼이 있습니다. 결과 건수를 표시하고, 결과가 없으면 ‘조건에 맞는 전시가 없습니다’를 보여 줍니다.
>
> 디자인 시안: 검색란은 안내 문구 ‘전시 이름 검색’만 둡니다. 요일 선택은 제목 없이 첫 항목을 ‘요일’로 둡니다. 검색 버튼은 돋보기 아이콘, 초기화는 ↺ 아이콘입니다. 결과 건수 ‘총 4건’은 13px `#aaaaaa`입니다.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트가 조정한 내용과 보고서에 적은 이유는 다음과 같습니다. 이번 개선에서 바뀐 파일은 `style.css` 하나입니다.

| 요청서 또는 off 화면 | on 화면 | 보고서에 적은 이유 |
|---|---|---|
| 결과 건수 13px `#aaaaaa` | 13px `#595959` | 흰 배경에서 4.5:1에 못 미침(5.4.3) |
| 안내 문구의 색 지정 없음 | `::placeholder`에 `#595959`와 `opacity: 1` 지정 | 안내 문구도 텍스트라 5.4.3 대상. 시안과 충돌하지 않음 |

- 안내 문구만 있는 이름 검색란과 제목 없는 요일 선택은 시안대로 두었습니다. 화면에서 숨긴 `label`이 이미 연결돼 있어 7.3.2를 충족한다고 판단했습니다.
- 돋보기 아이콘과 ↺ 아이콘 버튼은 `aria-label`로 이름을 제공하고 있어 유지했습니다.
- 보고서는 코드를 읽어 확인한 범위에서 접근성과 무관한 기능 결함이 없다고 적었습니다. 이름 검색, 요일 필터, 건수 표시, 빈 결과 문구, 초기화는 요청서와 일치한다고 판단했습니다.

## 개발 조건

- 출발점: off 화면을 복사한 뒤 국내 접근성 자료를 조회해 적용하는 절차를 켜고 같은 요청서 기준으로 개선했습니다.
- 충돌 처리: 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 개발 중 확인: 개발 에이전트는 브라우저 도구가 없어 화면을 열지 못했고 코드와 명령으로만 확인했다고 보고했습니다.
- off 파일 보존: on 개발 뒤에도 off 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준과 참고 자료

근거 구분은 개발 에이전트의 보고서를 따릅니다. 보고서는 레코드 종류가 요구사항인 본문을 요구사항으로, NIA 제작기법의 기본 규칙을 권장 사항으로 구분했습니다.

- 아이콘 버튼에는 보이는 텍스트 레이블이 없어 적용 대상이 아니라고 판단했습니다. [6.5.3 레이블과 네임](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.3.json)

### 자료 밖 근거

- 일부 브라우저가 안내 문구를 기본으로 흐리게 그려서 `::placeholder`의 색과 `opacity`를 직접 지정했습니다. [CSS Pseudo-Elements Level 4의 ::placeholder](https://www.w3.org/TR/css-pseudo-4/#placeholder-pseudo)
- 이미 있던 `role="status"`로 건수 갱신을 알립니다. [WAI-ARIA 1.2 status 역할](https://www.w3.org/TR/wai-aria-1.2/#status)

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
|---|---|---|
| 초기 상태 확장 검사(위반 / 판정 보류 / 통과 규칙 수) | 1 / 1 / 26 | 0 / 2 / 26 |
| 검색 0건 상태 확장 검사(위반 / 판정 보류 / 통과 규칙 수) | 1 / 1 / 25 | 0 / 2 / 25 |
| 위반 규칙과 측정 대비 | `color-contrast` 1개 요소(결과 건수 `#count`, 2.32:1) | 없음 |
| 판정 보류 대상 요소 | `color-contrast` 1개, `label-content-name-mismatch` 1개 | 같음 |
| 보이는 레이블 | 없음(안내 문구와 숨긴 이름) | 같음 |
| 결과 건수 표시 | 상태 영역(`p`) | 같음 |
| 키보드 조작 | Tab 순서대로 초점 이동, 초점 표시 있음 | 같음 |
| 폭 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | 0건 | 0건 |

### 브라우저에서 관찰한 결과

- off의 결과 건수는 측정 대비 2.32:1로 `color-contrast` 위반이었습니다. on에서는 위반이 없었습니다.
- 판정 보류 대상 요소는 두 화면이 같았습니다. off에서는 `color-contrast`가 위반 규칙에도 들어 있습니다.
- 두 화면 모두 보이는 레이블이 없었고, 입력란과 선택의 이름은 안내 문구와 숨긴 레이블에서 왔습니다.
- 두 화면 모두 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- ‘종이’와 토요일로 검색하면 전시 1건과 ‘총 1건’이 표시됐습니다. ‘없는전시’로 검색하면 0건과 ‘총 0건’, ‘조건에 맞는 전시가 없습니다’가 표시됐습니다. ‘초기화’를 누르면 전시 4건이 다시 보였습니다.

### 코드에서 확인한 사실

- off와 on의 `index.html`과 `script.js`는 같습니다.
- `style.css`에서 `.count`의 색이 `#595959`로 바뀌었고, `::placeholder { color: #595959; opacity: 1 }`이 추가됐습니다.
- 결과 없음 문구는 상태 영역 밖의 별도 문단입니다. 상태 영역에는 ‘총 0건’만 들어갑니다.

## 미검증 항목

- 스크린 리더 발화: 아이콘 버튼 이름(‘검색’, ‘초기화’)과 건수 변경 안내를 확인하지 않았습니다. 보고서는 같은 조건으로 다시 검색하면 건수 문구가 같아 다시 읽지 않을 수 있다고 적었습니다.
- 초기화 뒤 초점 이동은 브라우저에서 확인하지 않았습니다.
- 바뀐 결과 건수와 안내 문구 색이 화면에서 읽기 편한지는 확인하지 않았습니다.
- 판정 보류 두 건의 대상 요소는 이 문서에서 특정하지 않았습니다.
- 실제 터치 기기, Chrome 외 브라우저, 화면 확대 상태는 확인하지 않았습니다.
- 개발 중 읽지 못한 자료: 보고서는 읽지 못한 주소가 없고 15개 항목의 레코드를 읽었다고 적었습니다. 사례 레코드는 화면에 모달, 표, 움직이는 콘텐츠가 없어 읽지 않고 기본 규칙만 참고했다고 적었습니다.
