# 도서관 이용 안내 · 기본 개발 (off) 실행 결과

공통 헤더의 메뉴 10개와 검색, 회원 가입·대출·반납 안내 본문으로 이루어진 이용 안내 페이지입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-library-guide-on)에 있습니다.

확장 검사에서 위반 규칙은 없었고 판정 보류 규칙이 1개였습니다(0 / 1 / 28). 판정 보류는 시안 색 `#8a8a8a`를 쓴 메뉴 글자 9개의 명도 대비입니다(측정 3.45:1). ‘본문 바로가기’ 링크를 Enter로 실행하면 주소는 `#main`으로 바뀌었지만 초점을 가진 요소는 `body`였습니다.

## 사용 방법

1. 페이지를 열고 Tab 키를 처음 누르면 왼쪽 위에 ‘본문 바로가기’ 링크가 나타납니다. Enter를 누르면 주소가 `#main`으로 바뀝니다.
2. 헤더에는 텍스트 로고 ‘푸른숲도서관’, 검색 입력란과 돋보기 버튼, 메뉴 10개가 있습니다. 로고와 메뉴의 주소는 `#`입니다.
3. 현재 메뉴 ‘이용 안내’는 초록색 굵은 글씨로 표시됩니다.
4. 검색 양식에는 `onsubmit="return false"`가 있어 제출해도 다른 화면으로 이동하지 않게 만들어졌습니다.
5. 본문은 ‘이용 안내’ 제목 아래 ‘회원 가입’, ‘대출’, ‘반납’ 소제목과 문단으로 이루어지고, 아래에 도서관 주소가 있는 푸터가 있습니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 도서관 이용 안내’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 공통 메뉴와 검색이 있는 이용 안내 페이지입니다.
>
> 공통 헤더에 텍스트 로고 ‘푸른숲도서관’, 메뉴 10개(도서관 소개, 이용 안내, 자료 검색, 전자도서관, 프로그램, 열람실, 공지사항, 자주 묻는 질문, 오시는 길, 마이페이지), 검색이 있습니다. 메뉴 주소는 `#`입니다. 본문은 ‘이용 안내’ 제목 아래 ‘회원 가입’, ‘대출’, ‘반납’ 소제목과 소제목마다 두 문단입니다. 아래에 도서관 주소가 있는 푸터를 둡니다.
>
> 디자인 시안: 헤더 검색은 입력란(안내 문구 ‘검색어 입력’)과 돋보기 아이콘 버튼입니다. 메뉴 글자는 15px `#8a8a8a`, 현재 메뉴(이용 안내)는 초록색입니다. 시안에 그려진 요소 외에는 화면에 보이지 않게 해 주세요.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값만 읽었습니다. 자료 목록과 검사항목 레코드는 한 번도 받지 않았습니다(실행 기록에서 자료 조회 0회 확인).
- 지시: 화면 요청서만 주었습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 이 세션에서 거부된 셸 호출은 0건이었습니다. 개발 에이전트는 화면을 브라우저로 열어 확인하지 않았다고 보고했습니다.
- 수정 요청: 이 화면에는 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행: 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후): 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(2026-11-27 밤): 개발 절차를 ‘설정 확인’ 문서와 ‘절차’ 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본입니다. 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 아래 목록은 개발 에이전트가 일반 지식으로 넣은 처리를 코드에서 확인한 것입니다.

### 자료 밖 근거(HTML, WAI-ARIA)

- 검색 양식에 `role="search"`를 주었습니다. [WAI-ARIA 1.2 search 역할](https://www.w3.org/TR/wai-aria-1.2/#search)
- 검색 입력란에 화면에서 숨긴 `label`(‘검색어 입력’)을 `for="q"`로 연결했습니다. 안내 문구 ‘검색어 입력’은 `placeholder`로 두었습니다. [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element)
- 돋보기 버튼의 이름은 `aria-label="검색"`이고, SVG 아이콘은 `aria-hidden="true"`로 숨겼습니다. [WAI-ARIA 1.2 aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [WAI-ARIA 1.2 aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden)
- 메뉴를 `nav aria-label="주 메뉴"`와 목록(`ul`, `li`)으로 마크업했습니다. [HTML nav 요소](https://html.spec.whatwg.org/multipage/sections.html#the-nav-element)
- 현재 메뉴에 `aria-current="page"`를 붙이고 초록색(`#1b6b35`)과 굵은 글씨로 표시했습니다. [WAI-ARIA 1.2 aria-current](https://www.w3.org/TR/wai-aria-1.2/#aria-current)
- 문서 맨 앞에 ‘본문 바로가기’ 링크(`href="#main"`)를 두었습니다. 링크는 평소 화면 밖(`top:-100px`)에 있고 초점을 받으면 `top:8px`로 들어옵니다. 이동 대상 `<main id="main">`에는 `tabindex`가 없습니다. [HTML 하이퍼링크 href 속성](https://html.spec.whatwg.org/multipage/links.html#attr-hyperlink-href)
- 소제목 구역은 `section aria-labelledby`로 각 소제목과 연결했습니다. [WAI-ARIA 1.2 aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby)
- 푸터 주소는 `address` 요소로 표시했습니다. [HTML address 요소](https://html.spec.whatwg.org/multipage/sections.html#the-address-element)
- 링크, 버튼, 입력란의 `:focus-visible`에 `outline:3px solid #1b6b35`를 그립니다. [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo)
- `<html lang="ko">`입니다. [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang)

### 요청서와 다르게 판단한 부분

- 메뉴 글자색은 시안대로 `#8a8a8a`를 썼습니다. 개발 에이전트는 이 색이 흰 배경 대비 약 3.5:1로 일반 글자 기준 4.5:1에 못 미친다고 보고했습니다. 시안 값이라 그대로 썼고, 바꾸려면 시안 담당자의 결정이 필요하다고 적었습니다.
- ‘시안에 그려진 요소 외에는 화면에 보이지 않게’ 하라는 요청에 맞춰, 시안에 없는 검색 레이블은 화면에서 숨기고 ‘본문 바로가기’ 링크는 키보드 초점이 갈 때만 보이게 했습니다.
- 페이지 제목에는 요청서 제목을 따라 ‘도서관 이용 안내’를 썼습니다. 본문 `h1`은 ‘이용 안내’입니다.
- 검색은 제출해도 이동하지 않게 막았습니다.
- 개발 에이전트는 폭 320px에서 메뉴 10개가 여러 줄로 줄바꿈되고 검색란이 로고 아래로 내려간다고 보고했습니다.
- 문단 내용(5권·14일 대출, 7일 연장 등), 푸터 주소(‘서울특별시 푸른구 숲길로 123’), 초록색 계열 색상값은 임의로 정했다고 보고했습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다. KWCAG 검사 0.1.17은 건너뛰기 링크가 예상 Tab 순서의 첫 항목이고 연결 대상이 있으면 통과로 처리합니다(0.1.16은 판정 보류로 남겼습니다).

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 0 / 1 / 28 |
| 판정 보류 규칙과 측정 대비 | color-contrast 9개 요소(메뉴 링크, 3.45:1) |
| 첫 Tab | ‘본문 바로가기’가 초점을 받았고 화면에 보였습니다. |

### 브라우저에서 관찰한 결과

- 확장 검사의 판정 보류는 color-contrast 한 규칙이고 대상은 메뉴 링크 9개였습니다. 기록에 남은 요소 세 개의 측정 대비는 모두 3.45:1이었습니다. 검사 기록에는 axe가 위반으로 검출했으며 KWCAG 5.4.3과 표준심사 지침의 화면 확대 예외가 적용되는지 확인하라는 안내가 남았습니다.
- 건너뛰기 링크와 관련해 위반이나 판정 보류로 나온 규칙은 없었습니다.
- 첫 Tab에서 ‘본문 바로가기’가 초점을 받았고 화면에 보였습니다.
- ‘본문 바로가기’에서 Enter를 누르면 주소가 `#main`으로 바뀌었습니다. 그때 초점을 가진 요소(`document.activeElement`)는 `body`였습니다. 이어서 Tab을 한 번 누른 뒤에도 `body`였습니다.
- Tab 순서는 ‘본문 바로가기’, 로고 ‘푸른숲도서관’, 검색 입력란, 검색 버튼, 메뉴 10개였고 그다음은 `body`였습니다. 초점 표시가 없는 정지점은 없었습니다.
- 메뉴 영역의 링크는 10개이고 영역 이름은 ‘주 메뉴’였습니다. `aria-current`가 붙은 항목은 ‘이용 안내’였습니다.
- 검색 입력란의 레이블과 안내 문구는 모두 ‘검색어 입력’이었습니다. 레이블은 화면에 보이지 않았습니다.
- 확장의 수동 확인 목록에는 돋보기 SVG가 보조기술에서 숨겨져 있고 연결된 버튼의 `aria-label`이 ‘검색’이라고 기록됐습니다. 제목은 수준 1 ‘이용 안내’와 수준 2 ‘회원 가입’, ‘대출’, ‘반납’이 기록됐습니다.
- 폭 320px에서 가로 넘침은 0px이었습니다.

### 코드에서 확인한 사실

- 메뉴 링크는 흰 배경(`#fff`)에 15px `#8a8a8a` 글자입니다. 이 두 색으로 WCAG 상대 휘도 공식을 계산하면 3.45:1로 측정값과 같습니다. 현재 메뉴만 `#1b6b35` 굵은 글씨입니다.
- `<main id="main">`에 `tabindex`가 없습니다. `main`과 푸터 안에는 초점을 받는 요소가 없습니다.
- 검색 양식의 테두리는 `1px solid #999`입니다. 안내 문구 색은 `#6b6b6b`, `opacity: 1`로 지정했습니다.
- 검색 버튼은 `width: 44px; height: 40px`이고, 메뉴 링크의 안쪽 여백은 `8px 10px`입니다.
- 검색 양식은 `onsubmit="return false"`입니다. 화면에 JavaScript 파일은 없습니다.

## 미검증 항목

- 스크린 리더 발화: 검색 입력란의 이름, 현재 메뉴 표시, ‘본문 바로가기’ 실행 뒤 읽는 위치를 확인하지 않았습니다.
- ‘본문 바로가기’ 실행 뒤 Tab이 이어지는 위치는 이 기록으로 판단할 수 없습니다. 기록은 초점을 가진 요소가 `body`였다는 값뿐이고, 본문과 푸터에 초점을 받는 요소가 없기 때문입니다.
- 폭 320px에서 메뉴가 줄바꿈되고 검색란이 로고 아래로 내려가는 모양은 확인하지 않았습니다. 기록은 가로 넘침 값뿐입니다.
- 검색 양식을 제출했을 때의 동작은 브라우저에서 확인하지 않았습니다.
- 실제 터치 기기, Chrome 이외의 브라우저, 화면 확대 상태는 확인하지 않았습니다.
