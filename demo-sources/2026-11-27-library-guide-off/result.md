# 도서관 이용 안내 · 기본 개발 (off) 실행 결과

공통 헤더의 메뉴 10개와 검색, 회원 가입·대출·반납 안내 본문으로 이루어진 이용 안내 페이지입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다.

같은 요청서로 접근성 자료를 적용해 개선한 화면은 [도서관 이용 안내 · 접근성 자료 적용 (on)](/?demo=2026-11-27-library-guide-on)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열고 Tab 키를 처음 누르면 왼쪽 위에 ‘본문 바로가기’ 링크가 나타납니다. Enter를 누르면 본문으로 이동합니다.
2. 헤더에는 텍스트 로고 ‘푸른숲도서관’, 검색 입력란과 돋보기 버튼, 메뉴 10개가 있습니다. 로고와 메뉴의 주소는 `#`입니다.
3. 현재 메뉴 ‘이용 안내’는 초록색 굵은 글씨로 표시됩니다.
4. 검색 양식은 제출해도 아무 동작을 하지 않습니다.
5. 본문은 ‘이용 안내’ 제목 아래 ‘회원 가입’, ‘대출’, ‘반납’ 소제목과 문단으로 이루어지고, 아래에 도서관 주소가 있는 푸터가 있습니다.

## 요청서

‘화면 요청서: 도서관 이용 안내’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 공통 메뉴와 검색이 있는 이용 안내 페이지입니다.
>
> 공통 헤더에 텍스트 로고 ‘푸른숲도서관’, 메뉴 10개(도서관 소개, 이용 안내, 자료 검색, 전자도서관, 프로그램, 열람실, 공지사항, 자주 묻는 질문, 오시는 길, 마이페이지), 검색이 있습니다. 메뉴 주소는 `#`입니다. 본문은 ‘이용 안내’ 제목 아래 ‘회원 가입’, ‘대출’, ‘반납’ 소제목과 소제목마다 두 문단입니다. 아래에 도서관 주소가 있는 푸터를 둡니다.
>
> 디자인 시안: 헤더 검색은 입력란(안내 문구 ‘검색어 입력’)과 돋보기 아이콘 버튼입니다. 메뉴 글자는 15px `#8a8a8a`, 현재 메뉴(이용 안내)는 초록색입니다. 시안에 그려진 요소 외에는 화면에 보이지 않게 해 주세요.

## 개발 조건

- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 끄고 요청서대로 만들었습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 개발 중 확인: 개발 에이전트는 브라우저로 화면을 열지 않고 코드만 점검했다고 보고했습니다.
- 수정 요청: 화면에 기능 결함이 없어 수정 요청을 보내지 않았습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 아래 목록은 개발 에이전트가 일반 지식으로 넣은 처리를 코드에서 확인한 것입니다.

### 자료 밖 근거(HTML, WAI-ARIA)

- 검색 양식에 `role="search"`를 주었습니다. [WAI-ARIA 1.2 search 역할](https://www.w3.org/TR/wai-aria-1.2/#search)
- 검색 입력란에 화면에서 숨긴 `label`(‘검색어 입력’)을 `for="q"`로 연결했습니다. 안내 문구 ‘검색어 입력’은 `placeholder`로 두었습니다. [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element)
- 돋보기 버튼의 이름은 `aria-label="검색"`이고, SVG 아이콘은 `aria-hidden="true"`로 숨겼습니다. [WAI-ARIA 1.2 aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [WAI-ARIA 1.2 aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden)
- 메뉴를 `nav aria-label="주 메뉴"`로 감쌌습니다. [HTML nav 요소](https://html.spec.whatwg.org/multipage/sections.html#the-nav-element)
- 현재 메뉴에 `aria-current="page"`를 붙이고 초록색(`#1b7a3a`)과 굵은 글씨로 표시했습니다. [WAI-ARIA 1.2 aria-current](https://www.w3.org/TR/wai-aria-1.2/#aria-current)
- 문서 맨 앞에 ‘본문 바로가기’ 링크를 두고, 이동 대상 `main`에 `tabindex="-1"`을 주었습니다. 링크는 평소 화면 밖에 있고 초점을 받으면 보입니다. [HTML tabindex 속성](https://html.spec.whatwg.org/multipage/interaction.html#the-tabindex-attribute)
- 소제목 구역은 `section aria-labelledby`로 각 소제목과 연결했습니다. [WAI-ARIA 1.2 aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby)
- 푸터 주소는 `address` 요소로 표시했습니다. [HTML address 요소](https://html.spec.whatwg.org/multipage/sections.html#the-address-element)
- 초점을 받은 요소에 `:focus-visible` 3px 윤곽선을 표시합니다. [Selectors Level 4의 :focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo)

### 요청서와 다르게 판단한 부분

- 메뉴 글자색은 시안대로 `#8a8a8a`를 썼습니다. 개발 에이전트는 이 색이 일반 텍스트 대비 기준 4.5:1에 못 미친다고 보고했지만 바꾸지 않았습니다.
- 시안에 없는 보이는 레이블과 ‘본문 바로가기’ 링크는 평소 화면에 보이지 않게 처리했습니다.
- 폭 320px에서는 메뉴를 줄바꿈으로 배치했습니다. 가로 스크롤 메뉴나 햄버거 메뉴처럼 시안에 없는 요소는 넣지 않았습니다.
- 본문 문장과 푸터 주소(‘서울특별시 푸른구 숲길로 123’)는 가상으로 지어 넣었습니다.

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

### 확장 검사

초기 상태에서 위반 규칙은 0개, 판정 보류 규칙은 2개, 통과 규칙은 27개였습니다. 판정 보류 규칙은 `color-contrast`(9개 요소)와 `audit-skip-link`입니다. `color-contrast` 판정 보류 대상은 메뉴 글자 대비였고, 측정 대비 값은 기록되지 않았습니다.

### 브라우저에서 관찰한 결과

- 첫 Tab에서 ‘본문 바로가기’가 초점을 받았습니다.
- 폭 1280px에서 Tab 순서대로 초점이 이동했습니다. 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 폭 320px에서 페이지 가로 스크롤이 없었습니다.
- 마크업 검사 오류는 0건이었습니다.
- 초기 상태에서 콘솔 오류(pageerror)는 0건이었습니다.

### 코드에서 확인한 사실

- 메뉴 링크는 흰 배경에 15px `#8a8a8a` 글자이고, 현재 메뉴만 `#1b7a3a` 굵은 글씨입니다.
- 검색 입력란의 안내 문구 색은 지정하지 않아 브라우저 기본 색을 씁니다.
- 검색 양식은 `onsubmit="return false"`라 제출해도 동작하지 않습니다.

## 미검증 항목

- 스크린 리더 발화: 검색 입력란의 이름, 현재 메뉴 표시, 본문 바로가기 이동 뒤 읽는 위치를 확인하지 않았습니다.
- ‘본문 바로가기’를 Enter로 눌렀을 때 초점이 본문으로 옮겨지는지는 브라우저에서 확인하지 않았습니다.
- 메뉴 글자의 명도 대비 측정값은 확인하지 않았습니다.
- 실제 터치 기기, Chrome 외 브라우저, 화면 확대 상태는 확인하지 않았습니다.
