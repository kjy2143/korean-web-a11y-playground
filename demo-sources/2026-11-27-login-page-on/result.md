# 로그인 · 접근성 자료 적용 (on) 실행 결과

푸른숲도서관 회원 로그인 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-login-page-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사에서 off의 명도 대비 위반(보조 링크 2.32:1)이 사라져 두 상태 모두 위반과 판정 보류가 0건이었습니다. 입력란의 레이블은 off와 같이 화면에서 숨겨져 있고 placeholder만 보입니다. 개발 에이전트는 이 시안을 요청서대로 두었습니다. Tab 순서, 320px 화면, 마크업 검사 결과는 off와 같았습니다.

## 사용 방법

- 아이디 `reader01`, 비밀번호 `green1234`를 입력하고 ‘로그인’을 누르면 환영 화면(`welcome.html`)으로 이동합니다. 예시 계정은 로그인 화면 아래에 적혀 있습니다.
- 환영 화면에서 ‘로그아웃’을 누르면 로그인 화면으로 돌아갑니다.
- 빈 칸으로 제출하거나 틀린 비밀번호를 넣으면 입력란 테두리가 빨간색으로 바뀌고 아래에 오류 문구가 나타납니다.
- 비밀번호 칸 오른쪽의 눈 모양 버튼으로 비밀번호를 보이거나 숨깁니다.
- off 화면과 나란히 열어 보조 링크의 색과 밑줄, 계정이 틀렸을 때의 오류 문구를 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 로그인’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 예시 계정으로 로그인하고 로그아웃합니다.
>
> 푸른숲도서관 회원 로그인 화면을 만들어 주세요. 예시 계정은 아이디 `reader01`, 비밀번호 `green1234`이고 화면 아래에 예시 계정을 안내합니다. 아이디나 비밀번호가 비었거나 틀리면 오류를 보여 주고, 맞으면 환영 화면(`welcome.html`)으로 이동합니다. 환영 화면의 ‘로그아웃’을 누르면 로그인 화면으로 돌아갑니다.
>
> 디자인 시안: 입력란 위에 별도 제목을 두지 않고 입력란 안의 안내 문구(‘아이디’, ‘비밀번호’)로 표시합니다. 비밀번호 칸 오른쪽 안쪽에 눈 모양 아이콘 버튼을 두어 비밀번호를 보이거나 숨깁니다. 로그인 버튼 아래 ‘아이디 찾기 · 비밀번호 찾기 · 회원가입’ 링크는 13px, `#aaaaaa`로 작게 둡니다. 이동할 페이지는 아직 없으니 주소는 `#`으로 둡니다. 오류가 나면 해당 입력란의 테두리를 빨간색으로 바꾸고 아래에 짧은 빨간 문구를 표시합니다.

요청서 시안과 다르게 구현한 부분은 아래와 같습니다. 근거 구분은 on 개발 에이전트의 보고를 따랐습니다.

| 요청서 시안 | 조정한 내용 | 이유 |
| --- | --- | --- |
| 보조 링크 13px, `#aaaaaa` | 색을 `#595959`로 바꾸고 밑줄을 넣었습니다. 13px은 유지했습니다. | 보고서는 `#aaaaaa`가 흰 배경에서 약 2.3:1이라 5.4.3의 4.5:1(KWCAG 요구사항)에 못 미치고, `#595959`는 약 7:1이라고 적었습니다. 밑줄은 5.4.1(KWCAG 요구사항)의 적용 내용으로 적었습니다. |
| 한 줄로 놓인 링크 세 개와 구분점 `·` | 링크의 가로 안쪽 여백을 6px, 최소 높이를 32px로 넓혔습니다. 한 줄 배치는 유지했습니다. 구분점은 글자 대신 CSS로 만들었습니다. | 조작 영역을 확보하려는 조정입니다(6.1.3, 보고서의 근거 구분은 ‘요구사항, 권장 사항’). |
| 오류 시 짧은 빨간 문구 | 계정이 틀렸을 때의 문구를 ‘아이디 또는 비밀번호가 올바르지 않습니다. 예시 계정을 확인해 다시 입력해 주세요.’로 바꿨습니다. | 문구를 구체적으로 쓰려는 조정입니다(7.3.1, NIA 권장 사항). 보고서는 요청서의 ‘짧은 문구’보다 길어졌다고 적었습니다. |

요청서대로 둔 부분은 다음과 같습니다.

- 입력란 위에 보이는 제목을 두지 않고 placeholder로 표시합니다. 보고서는 숨김 `label`을 `for`와 `id`로 연결해 두었으므로 7.3.2를 충족한다고 판단했습니다.
- 비밀번호 칸의 눈 모양 아이콘 버튼, 빨간 테두리와 빨간 오류 문구를 유지했습니다.

시안과 충돌하지 않는 접근성 개선은 네 가지입니다.

- 눈 모양 버튼의 이름을 ‘비밀번호 표시’로 고정하고 상태는 `aria-pressed`로만 알립니다. off는 이름과 `aria-pressed`를 함께 바꿨습니다.
- 계정이 틀렸을 때 초점이 가는 아이디 칸의 `aria-describedby`가 비밀번호 칸 아래의 오류 문구를 가리키게 했습니다. off는 비어 있는 요소를 가리켰습니다.
- 오류 문구의 `role="alert"`를 없앴습니다. 보고서는 숨겼던 요소를 표시할 때의 안내가 불안정하고, 초점 이동 때 `aria-describedby`로 읽히는 것과 겹친다고 적었습니다.
- 보조 링크를 `nav`와 `ul` 목록으로 바꿨습니다.

접근성과 무관한 기능 결함 수정도 하나 있습니다. off는 계정 불일치 오류가 난 뒤 비밀번호만 고치면 비밀번호 칸의 오류만 지워지고 아이디 칸의 빨간 테두리가 남았습니다. on은 불일치 오류를 두 칸에서 함께 지웁니다.

개발 에이전트는 구현하지 않은 제안 두 가지를 남겼습니다. `welcome.html`에 로그인 여부 확인을 넣는 것과, 입력란에 보이는 레이블을 두는 것입니다. 앞의 것은 요청서에 없는 기능이라, 뒤의 것은 시안과 충돌해 넣지 않았다고 보고했습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행). 개발 세션은 대화 턴 41회, 127초였습니다.
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치게 했습니다.
- 자료 조회: 설정 확인, 절차 문서, 자료 목록, 레코드 순서로 읽었습니다. 자료 조회 명령 27회는 모두 주소 하나에 명령 하나인 같은 형태였고, 실패한 조회는 없었습니다. KWCAG 레코드 18개와 NIA 사례 레코드 8개를 읽었습니다. 화면 종류와 관계없이 고르는 12개 항목(5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1)의 레코드를 모두 받았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 명도 대비 계산 스크립트를 만들고 실행하려던 명령 2건(`cat`으로 파일 쓰기, `python3`)이 거부됐습니다. 그래서 개발 에이전트는 링크 색의 대비를 공식으로 직접 계산했고, 다른 색은 암산으로 추정했다고 보고했습니다.
- 수정 요청: 이 화면에는 결함 보고를 보내지 않았습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

### 자료 밖 근거

- 오류 상태: 오류가 나면 `aria-invalid`와 `aria-describedby`를 씁니다. [aria-invalid](https://www.w3.org/TR/wai-aria-1.2/#aria-invalid) · [aria-describedby](https://www.w3.org/TR/wai-aria-1.2/#aria-describedby)
- 눈 모양 버튼: `aria-pressed` 토글 버튼 패턴입니다. [aria-pressed](https://www.w3.org/TR/wai-aria-1.2/#aria-pressed)
- 숨김 레이블: 화면에서만 숨기는 `.sr-only` CSS 기법입니다. 이 기법을 정한 단일 표준은 없습니다.
- 구분점: `content: "·" / ""`는 CSS 생성 콘텐츠의 대체 텍스트 구문입니다. [CSS Generated Content 대체 텍스트](https://www.w3.org/TR/css-content-3/#alt)

### 코드에서 확인한 사실

- `style.css`: 보조 링크는 `#595959`, 밑줄, `min-height:32px`, 가로 안쪽 여백 6px입니다. `#aaaaaa` 값은 남아 있지 않습니다. 글자 크기 13px과 placeholder 색 `#6b6b6b`는 off와 같습니다.
- 구분점은 `.links li+li::before`의 `content:"·" / ""` 한 선언으로 만듭니다. 대체 텍스트 구문이 없는 `content:"·"` 선언은 따로 두지 않았습니다.
- `index.html`: 보조 링크가 `nav aria-label="계정 찾기와 가입"` 안의 `ul`과 `li` 세 개로 바뀌었고, 비밀번호 칸 오류 문구의 `role="alert"`가 없어졌습니다. `id`는 6개이고 중복이 없습니다.
- `script.js`: 눈 모양 버튼을 누르면 `aria-pressed`만 바꿉니다. 계정이 틀리면 아이디 칸의 `aria-describedby`를 `pw-err`로 바꾸고, 오류를 지울 때 `uid-err`로 되돌립니다. 불일치 오류 상태에서 어느 칸이든 입력하면 두 칸의 오류를 함께 지웁니다.
- `welcome.html`은 off와 같습니다. 로그인 여부를 확인하는 코드는 없습니다.

## 미검증 항목

- 스크린 리더 발화: 오류 뒤 아이디 칸에서 레이블, 오류 상태, 오류 문구를 이어서 읽는지 확인하지 않았습니다. 눈 모양 버튼을 ‘비밀번호 표시, 토글 버튼, 눌리지 않음’으로 읽고 눌렀을 때 상태만 바뀌는지도 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다. `content:"·" / ""` 구문을 지원하지 않는 브라우저에서 구분점이 보이는지도 확인하지 않았습니다.
- 폭 320px에서 보조 링크가 줄바꿈될 때 구분점과 정렬이 어떻게 보이는지는 기록하지 않았습니다. 가로 스크롤이 없다는 것만 확인했습니다.
- 초점 윤곽선이 눈 모양 버튼과 링크에서 잘리지 않는지는 기록하지 않았습니다. 초점 표시가 있다는 것만 확인했습니다.
- 눈 모양 버튼을 눌렀을 때 비밀번호가 보이는지와 `aria-pressed`가 바뀌는지는 브라우저에서 기록하지 않았습니다.
- 계정 불일치 오류 뒤 입력을 고치면 두 칸의 오류가 함께 지워지는 동작은 코드로만 확인했습니다.
- 링크 색 `#595959`가 시안과 어울리는지는 디자인 판단이라 확인하지 않았습니다.
- 브라우저 자동 완성과 비밀번호 관리자 연동, 화면 확대, 고대비 모드는 확인하지 않았습니다.
