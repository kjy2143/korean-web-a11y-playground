# 관심 프로그램 · 기본 개발 (off) 실행 결과

관심 프로그램 카드 세 개의 순서를 끌어서 바꾸는 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다.

같은 요청서로 접근성 자료를 적용해 개선한 화면은 [관심 프로그램 · 접근성 자료 적용 (on)](/?demo=2026-11-27-program-reordering-on)에서 볼 수 있습니다.

## 사용 방법

1. 카드 왼쪽의 점 여섯 개 손잡이를 끌어 다른 카드 위에 놓으면 순서가 바뀝니다. 원래 위치보다 아래 카드에 놓으면 그 카드 뒤로, 위 카드에 놓으면 그 카드 앞으로 들어갑니다.
2. 키보드에서는 손잡이에 초점을 두고 위쪽·아래쪽 화살표 키를 누르면 카드가 한 칸씩 이동합니다.
3. 이동하면 화면에 보이지 않는 상태 영역에 ‘그림책 읽기, 3개 중 2번째로 이동했습니다.’ 같은 문구가 들어갑니다.
4. 순서는 저장하지 않으므로 새로고침하면 처음 순서로 돌아갑니다.

## 요청서

‘화면 요청서: 관심 프로그램’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 관심 프로그램 카드의 순서를 바꿉니다.
>
> 관심 프로그램 카드 세 개(‘그림책 읽기’ 토 10:00 어린이실, ‘동네 사진 산책’ 일 14:00 1층 로비, ‘겨울 글쓰기 모임’ 수 19:00 세미나실)의 순서를 바꾸는 화면입니다. 새로고침하면 처음 순서로 돌아가도 됩니다.
>
> 디자인 시안: 카드 왼쪽의 점 여섯 개 손잡이 아이콘을 끌어 다른 카드 위에 놓으면 순서가 바뀝니다. 카드에는 다른 버튼을 두지 않습니다. 카드의 요일·장소 정보는 `#aaaaaa`입니다.

## 개발 조건

- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 끄고 요청서대로 만들었습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 개발 중 확인: 개발 에이전트는 스크립트 문법 검사만 통과시켰고, 끌어 놓기·키보드 이동·폭 320px 표시는 실행해 보지 않았다고 보고했습니다.
- 수정 요청: 화면에 기능 결함이 없어 수정 요청을 보내지 않았습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 아래 목록은 개발 에이전트가 일반 지식으로 넣은 처리를 코드에서 확인한 것입니다.

### 자료 밖 근거(HTML, WAI-ARIA)

- 손잡이를 `button`으로 만들어 초점을 받게 했습니다. 이름은 `aria-label`의 ‘그림책 읽기 순서 이동’ 형식이고, 점 아이콘 SVG는 `aria-hidden="true"`로 숨겼습니다. [HTML button 요소](https://html.spec.whatwg.org/multipage/form-elements.html#the-button-element), [WAI-ARIA 1.2 aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [WAI-ARIA 1.2 aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden)
- 손잡이에서 위쪽·아래쪽 화살표 키를 누르면 카드가 한 칸 이동하고, 이동 뒤 초점을 같은 손잡이에 되돌립니다.
- 이동 결과를 화면에서 숨긴 `role="status"`(`aria-live="polite"`) 영역에 적습니다. [WAI-ARIA 1.2 status 역할](https://www.w3.org/TR/wai-aria-1.2/#status)
- 카드 목록 `ol`에 `aria-describedby`로 도움말 문단을 연결했습니다. 도움말은 끌기와 화살표 키 사용법을 설명합니다. [WAI-ARIA 1.2 aria-describedby](https://www.w3.org/TR/wai-aria-1.2/#aria-describedby)
- 끌기는 포인터 이벤트로 구현했습니다. 손잡이에 포인터를 잡아 두고(`setPointerCapture`), `pointercancel`이 오면 이동하지 않습니다. 손잡이에 `touch-action: none`을 주었습니다. [Pointer Events Level 3](https://www.w3.org/TR/pointerevents3/)
- 손잡이에 `:focus-visible` 노란 3px 윤곽선을 표시합니다. [Selectors Level 4의 :focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo)

### 요청서와 다르게 판단한 부분

- 요일·장소 글자는 시안대로 `#aaaaaa`를 썼습니다. 흰 배경에서는 읽기 어렵다고 보고, 요청서에 없는 카드 배경을 어두운 색(`#1e2b26`)으로 정했습니다.
- 끌어 놓기만으로는 키보드 사용자가 순서를 바꿀 수 없다고 보고 손잡이 버튼에 화살표 키 이동을 넣었습니다. 시안대로 카드에 다른 버튼은 늘리지 않았습니다.
- 요청서에 없는 도움말 문단을 제목 아래에 넣었습니다.

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

### 확장 검사

| 상태 | 위반 규칙 수 | 판정 보류 규칙 수 | 통과 규칙 수 |
|---|---|---|---|
| 초기 | 0 | 0 | 22 |
| 끌어서 이동 | 0 | 0 | 22 |

### 브라우저에서 관찰한 결과

- 마우스로 첫 카드의 손잡이를 마지막 카드로 끌자 순서가 바뀌었습니다.
- 손잡이를 한 번 누르는 것만으로는 순서가 바뀌지 않았습니다. 순서를 바꾸려면 끌기가 필요했습니다.
- 손잡이 버튼에 초점을 두고 아래쪽 화살표 키를 누르면 순서가 바뀌었고 초점은 손잡이에 남았습니다. Enter만 누르면 순서가 바뀌지 않았습니다.
- 폭 1280px에서 Tab 순서대로 초점이 이동했습니다. 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 폭 320px에서 페이지 가로 스크롤이 없었습니다.
- 마크업 검사 오류는 0건이었습니다.
- 초기 상태에서 콘솔 오류(pageerror)는 0건이었습니다.

### 코드에서 확인한 사실

- 키보드 이동은 손잡이의 위쪽·아래쪽 화살표 키 입력만 처리합니다. Enter에는 별도 동작이 없습니다.
- 손잡이 클릭에는 처리기가 없어, 끌기 없이 포인터 한 번으로 순서를 바꾸는 수단은 없습니다.
- 카드 이동은 `li` 요소를 목록 안에서 다시 끼우는 방식이라 화면 순서와 문서 순서가 같습니다.

## 미검증 항목

- 스크린 리더 발화: 손잡이 이름, 도움말, 이동 안내 문구를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기에서 끌기와 페이지 스크롤이 겹치지 않는지 확인하지 않았습니다.
- 카드 밖에서 놓거나 포인터 입력이 취소될 때 순서가 그대로인지 브라우저에서 확인하지 않았습니다.
- 요일·장소 글자의 측정 대비는 기록하지 않았습니다. 확장 검사에서 `color-contrast` 위반은 없었습니다.
- Chrome 외 브라우저와 화면 확대 상태는 확인하지 않았습니다.
