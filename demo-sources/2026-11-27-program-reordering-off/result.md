# 관심 프로그램 · 기본 개발 (off) 실행 결과

관심 프로그램 카드 세 개의 순서를 끌어서 바꾸는 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 화면 요청서만으로 만들었습니다. 확장 검사에서 위반 규칙과 판정 보류 규칙은 없었습니다. 순서는 끌기와 손잡이의 화살표 키로 바꿀 수 있고, 끌기 없이 포인터 한 번으로 바꾸는 수단은 없습니다.

같은 요청서로 접근성 자료를 적용해 개선한 화면은 [관심 프로그램 · 접근성 자료 적용 (on)](/?demo=2026-11-27-program-reordering-on)에서 볼 수 있습니다.

## 사용 방법

1. 카드 왼쪽의 점 여섯 개 손잡이를 끌어 다른 카드 위에 놓으면 순서가 바뀝니다. 원래 위치보다 아래 카드에 놓으면 그 카드 뒤로, 위 카드에 놓으면 그 카드 앞으로 들어갑니다.
2. 키보드에서는 손잡이에 초점을 두고 위쪽·아래쪽 화살표 키를 누르면 카드가 한 칸씩 이동합니다.
3. 이동하면 화면에서 숨긴 상태 영역에 ‘그림책 읽기, 3개 중 3번째로 이동했습니다.’ 같은 문구가 들어갑니다.
4. 순서는 저장하지 않으므로 새로고침하면 처음 순서로 돌아갑니다.

## 요청서

‘화면 요청서: 관심 프로그램’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 관심 프로그램 카드의 순서를 바꿉니다.
>
> 관심 프로그램 카드 세 개(‘그림책 읽기’ 토 10:00 어린이실, ‘동네 사진 산책’ 일 14:00 1층 로비, ‘겨울 글쓰기 모임’ 수 19:00 세미나실)의 순서를 바꾸는 화면입니다. 새로고침하면 처음 순서로 돌아가도 됩니다.
>
> 디자인 시안: 카드 왼쪽의 점 여섯 개 손잡이 아이콘을 끌어 다른 카드 위에 놓으면 순서가 바뀝니다. 카드에는 다른 버튼을 두지 않습니다. 카드의 요일·장소 정보는 `#aaaaaa`입니다.

## 개발 조건

- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 끄고 화면 요청서만 주었습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값만 읽었습니다. 자료 목록과 검사항목 레코드는 한 번도 받지 않았고, 실행 기록에서 자료 조회가 0회임을 확인했습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 이 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다. 개발 에이전트는 코드와 명령으로만 확인했습니다.
- 셸 명령: 허용한 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 1건이고, `cd` 뒤에 다른 명령을 이은 복합 명령이었습니다. 거부된 뒤에도 파일 세 개(`index.html`, `style.css`, `script.js`)는 모두 만들어졌습니다.
- 개발 중 확인: 개발 에이전트는 브라우저에서 열어 동작을 확인하지는 않았다고 보고했습니다.
- 수정 요청: 브라우저 확인에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 첫 실행에서는 on 화면을 만들지 않았습니다. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. 이때 off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 아래 목록은 개발 에이전트가 일반 지식으로 넣은 처리를 코드에서 확인한 것입니다.

### 자료 밖 근거(HTML, WAI-ARIA)

- 손잡이를 `button`으로 만들어 초점을 받게 했습니다. 이름은 스크립트가 `aria-label`에 ‘그림책 읽기 순서 바꾸기’ 형식으로 넣습니다. 점 아이콘 SVG는 `aria-hidden="true"`로 숨겼습니다. [HTML button 요소](https://html.spec.whatwg.org/multipage/form-elements.html#the-button-element), [WAI-ARIA 1.2 aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [WAI-ARIA 1.2 aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden)
- 손잡이에서 위쪽·아래쪽 화살표 키를 누르면 카드가 한 칸 이동하고, 이동 뒤 초점을 같은 손잡이에 되돌립니다.
- 이동 결과를 화면에서 숨긴 `role="status"` 문단에 적습니다. [WAI-ARIA 1.2 status 역할](https://www.w3.org/TR/wai-aria-1.2/#status)
- 손잡이마다 `aria-describedby`로 도움말 문단을 연결했습니다. 도움말은 끌기와 화살표 키 사용법을 설명합니다. [WAI-ARIA 1.2 aria-describedby](https://www.w3.org/TR/wai-aria-1.2/#aria-describedby)
- 끌기는 포인터 이벤트로 구현했습니다. 손잡이에 포인터를 잡아 두고(`setPointerCapture`), `pointercancel`이 오면 이동하지 않습니다. 손잡이에 `touch-action: none`을 주었습니다. [Pointer Events Level 3](https://www.w3.org/TR/pointerevents3/)
- 손잡이에 `:focus-visible` 노란(`#ffd54a`) 3px 윤곽선을 표시합니다. [Selectors Level 4의 :focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo)
- 손잡이 크기는 44×44px입니다.
- 카드는 순서가 있는 목록(`ol`, `li`)이고 카드 제목은 `h2`입니다.
- 동작 줄이기 설정에서는 이동한 카드의 강조 애니메이션을 끕니다. [Media Queries Level 5의 prefers-reduced-motion](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion)

### 요청서와 다르게 판단한 부분

- 요일·장소 글자는 시안대로 `#aaaaaa`를 썼습니다. 개발 에이전트는 흰 배경에서는 대비가 약 2.3:1이라 읽기 어렵다고 보고, 요청서에 없는 카드 배경을 어두운 색(`#222b27`)으로 정했습니다. 보고서는 이 조합의 대비를 약 7:1로 적었습니다. 같은 조합을 on 개발 에이전트는 직접 계산해 약 6.3:1로 적었습니다.
- 끌기만으로는 키보드나 보조기기로 순서를 바꿀 수 없다고 보고 손잡이 자체를 `button`으로 만들어 화살표 키 이동을 넣었습니다. 시안대로 카드에 다른 버튼은 두지 않았습니다.
- 요청서에 없는 도움말 문단을 제목 아래에 넣었습니다.
- 새로고침하면 처음 순서로 돌아가도 된다는 요청에 따라 저장 기능은 넣지 않았습니다.

## 검증 결과

확장 검사는 Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에서 했습니다. KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 요소 수가 아니라 규칙 종류 수입니다.

### 확장 검사

| 상태 | 위반 규칙 수 | 판정 보류 규칙 수 | 통과 규칙 수 |
|---|---|---|---|
| 초기 | 0 | 0 | 22 |
| 끌어서 이동 | 0 | 0 | 22 |

### 브라우저에서 관찰한 결과

- 마우스로 첫 카드의 손잡이를 마지막 카드의 아래쪽으로 끌어 놓자 순서가 ‘동네 사진 산책, 겨울 글쓰기 모임, 그림책 읽기’로 바뀌었습니다. 상태 영역에는 ‘그림책 읽기, 3개 중 3번째로 이동했습니다.’가 들어갔습니다.
- 첫 카드의 손잡이를 한 번 누르는 것만으로는 순서가 바뀌지 않았습니다.
- 첫 카드의 손잡이에 초점을 두고 아래쪽 화살표 키를 누르자 순서가 ‘동네 사진 산책, 그림책 읽기, 겨울 글쓰기 모임’으로 바뀌었습니다. 초점은 같은 손잡이에 남았습니다.
- Tab 정지점은 손잡이 세 개였습니다. Tab 순서대로 초점이 이동했고, 정지점마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 손잡이의 이름은 ‘그림책 읽기 순서 바꾸기’, ‘동네 사진 산책 순서 바꾸기’, ‘겨울 글쓰기 모임 순서 바꾸기’였습니다.
- 폭 320px에서 페이지 가로 스크롤이 없었습니다.
- 마크업 검사 오류는 0건이었습니다.
- 초기 상태의 콘솔 오류와 조작 중 페이지 오류는 0건이었습니다.

### 코드에서 확인한 사실

- 키보드 이동은 손잡이의 위쪽·아래쪽 화살표 키 입력만 처리합니다. Enter와 Space에는 별도 동작이 없습니다.
- 손잡이 클릭에는 처리기가 없습니다. 끌기 없이 포인터 한 번으로 순서를 바꾸는 수단은 없습니다.
- 카드 이동은 `li` 요소를 `insertBefore`로 목록 안에서 다시 끼우는 방식입니다. 화면 순서와 문서 순서가 같습니다.
- 끌기 중 놓을 대상 카드는 노란 3px 그림자(`box-shadow`)로만 표시합니다. 끌고 있는 카드는 반투명과 흰 점선 윤곽선으로 표시합니다.
- 상태 영역은 `role="status"`만 있는 문단입니다. 크기 1px과 `clip-path`로 화면에서 숨겼습니다.
- 요일·장소 글자는 `#222b27` 배경 위 `#aaaaaa`입니다.

## 미검증 항목

- 스크린 리더 발화: 손잡이 이름, 연결한 도움말, 이동 안내 문구를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기에서 끌기와 페이지 스크롤이 겹치지 않는지 확인하지 않았습니다.
- 카드 밖에서 놓거나 포인터 입력이 취소될 때 순서가 그대로인지 브라우저에서 확인하지 않았습니다.
- 위쪽 화살표 키 이동과, 맨 앞·맨 뒤 카드에서 화살표 키를 눌렀을 때의 동작은 브라우저에서 확인하지 않았습니다.
- 요일·장소 글자의 측정 대비는 기록에 없습니다. 확장 검사는 위반 요소의 대비만 남기고, 이 화면에는 `color-contrast` 위반이 없었습니다.
- Chrome 외 브라우저와 화면 확대 상태는 확인하지 않았습니다.
