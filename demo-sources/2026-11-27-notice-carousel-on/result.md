# 공지 배너 · 접근성 자료 적용 (on) 실행 결과

도서관 공지 세 건이 6초마다 바뀌는 배너 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-notice-carousel-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사 결과는 off와 같았습니다. 두 화면 모두 위반과 판정 보류가 없었고 통과 규칙은 24개였습니다. on 개발 에이전트는 off에 정지 버튼과 대체 안내가 이미 있어 대부분의 요구사항을 충족한다고 보고했습니다. 바꾼 것은 제목 순서, 공지를 감싼 요소, 본문의 `tabindex`, 점 사이 간격, 마우스 올림 처리입니다. off에 있던 동작 줄이기 설정 대응(설정이 켜져 있으면 정지 상태로 시작)은 on에서 없어졌습니다. 브라우저에서 확인한 자동 전환, 정지 버튼, 마우스 올림, Tab 순서는 off와 같았습니다. 다른 점은 제목의 문서 순서와, 동작 줄이기 설정을 켠 상태의 시작 동작입니다.

## 사용 방법

- 페이지를 열면 머리글의 ‘푸른숲도서관 소식’ 제목 아래에서 배너가 첫 공지를 보여 줍니다. 공지는 6초마다 바뀌고, 세 번째 공지 다음에는 첫 공지로 돌아갑니다.
- 배너 좌우의 화살표 버튼과 배너 아래의 점 세 개로 공지를 고릅니다. 현재 공지의 점은 더 크고 속이 채워져 있습니다.
- 점 왼쪽의 정지 버튼을 누르면 자동 전환이 멈추고, 다시 누르면 시작합니다.
- 배너나 그 아래 조작부에 마우스를 올리거나 키보드 초점을 두면 그동안 자동 전환이 멈춥니다.
- off와 달리 운영체제의 동작 줄이기 설정이 켜져 있어도 자동 전환 상태로 시작합니다.
- off 화면과 나란히 열어 ‘푸른숲도서관 소식’ 제목의 위치를 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 공지 배너’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 도서관 소식이 6초마다 바뀌는 배너입니다.
>
> 공지 세 개(‘겨울 독서 교실 모집’, ‘12월 휴관일 안내’, ‘전자책 신규 도서 입고’)를 배너로 보여 줍니다. 공지마다 제목, 한 줄 설명, ‘자세히’ 링크(주소 `#`)가 있습니다. 6초마다 다음 공지로 자동 전환하고, 마지막 다음에는 처음으로 돌아갑니다. 배너 아래에 짧은 페이지 본문을 둡니다.
>
> 디자인 시안: 배너 아래 가운데에 점 세 개를 두고 현재 공지의 점을 진하게 표시합니다. 점을 누르면 그 공지로 이동합니다. 배너 좌우 끝에 화살표 아이콘 버튼을 둡니다. 배너 배경은 공지마다 다른 파스텔색(`#bfe3d0`, `#f6d6c8`, `#cfd8f5`)이고 글씨는 흰색입니다.

요청서 시안과 다르게 구현한 부분은 아래와 같습니다. 세 가지 모두 off에 이미 있었고 on에서 유지했습니다. 근거 구분은 on 개발 에이전트의 보고를 따랐습니다.

| 요청서 시안 | 조정한 내용 | 이유 |
| --- | --- | --- |
| 파스텔 배경에 흰 글씨 | 배경은 시안의 파스텔 세 색을 그대로 두었습니다. 흰 글씨는 어두운 반투명 글상자(`rgba(20,30,25,.72)`) 위에 두었습니다. | 개발 에이전트는 시안 조합의 명도 대비를 계산하지 않았지만 4.5:1에 크게 못 미칠 것으로 보았습니다(5.4.3, KWCAG 요구사항). |
| 정지 수단 없음 | 정지·시작 버튼을 두었습니다. | 자동 전환에는 정지 수단이 있어야 합니다(6.2.2, KWCAG 요구사항). |
| 현재 공지의 점을 진하게 표시 | 색에 더해 크기와 채움으로도 구분합니다. | 색만으로 구분하지 않습니다(5.4.1, KWCAG 요구사항). |

화살표 아이콘 버튼과 ‘자세히’ 링크(주소 `#`)는 시안대로입니다.

요청서와 관계없이 고친 부분은 아래와 같습니다. 구분은 on 개발 에이전트의 보고를 따랐습니다.

| 구분 | 내용 |
| --- | --- |
| 접근성 개선 | `role="group"`을 단 `article`을 `div`로 바꿨습니다. 개발 에이전트는 `article`이 `group` 역할을 허용하지 않아 HTML 표준에 어긋났다고 보고했고, 이 규칙은 자료에 없어 자료 밖 근거로 적었습니다. |
| 접근성 개선 | `h1`을 배너 앞의 머리글로 옮겼습니다. off는 배너 안의 `h2`가 본문의 `h1`보다 앞에 나왔습니다. 본문에는 `h2` ‘도서관 이용 안내’를 두었습니다. |
| 접근성 개선 | `main`에 `tabindex="-1"`을 달고 `main:focus{outline:none}`을 더했습니다. 건너뛰기 링크를 실행하면 초점도 본문으로 옮기려는 처리입니다. |
| 접근성 개선 | 점 버튼 사이에 2px 간격을 두었습니다. 이웃한 조작 요소 사이에 1px 이상 간격을 두라는 권장 사항에 따랐습니다. |
| 접근성과 무관한 기능 수정 | 마우스 올림을 마우스 포인터(`pointerType === 'mouse'`)일 때만 멈춤으로 처리합니다. 개발 에이전트는 off가 터치 화면에서 `mouseenter`만 발생하고 `mouseleave`가 오지 않아 자동 전환이 멈춘 채 남는다고 보고했습니다. |
| off에 있던 처리를 없앰 | 동작 줄이기 설정(`prefers-reduced-motion: reduce`)이면 정지 상태로 시작하던 처리를 없앴습니다. on은 이 설정과 관계없이 자동 전환 상태로 시작합니다. 개발 에이전트는 이 변경을 접근성과 무관한 기능 결함 수정으로 분류했고, 요청서의 ‘6초마다 자동 전환’과 달랐고 이 화면에는 애니메이션이 없다는 이유를 적었습니다. off 문서는 같은 처리를 자료 밖 근거로 넣은 처리로 적었습니다. |

개발 에이전트는 요청에 없어 구현하지 않은 제안으로 ←, → 키로 이전·다음 공지로 이동하는 기능을 적었습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치게 했습니다.
- 자료 조회: 설정 확인, 절차 문서, 자료 목록, 레코드 순서로 읽었습니다. 자료 조회 명령 25회는 모두 주소 하나에 명령 하나인 같은 형태였고 실패는 없었습니다. KWCAG 레코드 16개와 NIA 사례 레코드 8개를 읽었습니다. 화면 종류와 관계없이 고르는 12개 항목(5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1)의 레코드는 모두 받았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다.
- 셸 명령: 허용한 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 2건으로, 모두 `python3` 명령이었습니다. 하나는 `index.html`을 고치는 스크립트였고, 다른 하나는 명도 대비를 계산하는 스크립트였습니다. 개발 에이전트는 세 배경의 대비를 스크립트로 재지 못해 가장 밝은 배경 하나만 손으로 계산했다고 보고했습니다.
- 수정 요청: 이 화면에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 첫 실행에서는 on 화면을 만들지 않았습니다. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. 이때 off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 개발 에이전트 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

### 자료 밖 근거

- 캐러셀 표시: `aria-roledescription="carousel"`, 공지의 `role="group"`, 현재 점의 `aria-current`는 WAI-ARIA 표준 지식에 근거합니다. off에 이미 있었습니다. [aria-roledescription](https://www.w3.org/TR/wai-aria-1.2/#aria-roledescription) · [group 역할](https://www.w3.org/TR/wai-aria-1.2/#group) · [aria-current](https://www.w3.org/TR/wai-aria-1.2/#aria-current)
- 전환 안내: 자동 전환 중에는 `aria-live="off"`, 멈추면 `polite`로 바꾸는 방식도 같은 근거이고 off에 이미 있었습니다. [aria-live](https://www.w3.org/TR/wai-aria-1.2/#aria-live)
- 공지를 감싼 요소: `article`에는 `group` 역할을 줄 수 없다는 규칙에 따라 `div`로 바꿨습니다. [ARIA in HTML의 article 요소](https://www.w3.org/TR/html-aria/#el-article)
- 마우스 포인터 구분: 기능 결함 수정에 `pointerType`을 썼습니다. [pointerType](https://www.w3.org/TR/pointerevents3/#dom-pointerevent-pointertype)

### 브라우저에서 관찰한 결과

- 확장 검사의 규칙 수는 두 화면이 같았습니다. `article`을 `div`로 바꾼 것과 제목 순서를 고친 것은 확장 검사와 마크업 검사의 수치에 나타나지 않았습니다.
- 제목의 문서 순서는 off가 ‘겨울 독서 교실 모집’, ‘12월 휴관일 안내’, ‘전자책 신규 도서 입고’(`h2`), ‘푸른숲도서관 소식’(`h1`)이었습니다. on은 ‘푸른숲도서관 소식’(`h1`), 공지 제목 세 개(`h2`), ‘도서관 이용 안내’(`h2`)였습니다.
- 두 화면 모두 처음에는 첫 공지가 보였고 공지 영역의 `aria-live`는 `off`였습니다. 6.6초 뒤에는 두 번째 공지가 보였습니다.
- 두 화면 모두 세 번째 점을 클릭하면 세 번째 공지로 바뀌었고 그때 `aria-live`는 `polite`였습니다. 이전 화살표를 클릭하면 두 번째 공지로 돌아갔습니다.
- 두 화면 모두 정지 버튼을 누른 뒤 6.6초 동안 공지가 그대로였습니다. 버튼 이름은 ‘자동 전환 시작’으로 바뀌었고 `aria-live`는 `polite`였습니다. 이때는 초점이 정지 버튼에 남아 있었습니다. 코드에서는 조작부에 초점이 있으면 정지 여부와 관계없이 전환이 멈추므로, 따로 한 번 더 확인했습니다. 두 화면 모두 정지 버튼을 클릭한 뒤 초점을 해제하고 마우스를 배너와 조작부 밖에 둔 상태에서도 6.6초 동안 공지가 바뀌지 않았습니다.
- 동작 줄이기 설정(`prefers-reduced-motion: reduce`)을 켠 브라우저로 열면 off는 버튼 이름이 처음부터 ‘자동 전환 시작’이었고 6.6초 동안 첫 공지가 그대로였습니다. on은 버튼 이름이 ‘자동 전환 정지’였고 6.6초 뒤 두 번째 공지로 바뀌었습니다.
- 두 화면 모두 버튼에서 Enter를 눌러 다시 시작한 뒤 초점을 해제하고 마우스를 배너와 조작부 밖에 두자 7초 안에 다음 공지로 바뀌었습니다.
- 두 화면 모두 공지 제목 위에 마우스를 올린 6.6초 동안 공지가 바뀌지 않았습니다.
- Tab 순서는 두 화면 모두 ‘본문 바로가기’, ‘이전 공지’, ‘자세히 - 겨울 독서 교실 모집’, ‘다음 공지’, ‘자동 전환 정지’, 점 버튼 세 개였고, 그다음은 `body`였습니다. 초점을 받은 요소마다 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- `index.html`의 차이는 세 곳입니다. 머리글의 `p` ‘푸른숲도서관’이 `h1` ‘푸른숲도서관 소식’으로 바뀌었습니다. 공지를 감싼 `article` 세 개가 `div`로 바뀌었고 `role="group"`, `aria-roledescription`, `aria-label`은 그대로입니다. `main`에 `tabindex="-1"`이 생겼고 본문의 `h1` ‘푸른숲도서관 소식’이 `h2` ‘도서관 이용 안내’로 바뀌었습니다.
- `script.js`의 차이는 두 곳입니다. 시작할 때 `prefers-reduced-motion`을 보던 코드가 `var userPaused = false`로 바뀌었습니다. `mouseenter`, `mouseleave`가 `pointerType`이 `mouse`일 때만 처리하는 `pointerenter`, `pointerleave`로 바뀌었습니다.
- `style.css`의 차이는 세 곳입니다. 점 목록의 `gap`이 0에서 2px로 바뀌었습니다. 본문 제목의 선택자가 `main h1`에서 `main h2`로 바뀌었습니다. `main:focus{outline:none}`이 더해졌습니다.
- 화살표, 공지, 정지 버튼, 점의 문서 순서는 두 화면이 같습니다.
- 정지 버튼, `aria-live` 전환, 초점으로 멈추는 처리, 글상자와 파스텔 배경, 버튼 크기는 off와 같습니다.

## 미검증 항목

- 스크린 리더 발화: 이전, 다음, 점을 눌렀을 때 새 공지를 읽는지 확인하지 않았습니다. 개발 에이전트는 전환 순간에 `aria-live` 값이 바뀌어 첫 안내가 빠질 수 있다고 적었습니다.
- 건너뛰기 링크를 실행한 뒤 초점이 본문으로 가는지, 그때 윤곽선이 보이지 않는지 두 화면 모두 기록하지 않았습니다.
- 키보드 초점만으로 자동 전환이 멈추는지는 따로 기록하지 않았습니다. 마우스를 올렸다가 뗀 뒤 전환이 다시 진행되는지도 따로 기록하지 않았습니다.
- 정지 버튼의 아이콘이 바뀌는지 확인하지 않았습니다. 개발 에이전트는 정지 버튼에 초점이 있는 동안에는 시작으로 바꿔도 초점 때문에 전환이 멈춰 있을 수 있고, 이는 off 코드의 설계 그대로라고 적었습니다. 이 동작도 확인하지 않았습니다.
- 실제 터치 화면에서 공지를 누른 뒤에도 자동 전환이 이어지는지 확인하지 않았습니다. off의 터치 문제도 재현하지 않았습니다.
- Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 흰 글씨와 어두운 글상자의 대비 측정값은 기록에 없습니다. 확장 검사에서 `color-contrast`가 위반과 판정 보류에 나오지 않은 것만 확인했습니다. 개발 에이전트는 가장 밝은 `#f6d6c8` 배경에서 약 7.8:1이라고 손으로 계산했습니다.
- 폭 320px에서는 가로 스크롤만 확인했습니다. 화살표, 글상자, 조작부의 배치와 화면 200% 확대는 확인하지 않았습니다.
