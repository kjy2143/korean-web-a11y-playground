# 공지 배너 · 접근성 자료 적용 (on) 실행 결과

도서관 공지 세 건이 6초마다 바뀌는 배너 화면입니다. 기본 개발 화면을 복사한 뒤, 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선했습니다.

비교 대상인 기본 개발 화면은 [공지 배너 · 기본 개발 (off)](/?demo=2026-11-27-notice-carousel-off)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열면 ‘푸른숲도서관 소식’ 제목 아래에서 배너가 첫 공지를 보여 줍니다. 공지는 6초마다 바뀌고, 세 번째 공지 다음에는 첫 공지로 돌아갑니다.
2. 화살표 버튼과 점 세 개로 공지를 고릅니다. 현재 공지의 점은 진한 색의 긴 알약 모양입니다.
3. ‘자동 전환 정지’를 누르면 전환이 멈추고 버튼 글자가 ‘자동 전환 시작’으로 바뀝니다. 정지한 상태에서 화살표나 점으로 이동해도 정지가 유지됩니다.
4. 화살표를 포함한 공지 영역이나 점에 마우스를 올리거나 키보드 초점을 두면 자동 전환이 멈춥니다. 정지 버튼에 초점을 두는 것만으로는 멈추지 않습니다.
5. Tab 키를 누르면 ‘본문 바로가기’, 이전 공지, ‘자세히’, 다음 공지, 점 세 개, ‘자동 전환 정지’ 순서로 초점이 이동합니다.

## 요청서와 조정한 부분

‘화면 요청서: 공지 배너’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 도서관 소식이 6초마다 바뀌는 배너입니다.
>
> 공지 세 개(‘겨울 독서 교실 모집’, ‘12월 휴관일 안내’, ‘전자책 신규 도서 입고’)를 배너로 보여 줍니다. 공지마다 제목, 한 줄 설명, ‘자세히’ 링크(주소 `#`)가 있습니다. 6초마다 다음 공지로 자동 전환하고, 마지막 다음에는 처음으로 돌아갑니다. 배너 아래에 짧은 페이지 본문을 둡니다.
>
> 디자인 시안: 배너 아래 가운데에 점 세 개를 두고 현재 공지의 점을 진하게 표시합니다. 점을 누르면 그 공지로 이동합니다. 배너 좌우 끝에 화살표 아이콘 버튼을 둡니다. 배너 배경은 공지마다 다른 파스텔색(`#bfe3d0`, `#f6d6c8`, `#cfd8f5`)이고 글씨는 흰색입니다.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트가 조정한 내용과 보고서에 적은 이유는 다음과 같습니다.

| 요청서 또는 off 화면 | on 화면 | 보고서에 적은 이유 |
|---|---|---|
| 파스텔 배경 위 흰 글씨 | off에서 넣은 어두운 반투명 판을 글씨 뒤에 유지 | 흰 글씨의 명도 대비 부족(5.4.3) |
| 현재 점을 진한 색으로만 표시 | 진한 색에 긴 알약 모양을 더함 | 색에만 의존하지 않기(5.4.1) |
| 요청서에 정지 수단 없음 | ‘자동 전환 정지’ 버튼 유지 | 자동으로 바뀌는 배너의 정지 수단(6.2.2) |
| off는 배너 `h2`가 본문 `h1`보다 앞 | 배너를 `main` 안으로 옮기고 `h1`을 배너 위에 둠 | 제목 순서(5.3.2, 6.4.2) |
| off는 점에 초점을 두어도 전환이 계속됨 | 점에 마우스를 올리거나 초점을 두어도 멈춤 | 접근성 개선 |
| off는 전환이 멈춘 상태에서만 `aria-live="polite"` | 화살표나 점으로 직접 이동할 때 `polite`, 자동 전환 때 `off` | 자동 전환은 안내하지 않고 직접 이동만 안내 |
| off는 정지 버튼에 `aria-pressed`와 글자 변경을 함께 사용 | `aria-pressed`를 지우고 글자만 바꿈 | ‘시작, 눌림’처럼 상태가 겹쳐 읽힘 |
| off는 공지를 `article`로 표시 | `div`에 `role="group"`을 줌 | 자료 밖 근거(WAI-ARIA) |

- `h1`이 배너 위에 보이게 된 점은 시안과 다릅니다.
- 보고서는 접근성과 무관한 기능 결함 수정 두 가지를 적었습니다. 하나는 정지 버튼을 멈춤 판단 영역에서 뺀 것입니다. off 코드에서도 정지 버튼은 멈춤 판단 영역 밖에 있었습니다.
- 다른 하나는 터치 입력을 마우스 올림으로 처리하지 않게 한 것입니다. off는 `mouseenter`로 올림을 판단하고, on은 `pointerType`이 `mouse`인 `pointerenter`만 올림으로 처리합니다. 실제 터치 기기에서는 확인하지 않았습니다.
- 공지 세 건의 내용과 ‘자세히’ 링크(주소 `#`), 6초 전환과 순환, 배너 아래 가운데의 점과 점 이동, 좌우 화살표 아이콘 버튼, 공지별 파스텔 배경, 본문 문단, 페이지 제목과 설명은 요청서대로 두었습니다.

## 개발 조건

- 출발점: off 화면을 복사한 뒤 국내 접근성 자료를 조회해 적용하는 절차를 켜고 같은 요청서 기준으로 개선했습니다.
- 충돌 처리: 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 개발 중 확인: 개발 에이전트는 브라우저에서 화면을 실행하지 못했고 코드와 명령으로만 확인했다고 보고했습니다.
- off 파일 보존: on 개발 뒤에도 off 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

- 현재 점을 모양으로도 구분했습니다. [5.4.1 색에 무관한 콘텐츠 인식](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.1.json)

- 점과 정지 버튼 사이에 간격을 두고 정지 버튼에 테두리를 그렸습니다. [5.4.4 콘텐츠 간의 구분](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.4.json)

### 자료 밖 근거

- 캐러셀의 `aria-roledescription`, 공지의 `role="group"`, 공지 영역의 `aria-live`는 WAI-ARIA 표준 지식으로 구현했습니다. [WAI-ARIA 1.2 aria-roledescription](https://www.w3.org/TR/wai-aria-1.2/#aria-roledescription), [WAI-ARIA 1.2 group 역할](https://www.w3.org/TR/wai-aria-1.2/#group), [WAI-ARIA 1.2 aria-live](https://www.w3.org/TR/wai-aria-1.2/#aria-live)
- 자동 전환 때 `aria-live`를 `off`로 바꾸는 방식도 같은 근거입니다.

### 브라우저에서 관찰한 결과

- 두 화면 모두 ‘자동 전환 정지’ 버튼이 있었습니다. 버튼을 누른 뒤 6.6초 동안 공지가 바뀌지 않았습니다.
- 두 화면 모두 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 확장 검사에서 위반 규칙은 두 화면 모두 없었습니다. 판정 보류 규칙은 두 화면 모두 `audit-skip-link` 하나였습니다.
- 배너 위에 마우스를 올린 동안 6.6초가 지나도 공지가 바뀌지 않았습니다. 마우스를 배너 밖으로 옮기자 6.6초 안에 다음 공지로 넘어갔습니다.

### 코드에서 확인한 사실

- 멈춤 판단 영역은 공지 영역(`#stage`)과 점 목록(`#dots`)입니다. 정지 버튼은 이 영역에 들어 있지 않습니다.
- `aria-live`는 처음에 `off`입니다. 화살표나 점으로 이동하면 `polite`로, 자동 전환이 일어나면 `off`로 바뀝니다.
- 현재 점은 `aria-current="true"`와 함께 폭 24px의 긴 모양으로 그려집니다.
- 정지 버튼에는 `aria-pressed`가 없고, 아이콘 모양은 `.is-paused` 클래스로 바뀝니다.

## 미검증 항목

- 스크린 리더 발화: 점이나 화살표로 이동할 때 공지를 안내하는지, 자동 전환은 안내하지 않는지 확인하지 않았습니다. 보고서는 `aria-live` 값을 바꾼 직후 내용이 바뀌는 방식이라 환경에 따라 안내가 빠질 수 있다고 적었습니다.
- 점이나 화살표에 초점을 둔 동안 자동 전환이 멈추는지는 브라우저에서 확인하지 않았습니다.
- 실제 터치 기기에서 배너를 눌렀을 때 전환이 멈춘 채 남지 않는지 확인하지 않았습니다.
- Chrome 외 브라우저, 200% 확대, 글자 간격 조정 상태는 확인하지 않았습니다.
- 동작 줄이기 설정에서 정지 상태로 시작하는지 확인하지 않았습니다.
- 개발 중 읽지 못한 자료: 보고서는 모든 레코드를 내려받았다고 적었습니다. 6.1.1, 6.1.2, 6.2.1, 6.3.1 등은 본문과 기본 규칙만 읽고 사례 레코드는 읽지 않았습니다. 6.5.1, 7.1.1, 8.1.1은 본문을 읽지 않았습니다. 보고서는 그 이유를 적지 않았습니다. 개발 중에는 여러 레코드를 한 번에 내려받거나 읽는 복합 명령 일부가 셸 명령 제한으로 거부됐습니다.
