# 관심 프로그램 · 접근성 자료 적용 (on) 실행 결과

관심 프로그램 카드 세 개의 순서를 끌기나 버튼으로 바꾸는 화면입니다. 기본 개발 화면을 복사한 뒤, 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선했습니다. 카드마다 위·아래 이동 버튼이 생겼고, 손잡이는 끌기 전용 요소가 됐습니다. 확장 검사는 off와 같이 위반 규칙과 판정 보류 규칙이 없었습니다. 키보드 Enter로 버튼을 눌러 카드가 이동하고 초점이 같은 버튼에 남는 것을 확인했습니다. 마우스로 버튼을 누르는 조작은 확인하지 못했습니다.

비교 대상인 기본 개발 화면은 [관심 프로그램 · 기본 개발 (off)](/?demo=2026-11-27-program-reordering-off)에서 볼 수 있습니다.

## 사용 방법

1. 카드 왼쪽의 점 여섯 개 손잡이를 끌어 다른 카드 위에 놓으면 순서가 바뀝니다. 끌기를 취소하려면 Esc 키를 누르거나 카드 밖에서 놓습니다.
2. 카드 오른쪽의 위·아래 버튼을 누르면 카드가 한 칸씩 이동합니다. 키보드에서는 Tab으로 버튼에 이동해 Enter나 Space를 누릅니다.
3. 맨 위 카드의 위 버튼과 맨 아래 카드의 아래 버튼은 점선 테두리로 바뀌고 눌러도 이동하지 않습니다. 이 버튼도 Tab 초점은 받습니다.
4. 이동하면 화면에서 숨긴 상태 영역에 ‘그림책 읽기, 3개 중 3번째로 이동했습니다.’ 같은 문구가 들어갑니다.
5. 순서는 저장하지 않으므로 새로고침하면 처음 순서로 돌아갑니다.

## 요청서와 조정한 부분

‘화면 요청서: 관심 프로그램’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 관심 프로그램 카드의 순서를 바꿉니다.
>
> 관심 프로그램 카드 세 개(‘그림책 읽기’ 토 10:00 어린이실, ‘동네 사진 산책’ 일 14:00 1층 로비, ‘겨울 글쓰기 모임’ 수 19:00 세미나실)의 순서를 바꾸는 화면입니다. 새로고침하면 처음 순서로 돌아가도 됩니다.
>
> 디자인 시안: 카드 왼쪽의 점 여섯 개 손잡이 아이콘을 끌어 다른 카드 위에 놓으면 순서가 바뀝니다. 카드에는 다른 버튼을 두지 않습니다. 카드의 요일·장소 정보는 `#aaaaaa`입니다.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트가 조정한 내용과 보고서에 적은 이유는 다음과 같습니다.

| 요청서 또는 off 화면 | on 화면 | 보고서에 적은 이유 |
|---|---|---|
| 카드에 다른 버튼을 두지 않음 | 카드마다 위·아래 버튼 추가 | 끌기만으로 되는 기능은 끌기 없이 한 번의 포인터 입력으로도 조작할 수 있어야 함(6.5.1). off의 화살표 키 조작은 포인터 입력이 아니어서 이 요구를 충족하지 못함 |
| off의 손잡이는 초점을 받는 `button`이고 화살표 키로 이동 | 손잡이는 `aria-hidden` 요소이고 끌기 전용. 화살표 키 조작은 없앰 | off의 손잡이 버튼은 Enter를 눌러도 아무 일이 없는 초점 정지점이었음. 키보드 조작은 새 버튼이 맡음 |
| off의 놓을 대상 카드는 노란 그림자 | 노란 그림자에 점선 테두리를 더함 | 색에 무관한 콘텐츠 인식(5.4.1) |

보고서가 그대로 두었다고 적은 부분은 다음과 같습니다.

- 요일·장소 글자 `#aaaaaa`는 off에서 정한 카드 배경 `#222b27` 위에서 그대로 두었습니다. 개발 에이전트는 명도 대비를 직접 계산해 약 6.3:1이라고 적었습니다.
- 카드 구성, 손잡이 모양, 데스크톱과 폭 320px 레이아웃은 유지했습니다.
- 맨 위 카드의 위 버튼과 맨 아래 카드의 아래 버튼은 `disabled` 대신 `aria-disabled`로 표시했습니다. 보고서는 `disabled`로 바꾸면 방금 누른 버튼의 초점이 사라지기 때문이라고 적었습니다.

보고서는 접근성 개선과 별도로 기능 결함 두 가지를 고쳤다고 적었습니다.

- 손가락 두 개로 서로 다른 손잡이를 동시에 누르면 끌기 상태가 뒤섞일 수 있었습니다. 끌기 중에는 새 끌기를 시작하지 않도록 막았습니다.
- 끌 때 손잡이 주변 글자가 선택되지 않도록 `user-select: none`을 더했습니다.

보고서에 없지만 코드에서 달라진 부분도 있습니다. 도움말 문구가 끌기와 위·아래 버튼, 끌기 취소 안내로 바뀌었습니다. off에서 손잡이에 걸었던 `aria-describedby` 연결은 on에 없습니다.

## 개발 조건

- 출발점: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켜고 같은 요청서 기준으로 개선하게 했습니다. 질문하지 말고 개선까지 마치게 했습니다.
- 충돌 처리: 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다.
- 모델과 실행 방식: off와 같이 Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 이 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다. 개발 에이전트는 코드와 명령으로만 확인했습니다.
- 셸 명령: 허용한 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 2건으로, `cat`의 출력을 임시 파일로 보내려던 명령과 `python3` 명령이었습니다. 개발 에이전트는 명도 대비 계산 스크립트를 실행하지 못해 수식을 손으로 풀었고, 나머지 색 조합은 검사하지 않았다고 보고했습니다.
- 자료 조회: 설정 확인, 절차 문서, 자료 목록, 레코드 순서로 읽었습니다. 화면 종류와 관계없이 고르는 12개 항목(5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1)의 레코드를 모두 받았습니다. 여기에 6.5.1, 6.5.2, 8.2.1을 더해 KWCAG 레코드 15개를 읽었습니다. NIA 사례 레코드는 2.5.1과 4.2.1의 적용 사례와 개선 필요 사례 4개를 읽었습니다. 자료 조회 명령 20회는 모두 주소 하나에 명령 하나인 같은 형태였고, 실패한 조회는 없었습니다.
- 개발 중 확인: 개발 에이전트는 코드와 명령으로만 확인했고 실제 조작은 확인하지 못했다고 보고했습니다. 스크립트는 문법 검사만 통과시켰고, 초점 복원과 `aria-disabled` 갱신은 코드를 읽어 확인했다고 적었습니다.
- 수정 요청: 이 화면에는 검증 뒤 수정 요청을 보내지 않았습니다.
- off 파일 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 첫 실행에서는 on 화면을 만들지 않았습니다. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. 이때 off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준과 참고 자료

적용 항목과 근거 구분은 개발 에이전트의 보고서를 따릅니다. 보고서는 KWCAG 본문을 요구사항, NIA 제작기법을 권장 사항으로 구분했습니다.

### KWCAG 2.2 요구사항

- 순서 변경을 문서 안의 요소 이동으로 처리해 읽는 순서와 화면 순서를 맞췄습니다. [5.3.2 콘텐츠의 선형구조](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.3.2.json)
- 놓을 대상 표시에 노란 그림자와 함께 점선 테두리를 더했습니다. [5.4.1 색에 무관한 콘텐츠 인식](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.1.json)
- 요일·장소 글자의 대비를 직접 계산해 약 6.3:1로 확인했습니다. [5.4.3 텍스트 콘텐츠의 명도 대비](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.3.json)
- 카드를 간격과 배경색으로 구분합니다. [5.4.4 콘텐츠 간의 구분](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.4.json)
- 이동 버튼을 기본 `button`으로 만들어 키보드로 조작하게 했습니다. [6.1.1 키보드 사용 보장](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.1.json)
- 이동 뒤 누른 버튼에 초점을 되돌리고, 3px 노란 초점 표시를 두었습니다. [6.1.2 초점 이동과 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.2.json)
- 버튼을 44×44px로 만들고 버튼 사이에 4px 간격을 두었습니다. 보고서는 근거를 요구사항으로 적고, 대각선 6mm 이상이라는 크기는 본문에서 ‘바람직하다’로 적혀 있다고 덧붙였습니다. [6.1.3 조작 가능](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.3.json)
- 페이지 제목, `h1`, 카드별 `h2`가 있습니다. [6.4.2 제목 제공](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.4.2.json)
- 끌기의 대체 수단으로 위·아래 버튼을 더했습니다. 보고서는 대체 수단 제공을 요구사항으로, 이동 버튼이라는 제공 방식을 권장 사항으로 나눠 적었습니다. [6.5.1 단일 포인터 입력 지원](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.1.json)
- 포인터를 떼는 순간에 이동을 실행하고, Esc나 카드 밖에서 놓기로 취소합니다. [6.5.2 포인터 입력 취소](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.2.json)
- 버튼에 보이는 글자가 없어 적용 대상이 아니라고 판단했습니다. 이름은 ‘그림책 읽기 위로 이동’ 형식으로 제공했습니다. [6.5.3 레이블과 네임](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.3.json)
- `<html lang="ko">`입니다. [7.1.1 기본 언어 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-7.1.1.json)
- 초점만으로는 순서가 바뀌지 않습니다. [7.2.1 사용자 요구에 따른 실행](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-7.2.1.json)
- `id` 중복을 검사해 중복이 없음을 확인했습니다. [8.1.1 마크업 오류 방지](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-8.1.1.json)
- `button`을 쓰고, 순서 변경 결과를 `role="status"`로 알립니다. 보고서는 본문을 요구사항으로, 사례를 권장 사항으로 나눠 적었습니다. [8.2.1 웹 애플리케이션 접근성 준수](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-8.2.1.json)

### NIA 제작기법 권장 사항

- 끌기의 대체 수단을 이동 버튼으로 제공한 방식(6.5.1)은 NIA 2.5.1의 사례를 참고했습니다. [적용 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-2.5.1-s4.json), [개선 필요 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-2.5.1-s5.json)
- 직접 만든 조작 요소(8.2.1)는 NIA 4.2.1의 사례를 참고했습니다. 보고서는 ‘나쁜 ARIA보다 ARIA가 없는 것이 낫다’는 원칙이 개선 필요 사례 레코드에 있는 내용이라고 적었습니다. [적용 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-4.2.1-s4.json), [개선 필요 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-4.2.1-s5.json)

### 자료 밖 근거

- 더 이동할 수 없는 위치의 버튼을 `aria-disabled`로 표시했습니다. [WAI-ARIA 1.2 aria-disabled](https://www.w3.org/TR/wai-aria-1.2/#aria-disabled)
- 이동 안내는 `role="status"` 영역으로 전합니다. 보고서는 이 처리를 8.2.1의 적용 내용과 자료 밖 근거에 모두 적었습니다. [WAI-ARIA 1.2 status 역할](https://www.w3.org/TR/wai-aria-1.2/#status)
- 보고서는 W3C 표준 문서를 직접 열어 확인하지는 않았다고 적었습니다.

### 브라우저에서 관찰한 결과

- 두 화면 모두 확장 검사에서 위반 규칙과 판정 보류 규칙이 없었습니다. 통과 규칙 수는 off 22개, on 21개입니다. 어떤 규칙이 달라졌는지는 기록하지 않았습니다.
- on에서 마우스로 첫 카드의 손잡이를 마지막 카드의 아래쪽으로 끌어 놓자 순서가 ‘동네 사진 산책, 겨울 글쓰기 모임, 그림책 읽기’로 바뀌었습니다. 상태 영역에는 ‘그림책 읽기, 3개 중 3번째로 이동했습니다.’가 들어갔습니다. off도 같았습니다.
- on에서 첫 카드의 아래 버튼에 초점을 두고 Enter를 누르자 순서가 ‘동네 사진 산책, 그림책 읽기, 겨울 글쓰기 모임’으로 바뀌었습니다. 초점은 ‘그림책 읽기 아래로 이동’ 버튼에 남았습니다.
- Enter를 한 번 더 누르자 ‘그림책 읽기’가 맨 뒤로 갔습니다. 초점은 같은 버튼에 남았고, 상태 영역에는 ‘그림책 읽기, 3개 중 3번째로 이동했습니다.’가 들어갔습니다.
- 이어서 맨 뒤 카드의 ‘그림책 읽기 위로 이동’ 버튼에 초점을 두고 Enter를 누르자 카드가 한 칸 위로 이동했습니다. 초점은 그 버튼에 남았습니다.
- on에서 ‘그림책 읽기 위로 이동’ 버튼에 초점을 두고 아래쪽 화살표 키를 누르면 순서가 바뀌지 않았습니다. off에서는 손잡이에서 같은 키로 카드가 한 칸 이동했습니다.
- on의 Tab 정지점은 버튼 6개였고 카드 순서대로 위 버튼, 아래 버튼 순이었습니다. 더 이동할 수 없다고 표시된 ‘그림책 읽기 위로 이동’과 ‘겨울 글쓰기 모임 아래로 이동’도 초점을 받았습니다.
- 두 화면 모두 초기 상태의 콘솔 오류와 조작 중 페이지 오류가 0건이었습니다.

### 코드에서 확인한 사실

- 손잡이는 `aria-hidden="true"`를 준 `span`이고 초점을 받지 않습니다.
- 이동 버튼은 `aria-label`이 있는 `button`입니다. 스크립트가 순서가 바뀔 때마다 맨 위 카드의 위 버튼과 맨 아래 카드의 아래 버튼에 `aria-disabled="true"`를 줍니다. `disabled` 속성은 쓰지 않습니다.
- 버튼의 클릭 처리기는 `aria-disabled="true"`이면 아무 일도 하지 않습니다. 그렇지 않으면 카드의 `li`를 `insertBefore`로 옮기고, 누른 버튼에 `focus()`를 호출하고, 상태 문구를 씁니다.
- 화살표 키를 처리하는 코드는 없습니다. 키 입력 처리는 끌기 중 Esc로 취소하는 것뿐입니다.
- 끌기는 `pointerup`에서 놓을 대상 카드가 있을 때만 이동합니다. `pointercancel`이거나 놓을 대상이 없으면 이동하지 않습니다. 다른 끌기가 진행 중이면 `pointerdown`을 무시합니다.
- 놓을 대상 카드는 노란 3px 그림자와 노란 점선 테두리로 표시합니다.
- `aria-disabled="true"`인 버튼은 배경을 없애고 점선 테두리와 흐린 아이콘 색(`#9aa49f`)으로 표시합니다.
- 버튼은 44×44px이고 버튼 사이 간격은 4px입니다. 초점 표시는 3px `#ffd54a` 윤곽선입니다.

## 미검증 항목

- 마우스로 위·아래 버튼을 눌러 순서가 바뀌는지 확인하지 못했습니다. 버튼의 동작은 키보드 Enter로만 확인했습니다.
- 손잡이를 한 번 눌렀을 때 순서가 그대로인지 on에서는 확인하지 못했습니다. 확인 스크립트가 페이지의 첫 `button`을 누르게 돼 있었습니다. on에서는 그 버튼이 더 이동할 수 없다고 표시된(`aria-disabled="true"`) ‘그림책 읽기 위로 이동’이어서 클릭 단계가 30초 시간 초과로 끝났습니다. 화면의 결함으로 판단할 근거가 아니어서 미검증으로 둡니다.
- `aria-disabled="true"`인 버튼을 눌렀을 때 반응이 없는지 브라우저에서 확인하지 않았습니다.
- 끌기 중 Esc를 누르거나 카드 밖에서 놓을 때 순서가 그대로인지 브라우저에서 확인하지 않았습니다.
- Space 키로 버튼을 누르는 동작과, 이동한 뒤의 Tab 순서는 확인하지 않았습니다.
- 스크린 리더 발화: 버튼 이름(‘그림책 읽기 위로 이동’ 형식), `aria-disabled` 상태, 이동 안내를 읽는지 확인하지 않았습니다.
- 폭 320px에서 제목이 줄바꿈되는지, 200% 확대에서 레이아웃이 유지되는지 확인하지 않았습니다. 폭 320px에서 가로 스크롤이 없다는 것만 확인했습니다.
- 실제 터치 기기에서 손잡이를 끌 때 페이지가 스크롤되지 않는지 확인하지 않았습니다. 보고서가 기능 결함으로 고쳤다고 적은 두 손가락 동시 터치 상황도 확인하지 않았습니다.
- 요일·장소 글자의 측정 대비는 기록에 없습니다. 약 6.3:1은 개발 에이전트가 손으로 계산한 값입니다. 확장 검사에서 `color-contrast` 위반은 없었습니다.
- Chrome 외 브라우저는 확인하지 않았습니다.
- 개발 중 읽지 못한 자료: 보고서는 읽지 못한 주소가 없다고 적었습니다. 사례 레코드는 6.5.1(끌어서 놓기)과 8.2.1(직접 만든 조작 요소)만 읽었고, 나머지 항목의 적용 사례와 개선 필요 사례 레코드는 읽지 않았다고 적었습니다. 6.4.1, 6.2.2 등은 이 화면에 해당 요소가 없어 레코드를 읽지 않았다고 적었습니다.
