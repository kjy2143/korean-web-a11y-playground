# 관심 프로그램 · 접근성 자료 적용 (on) 실행 결과

관심 프로그램 카드 세 개의 순서를 끌기나 버튼으로 바꾸는 화면입니다. 기본 개발 화면을 복사한 뒤, 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선했습니다. 검증에서 키보드로 카드를 옮긴 뒤 초점이 사라지는 결함을 찾아 같은 개발 에이전트에게 한 번 수정을 요청했습니다. 수정 뒤에는 이동한 뒤에도 초점이 이어졌습니다.

비교 대상인 기본 개발 화면은 [관심 프로그램 · 기본 개발 (off)](/?demo=2026-11-27-program-reordering-off)에서 볼 수 있습니다.

## 사용 방법

1. 카드 왼쪽의 점 여섯 개 손잡이를 끌어 다른 카드 위에 놓으면 순서가 바뀝니다. 카드가 아닌 곳에서 놓거나 포인터 입력이 취소되면 순서가 그대로입니다.
2. 각 카드의 ‘위로’, ‘아래로’ 버튼을 누르면 카드가 한 칸씩 이동합니다. 첫 카드의 ‘위로’와 마지막 카드의 ‘아래로’는 비활성입니다.
3. 이동하면 화면에 보이지 않는 상태 영역에 ‘그림책 읽기, 3개 중 2번째로 이동했습니다.’ 같은 문구가 들어갑니다.
4. 키보드로 버튼을 누르면 카드가 이동한 뒤에도 초점이 같은 버튼에 남습니다. 카드가 맨 앞이나 맨 뒤에 닿아 그 버튼이 비활성이 되면 같은 카드의 반대 방향 버튼으로 초점이 옮겨집니다.
5. 순서는 저장하지 않으므로 새로고침하면 처음 순서로 돌아갑니다.

## 요청서와 조정한 부분

‘화면 요청서: 관심 프로그램’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 관심 프로그램 카드의 순서를 바꿉니다.
>
> 관심 프로그램 카드 세 개(‘그림책 읽기’ 토 10:00 어린이실, ‘동네 사진 산책’ 일 14:00 1층 로비, ‘겨울 글쓰기 모임’ 수 19:00 세미나실)의 순서를 바꾸는 화면입니다. 새로고침하면 처음 순서로 돌아가도 됩니다.
>
> 디자인 시안: 카드 왼쪽의 점 여섯 개 손잡이 아이콘을 끌어 다른 카드 위에 놓으면 순서가 바뀝니다. 카드에는 다른 버튼을 두지 않습니다. 카드의 요일·장소 정보는 `#aaaaaa`입니다.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트가 조정한 내용과 보고서에 적은 이유는 다음과 같습니다.

| 요청서 또는 off 화면 | on 화면 | 보고서에 적은 이유 |
|---|---|---|
| 카드에 다른 버튼을 두지 않음 | 카드마다 ‘위로’, ‘아래로’ 버튼 추가 | 끌기만으로는 단일 포인터로 조작할 수 없음(6.5.1). 사전 승인된 조정 |
| off의 손잡이는 `button`이고 화살표 키로 이동 | 손잡이는 끌기 전용 장식 요소(`aria-hidden`, 초점 없음). 화살표 키 이동은 없앰 | 키보드와 음성 사용자는 버튼으로 이동 |
| off의 도움말은 끌기와 화살표 키 안내 | 끌기와 위로·아래로 버튼 안내 | 버튼 사용 안내 |
| off의 놓을 위치 카드는 노란 테두리 | 노란 테두리에 점선을 더함 | 색만으로 구분되지 않게 함(5.4.1) |

- 요일·장소 글자 `#aaaaaa`는 off에서 정한 어두운 카드 배경(`#1e2b26`) 위에서 그대로 두었습니다. 개발 에이전트는 손으로 계산해 기준을 충족한다고 판단했고, 스크립트로 검증하지 못했다고 적었습니다.
- 보고서는 접근성과 무관한 기능 결함을 찾지 못했다고 적었습니다. 끌기 취소와 같은 카드 위에서 놓기는 코드상 정상으로 보여 고치지 않았습니다.
- 검증 뒤 수정: 키보드 이동 뒤 초점이 사라지는 결함은 개발 조건에 적은 수정 요청 한 번으로 고쳤습니다.

## 개발 조건

- 출발점: off 화면을 복사한 뒤 국내 접근성 자료를 조회해 적용하는 절차를 켜고 같은 요청서 기준으로 개선했습니다.
- 충돌 처리: 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. 개발 에이전트는 Python 실행이 막혀 명도 대비를 손으로 계산했다고 보고했습니다.
- 개발 중 확인: 개발 에이전트는 브라우저를 쓰지 못해 코드와 구문 검사로만 확인했다고 보고했습니다.
- 검증 뒤 수정 요청: 브라우저 검증에서 키보드로 첫 카드의 ‘아래로’나 마지막 카드의 ‘위로’를 누르면 초점이 `body`로 사라지는 것을 확인했습니다. 같은 개발 세션(설정 on)을 이어서 실행해 관찰한 현상만 담은 결함 보고를 한 번 보냈습니다. 개발 에이전트는 `script.js` 한 줄을 고쳐, 이동 뒤 누른 버튼이 활성이면 그 버튼으로, 비활성이면 같은 카드의 활성 버튼으로 초점을 되돌리게 했습니다.
- off 파일 보존: on 개발 뒤에도 off 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준과 참고 자료

근거 구분은 개발 에이전트의 보고서를 따릅니다.

### KWCAG 2.2 요구사항

- `ol`과 `li`의 순서를 문서에서 직접 바꿔 화면 순서와 읽는 순서를 맞췄습니다. [5.3.2 콘텐츠의 선형구조](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.3.2.json)
- 도움말이 위치나 모양이 아닌 ‘위로·아래로 버튼’이라는 이름으로 지시합니다. [5.3.3 명확한 지시사항 제공](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.3.3.json)
- 놓을 위치를 색과 점선으로 표시합니다. [5.4.1 색에 무관한 콘텐츠 인식](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.1.json)
- 요일·장소 `#aaaaaa`와 버튼의 흰 글자가 모두 4.5:1 이상이라고 판단했습니다. [5.4.3 텍스트 콘텐츠의 명도 대비](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.3.json)
- 카드를 배경과 간격으로 구분합니다. [5.4.4 콘텐츠 간의 구분](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.4.json)
- 버튼이 기본 `button`이라 Tab, Enter, Space로 동작합니다. [6.1.1 키보드 사용 보장](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.1.json)
- 버튼에 노란 초점 윤곽선을 두었습니다. 이동 뒤 누른 버튼이 활성이면 그 버튼에, 비활성이 되면 같은 카드의 다른 버튼에 초점을 둡니다. 활성인 경우의 처리는 검증 뒤 수정으로 더했습니다. [6.1.2 초점 이동과 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.2.json)
- 버튼은 최소 44×44px이고 버튼 사이 간격은 8px입니다. 보고서는 컨트롤 크기를 본문이 ‘바람직’으로 쓴 부분으로 구분했습니다. [6.1.3 조작 가능](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.3.json)
- 페이지 `title`, `h1`, 카드별 `h2`가 있습니다. [6.4.2 제목 제공](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.4.2.json)
- 끌어서 놓기의 대체 수단으로 버튼을 제공했습니다. [6.5.1 단일 포인터 입력 지원](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.1.json)
- 포인터를 뗄 때만 이동이 실행되고, 카드 밖에서 놓으면 취소됩니다. [6.5.2 포인터 입력 취소](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.2.json)
- 보이는 글자 ‘위로’, ‘아래로’가 이름의 앞부분에 있고, 뒤에 숨긴 텍스트로 카드 이름을 붙였습니다. [6.5.3 레이블과 네임](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.3.json)
- `lang="ko"`입니다. [7.1.1 기본 언어 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-7.1.1.json)
- 초점만으로는 이동하지 않고, 버튼 클릭이나 끌어서 놓기로만 이동합니다. [7.2.1 사용자 요구에 따른 실행](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-7.2.1.json)
- `id` 중복이 없고 태그의 열고 닫음이 맞는지 눈으로 확인했습니다. [8.1.1 마크업 오류 방지](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-8.1.1.json)

보고서는 [8.2.1 웹 애플리케이션 접근성 준수](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-8.2.1.json)도 읽었지만, 플러그인이나 별도 웹 애플리케이션을 쓰지 않아 적용 항목에서 뺐습니다.

### NIA 제작기법 권장 사항

- 끌어서 놓기의 대체 수단(6.5.1)은 NIA 2.5.1의 사례를 참고했습니다. [적용 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-2.5.1-s4.json), [개선 필요 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-2.5.1-s5.json)
- 보고서는 NIA 2.1.1 키보드 사용 보장의 사례 레코드도 읽었다고 적었지만, 적용 항목과 연결하지 않았습니다.

### 자료 밖 근거

- 이동 안내는 `role="status"`(`aria-live="polite"`) 영역으로 전합니다. [WAI-ARIA 1.2 status 역할](https://www.w3.org/TR/wai-aria-1.2/#status)
- 손잡이는 `aria-hidden`으로 보조기술에서 숨겼습니다. [WAI-ARIA 1.2 aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden)
- 비활성이 된 버튼에서 초점을 옮기는 처리는 일반적인 구현 관행이며 자료에는 없다고 적었습니다.

## 검증 결과

### 브라우저에서 관찰한 결과

- on에서 ‘위로’, ‘아래로’ 버튼을 한 번 눌러 순서를 바꿀 수 있었습니다. 상태 문구 ‘그림책 읽기, 3개 중 2번째로 이동했습니다.’가 표시됐습니다.
- 수정 전에는 키보드로 첫 카드의 ‘아래로’ 또는 마지막 카드의 ‘위로’ 버튼을 누르면 카드는 이동했지만 초점이 `body`로 사라져 이어서 조작할 수 없었습니다.
- 수정 뒤에는 활성 버튼 4개 모두 이동 뒤 초점이 이어졌습니다. 첫 카드의 ‘아래로’를 Enter로 두 번 누르면 카드가 맨 뒤로 갔고, 초점은 같은 카드의 ‘위로’로 옮겨졌습니다. 이어서 Space를 누르면 한 칸 위로 이동했고 초점은 그 버튼에 남았습니다. 마우스 클릭과 끌기로도 순서가 바뀌었습니다.
- off에서는 손잡이 버튼에 초점을 둔 채 아래쪽 화살표 키를 누르면 순서가 바뀌었고 초점은 손잡이에 남았습니다. Enter만 누르면 순서가 바뀌지 않았습니다. 손잡이를 한 번 누르는 것만으로도 바뀌지 않았습니다.
- 두 화면 모두 확장 검사에서 위반과 판정 보류 규칙이 없었습니다.
- 수정 뒤 초기 상태와 끌어서 이동한 상태를 다시 검사해도 위반과 판정 보류 규칙이 없었습니다(0 / 0 / 22).

### 코드에서 확인한 사실

- 버튼으로 이동할 때 스크립트는 초점이 있는 카드의 `li` 요소를 `insertBefore`로 목록에 다시 끼웁니다.
- 수정 전에는 이동 뒤 초점을 다시 맞추는 처리가 누른 버튼이 비활성으로 바뀐 경우에만 있었습니다.
- 수정 뒤에는 이동이 끝나면 누른 버튼이 활성이면 그 버튼에, 비활성이면 같은 카드의 활성 버튼에 `focus()`를 호출합니다.
- 초점이 풀린 직접 원인(초점이 있는 `li`를 `insertBefore`로 옮길 때 브라우저가 초점을 해제하는지)은 따로 확인하지 않았습니다. 개발 에이전트는 이것을 원인으로 보고했습니다.
- off는 이동 뒤 `handle.focus()`로 초점을 손잡이에 되돌립니다.
- 손잡이는 `span`에 `aria-hidden="true"`를 준 요소이고 초점을 받지 않습니다.

## 미검증 항목

- 마우스로 버튼을 누른 뒤 이어서 키보드로 조작할 때의 초점 동작은 확인하지 않았습니다.
- 스크린 리더 발화: 버튼 이름(‘위로 이동, 그림책 읽기’ 형식)과 이동 안내를 읽는지 확인하지 않았습니다.
- 실제 터치 기기에서 손잡이를 끌 때 페이지가 같이 스크롤되지 않는지 확인하지 않았습니다.
- 카드 밖에서 놓거나 포인터 입력이 취소될 때 순서가 그대로인지 브라우저에서 확인하지 않았습니다.
- 폭 320px에서 버튼 줄이 카드 안에서 잘리지 않는지, 200% 확대에서 버튼과 글자가 겹치지 않는지 눈으로 확인하지 않았습니다. 가로 스크롤이 없다는 것만 확인했습니다.
- Chrome 외 브라우저는 확인하지 않았습니다.
- 개발 중 읽지 못한 자료: 보고서는 요청한 주소를 모두 읽어 읽지 못한 자료가 없다고 적었습니다.
