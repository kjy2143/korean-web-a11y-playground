# 회원가입 · 접근성 자료 적용 (on) 실행 결과

푸른숲도서관 회원가입 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-signup-page-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사 결과는 off와 같았습니다. 두 화면 모두 위반이 없고 건너뛰기 링크 규칙(audit-skip-link) 하나가 판정 보류로 남았습니다. 화면에서 보이는 차이는 입력란 레이블에 붙은 ‘필수’ 글자와 색을 언급하지 않는 안내 문장입니다.

## 사용 방법

- 아이디(영문 소문자·숫자 4~12자), 비밀번호(8자 이상), 비밀번호 확인, 이메일을 입력합니다.
- ‘[필수] 이용약관 동의’와 ‘[필수] 개인정보 수집·이용 동의’를 선택하고 ‘가입하기’를 누르면 가입 완료 화면으로 바뀝니다.
- 빈 칸이나 틀린 값으로 제출하면 화면 위쪽에 오류 요약이 나타나고 초점이 요약으로 이동합니다. 요약의 항목을 누르면 해당 입력란으로 이동합니다.
- off 화면과 나란히 열어 입력란 레이블의 ‘필수’ 글자와 본문 위 안내 문장을 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 회원가입’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 입력 오류를 고치고 필수 약관에 동의해 가입을 완료합니다.
>
> 아이디(영문 소문자·숫자 4~12자), 비밀번호(8자 이상), 비밀번호 확인, 이메일을 입력받습니다. 약관은 ‘[필수] 이용약관 동의’, ‘[필수] 개인정보 수집·이용 동의’, ‘[선택] 소식 메일 받기’와 ‘전체 동의’입니다. ‘가입하기’를 누르면 입력값을 검사해 틀린 항목을 알려 주고, 모두 맞으면 같은 페이지를 가입 완료 화면으로 바꿉니다.
>
> 디자인 시안: 입력란 위에 제목 없이 안내 문구만 표시합니다(예: ‘아이디 (영문 소문자·숫자 4~12자)’). 필수 입력란은 오른쪽 위에 작은 빨간 점을 찍습니다. 약관 동의는 디자인한 원형 체크 아이콘을 쓰고 기본 체크박스 모양은 보이지 않게 합니다. 입력 규칙 같은 보조 안내 글씨는 `#b0b0b0`입니다. 오류가 나면 입력란 테두리를 빨간색으로 바꿉니다.

on 개발 에이전트는 off 화면이 대부분 기준을 충족했다고 보고 필요한 부분만 고쳤습니다. `script.js`는 바꾸지 않았습니다. 요청서 시안과의 관계는 아래와 같습니다.

| 요청서 시안 | 조정한 내용 | 이유 |
| --- | --- | --- |
| 보조 안내 글씨 `#b0b0b0` | `#6b6b6b`를 유지했습니다. 이 조정은 off에 이미 있었습니다. | `#b0b0b0`은 흰 배경에서 4.5:1에 못 미칩니다(5.4.3). |
| 필수 입력란에 작은 빨간 점 | 빨간 점은 유지하고, 입력란 네 개의 레이블에 보이는 글자 ‘필수’를 더했습니다. 본문 위 안내 문장을 ‘입력란은 모두 필수이고, [필수] 약관에 동의해야 가입할 수 있습니다.’로 바꿨습니다. | 색과 점만으로는 필수 여부를 알 수 없습니다(5.4.1). off의 안내 문장은 ‘빨간 점’이라는 색에 기대어 설명했습니다(5.3.3). |
| 입력란 위에 제목 없이 안내 문구만 | 안내 문구를 레이블 안에 둔 off의 구조를 유지했습니다. | `label for`로 연결해 레이블을 제공합니다(7.3.2). |
| 오류 시 빨간 테두리 | 테두리를 유지하고 오류 문구, ‘!’ 기호, 두꺼운 테두리를 함께 씁니다. ‘!’ 기호는 스크린 리더가 읽지 않게 했습니다. | 색만으로 오류를 알리지 않습니다. |
| 원형 체크 아이콘, 기본 체크 상자 숨김 | 기본 체크 상자를 `opacity:0`으로 남긴 off의 구조를 유지했습니다. | 실제 입력 요소가 남아 키보드와 보조기술로 조작할 수 있습니다. |

요청서와 관계없는 접근성 수정이 하나 더 있습니다. ‘본문 바로가기’가 실제로 초점을 옮기도록 `main`에 `tabindex="-1"`을 붙였습니다. 접근성과 무관한 기능 결함은 찾지 못해 고치지 않았다고 보고했습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치고, 접근성과 무관한 기능 결함을 고쳤으면 따로 구분해 적게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

### 자료 밖 근거

- ‘!’ 기호 숨김: `content: "! " / ""`는 CSS 생성 콘텐츠의 대체 텍스트 문법입니다. [CSS Generated Content 대체 텍스트](https://www.w3.org/TR/css-content-3/#alt)
- 건너뛰기 대상의 초점: `tabindex="-1"`로 `main`이 초점을 받게 했습니다. [HTML tabindex](https://html.spec.whatwg.org/multipage/interaction.html#attr-tabindex)
- 필수와 오류 상태: `aria-required`, `aria-invalid`, `aria-describedby`를 썼습니다. [aria-required](https://www.w3.org/TR/wai-aria-1.2/#aria-required) · [aria-invalid](https://www.w3.org/TR/wai-aria-1.2/#aria-invalid) · [aria-describedby](https://www.w3.org/TR/wai-aria-1.2/#aria-describedby)

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서입니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 확장 검사: 초기 상태 | 0 / 1 / 23 | 0 / 1 / 23 |
| 확장 검사: 빈 값 제출 | 0 / 1 / 28 | 0 / 1 / 28 |
| 주요 위반·판정 보류 규칙 | 위반 없음. audit-skip-link 판정 보류 | 위반 없음. audit-skip-link 판정 보류 |
| 키보드 조작 | Tab 이동과 초점 표시 있음. 빈 값 제출 시 오류 요약으로 초점 이동 | off와 같음. Tab 순서도 같음 |
| 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | 0건 | 0건 |
| 입력란 이름 | ‘필수’ 없음 | ‘필수’ 포함 |

### 브라우저에서 관찰한 결과

- 두 화면 모두 빈 값으로 제출하면 초점이 오류 요약(`#error-summary`)으로 이동했고, `aria-invalid`가 붙은 요소가 6개였습니다.
- 1280px에서 Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다. Tab 순서는 off와 같았습니다.
- on의 입력란 이름에는 ‘필수’가 들어 있었습니다.
- `main`에 `tabindex="-1"`을 붙인 뒤에도 audit-skip-link는 판정 보류로 남았습니다.

### 코드에서 확인한 사실

- `class="req"`인 ‘필수’ 글자가 입력란 레이블 네 곳에 있습니다.
- 오류 문구 앞 기호는 `content: "! "`를 먼저 선언하고 `content: "! " / ""`로 덮어씁니다. 대체 텍스트 문법을 모르는 브라우저는 앞 선언을 씁니다.
- `main:focus`의 윤곽선은 지웠습니다.
- 오류를 고쳐도 오류 요약 목록은 다음 제출 때까지 바뀌지 않습니다. 개발 에이전트도 이 점을 개선 제안으로 남겼습니다.

## 미검증 항목

- 스크린 리더 발화: 오류 요약의 제목과 항목, ‘필수’가 들어간 레이블, ‘!’ 기호를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- ‘본문 바로가기’를 눌렀을 때 초점이 `main`으로 가는지, 약관 체크 상자의 Space 키 선택과 ‘전체 동의’ 연동은 기록하지 않았습니다.
- on 화면의 가입 완료 흐름과 완료 뒤 초점 위치는 브라우저에서 따로 기록하지 않았습니다.
- 320px에서 레이블이 줄바꿈될 때 ‘필수’ 글자와 빨간 점이 겹치는지, 고대비 모드에서 원형 아이콘과 오류 테두리가 보이는지 확인하지 않았습니다.

### 개발 중 읽지 못한 자료

- 5.3.2, 5.4.4, 6.1.3, 6.4.1, 7.1.1, 8.1.1의 본문을 읽지 못했습니다. 그래서 `lang`, 중복 `id`, 터치 영역 크기는 코드로만 확인했습니다.
- NIA 제작기법의 적용 사례와 개선 필요 사례는 읽지 않았습니다.
- 일부 `curl`과 `python` 명령이 셸 명령 제한으로 실행되지 않았습니다. 본문을 읽지 못한 이유입니다.
