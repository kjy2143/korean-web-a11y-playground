# 자주 묻는 질문 · 기본 개발 (off) 실행 결과

푸른숲도서관의 자주 묻는 질문 다섯 개를 눌러 답을 펼치고, 답 끝의 ‘바로가기’ 링크로 안내 페이지에 가는 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-faq-accordion-on)에 있습니다.

확장 검사에서 위반 규칙은 없었고 `color-contrast` 판정 보류가 1개 남았습니다. 시안 색 그대로인 질문 앞 ‘Q’ 글자(`#9ccc9c`)의 측정 대비가 1.82:1이었습니다. 질문은 마우스 클릭으로 펼치고 접을 수 있었고, 키보드로는 Enter로 펼치고 Space로 접었습니다. 두 질문을 동시에 펼칠 수 있었습니다.

## 사용 방법

- 질문 줄을 누르면 답이 펼쳐지고, 다시 누르면 접힙니다. 키보드로는 Tab으로 질문에 초점을 두고 Enter나 Space를 누릅니다.
- 여러 질문을 동시에 펼칠 수 있습니다.
- 답 끝의 ‘바로가기’ 링크는 요청서대로 주소가 `#`이고, 눌러도 페이지가 이동하지 않습니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 자주 묻는 질문’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 질문을 눌러 답을 펼치고 안내 페이지로 이동합니다.
>
> 질문 다섯 개(회원증 발급, 대출 권수와 기간, 연체, 열람실 예약, 분실 도서)와 답을 보여 줍니다. 질문을 누르면 답이 펼쳐지고 다시 누르면 접힙니다. 여러 개를 동시에 펼쳐도 됩니다. 답마다 관련 안내 페이지 링크가 하나씩 있습니다(주소는 `#`).
>
> 디자인 시안: 질문 줄 전체가 누르는 영역이고 오른쪽 끝에 +/− 아이콘이 있습니다(펼치면 −). 답 안의 링크는 문장 끝의 ‘바로가기’입니다. 질문 앞 ‘Q’는 연한 초록 `#9ccc9c` 굵은 글씨, 답 앞 ‘A’는 `#cccccc`입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값만 읽었습니다. 자료 목록과 검사항목 레코드는 한 번도 받지 않았고, 실행 기록에서 자료 조회가 0회임을 확인했습니다.
- 지시: 화면 요청서만 주었습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 개발 에이전트는 화면을 브라우저로 열어 확인하지 않았다고 보고했습니다.
- 셸 명령: 허용한 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 1건으로, `cat`의 출력을 파일로 보내 `index.html`을 쓰려던 명령이었습니다. 파일 세 개는 모두 만들어졌습니다.
- 수정 요청: 이 화면에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 첫 실행에서는 on 화면을 만들지 않았습니다. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. 이때 off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 개발 에이전트 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 펼침 버튼 | 질문은 `h2` 안의 `button`입니다. `aria-expanded`로 펼침 상태를 알리고 `aria-controls`로 답 영역을 가리킵니다. | [aria-expanded](https://www.w3.org/TR/wai-aria-1.2/#aria-expanded), [aria-controls](https://www.w3.org/TR/wai-aria-1.2/#aria-controls) |
| 답 영역 | 접힌 답은 `hidden` 속성으로 숨깁니다. 답 영역에는 `role="region"`과, 질문 버튼을 가리키는 `aria-labelledby`가 있습니다. | [HTML hidden 속성](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute), [region 역할](https://www.w3.org/TR/wai-aria-1.2/#region), [aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby) |
| ‘Q’, ‘A’ 글자 | 시안 색(`#9ccc9c`, `#ccc`)을 그대로 쓰고 두 글자에 `aria-hidden="true"`를 달았습니다. | [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| +/− 아이콘 | CSS 가상 요소로 그리고 `aria-hidden="true"`를 달았습니다. `aria-expanded="true"`이면 세로 막대를 숨겨 −로 보입니다. | [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 링크 이름 | 보이는 ‘바로가기’ 뒤에 화면에 보이지 않는 글자(예: ‘: 회원증 발급 안내’)를 붙였습니다. | [HTML a 요소](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-a-element) |
| 초점 표시와 언어 | 질문 버튼과 답 안 링크의 `:focus-visible`에 3px `#1a56c4` 윤곽선을 그립니다. `<html lang="ko">`입니다. | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo), [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |
| 강제 색상 모드 | `forced-colors: active`일 때 +/− 아이콘의 색을 `currentColor`로 바꿉니다. | [forced-colors](https://www.w3.org/TR/mediaqueries-5/#forced-colors) |

### 요청서와 다르게 판단한 부분

- ‘Q’, ‘A’ 색: 시안대로 `#9ccc9c`와 `#ccc`를 썼습니다. 개발 에이전트는 두 색이 흰 배경에서 글자 대비 기준에 못 미친다고 보고했습니다. 그래서 두 글자를 `aria-hidden`으로 숨겨 장식으로 처리했고, 질문과 답 본문에는 어두운 글자색을 썼다고 적었습니다.
- 링크 이름: ‘바로가기’가 다섯 번 반복되므로 보이지 않는 안내 문구를 덧붙여 구분했습니다. 보이는 글자는 시안대로 ‘바로가기’입니다.
- 링크 동작: 주소가 `#`인 링크를 눌러도 페이지 맨 위로 이동하지 않게 막았습니다.
- 답 내용: 요청서에 문구가 없어 권수와 기간 같은 수치를 포함해 임의로 썼습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 0 / 1 / 19 |
| 확장 검사: 첫 질문 펼침 | 0 / 1 / 24 |
| 위반·판정 보류 규칙 | 위반은 없습니다. `color-contrast` 판정 보류가 초기 상태에 5개 요소, 첫 질문을 펼친 상태에 6개 요소였습니다. 초기 상태 5개 가운데 기록에 남은 세 개는 첫째~셋째 질문 앞 ‘Q’ 글자이고 측정 대비는 모두 1.82:1입니다. |
| 키보드 조작 | Tab으로 질문 버튼 다섯 개를 차례로 이동했습니다. Enter로 펼치고 이어서 Space로 접었습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html` 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- 첫 질문을 클릭하면 `aria-expanded`가 `true`가 되고 답 영역 하나가 보였습니다. 다시 클릭하면 `false`가 됐습니다.
- 첫 질문에 초점을 두고 Enter를 누르면 `aria-expanded`가 `true`가 됐고, 이어서 Space를 누르면 `false`가 됐습니다. 초점은 그 질문 버튼에 남아 있었습니다.
- 첫 번째와 두 번째 질문을 차례로 클릭하면 두 질문이 함께 펼쳐진 상태(`true`, `true`, `false`, `false`, `false`)가 됐습니다.
- 모두 접힌 상태의 Tab 순서는 질문 버튼 다섯 개였고, 그다음은 `body`였습니다. 초점을 받은 요소마다 초점 표시가 있었습니다.
- 검사 도구는 ‘Q’ 글자를 판정 보류로 둔 이유를 글자가 너무 짧아 실제 텍스트인지 확인할 수 없기 때문이라고 기록했습니다.
- 첫 질문을 펼친 상태에서 ‘바로가기’ 링크의 크기는 55×18px이었습니다. ‘Q’ 글자의 계산된 색은 `rgb(156, 204, 156)`이었습니다.

### 코드에서 확인한 사실

- 질문 다섯 개는 `ul` 안의 `li`이고, 각 `li`에 질문 `h2`와 답 영역 `div`가 있습니다.
- 스크립트는 누른 질문의 `aria-expanded`와 그 답 영역의 `hidden`만 바꿉니다. 다른 질문은 건드리지 않습니다.
- 답 앞 ‘A’ 글자는 `#ccc`이고, 답 영역의 배경은 `#f7f7f7`입니다. 답을 펼치면 ‘A’ 글자 하나가 더 화면에 보입니다.
- ‘바로가기’ 링크는 문장 안의 인라인 요소이고 색은 `#0b4fb3`, 굵은 글씨입니다. 밑줄은 브라우저 기본값을 따릅니다.
- 질문 버튼은 줄 전체 폭(`width:100%`)이고 위아래 안쪽 여백이 16px입니다.

## 미검증 항목

- ‘바로가기’ 링크를 눌렀을 때 페이지가 이동하지 않는지는 코드로만 확인했습니다.
- 스크린 리더 발화: 질문을 펼침·접힘 상태와 함께 읽는지, 링크를 ‘바로가기: 회원증 발급 안내’처럼 읽는지, ‘Q’와 ‘A’를 읽지 않는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 답을 펼친 상태에서 Tab이 ‘바로가기’ 링크로 이동하는지, 그때 초점 표시가 보이는지 기록하지 않았습니다.
- 첫 질문을 펼친 상태에서 판정 보류에 더해진 여섯 번째 요소와 그 측정 대비는 기록하지 않았습니다.
- 폭 320px에서는 가로 스크롤만 확인했습니다. 글이 잘리지 않는지, 화면 200% 확대와 강제 색상 모드에서 어떻게 보이는지는 확인하지 않았습니다.
