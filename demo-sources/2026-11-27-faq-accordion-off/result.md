# 자주 묻는 질문 · 기본 개발 (off) 실행 결과

푸른숲도서관의 자주 묻는 질문 다섯 개를 펼치고 접는 화면입니다. 답마다 관련 안내 페이지로 가는 ‘바로가기’ 링크가 있습니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-faq-accordion-on)에 있습니다.

확장 검사에서 위반은 없었지만 명도 대비 규칙(color-contrast)이 판정 보류로 남았습니다. 판정 보류 요소는 초기 상태에서 5개, 첫 질문을 펼친 상태에서 6개였습니다. 질문 앞 ‘Q’와 답 앞 ‘A’는 요청서의 연한 색(`#9ccc9c`, `#cccccc`)을 그대로 썼습니다.

## 사용 방법

- 질문 줄을 누르면 답이 펼쳐지고, 다시 누르면 접힙니다. 키보드로는 Tab으로 질문에 초점을 두고 Enter나 Space를 누릅니다.
- 여러 질문을 동시에 펼칠 수 있습니다.
- 답 끝의 ‘바로가기’ 링크는 요청서대로 주소가 `#`입니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 자주 묻는 질문’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 질문을 눌러 답을 펼치고 안내 페이지로 이동합니다.
>
> 질문 다섯 개(회원증 발급, 대출 권수와 기간, 연체, 열람실 예약, 분실 도서)와 답을 보여 줍니다. 질문을 누르면 답이 펼쳐지고 다시 누르면 접힙니다. 여러 개를 동시에 펼쳐도 됩니다. 답마다 관련 안내 페이지 링크가 하나씩 있습니다(주소는 `#`).
>
> 디자인 시안: 질문 줄 전체가 누르는 영역이고 오른쪽 끝에 +/− 아이콘이 있습니다(펼치면 −). 답 안의 링크는 문장 끝의 ‘바로가기’입니다. 질문 앞 ‘Q’는 연한 초록 `#9ccc9c` 굵은 글씨, 답 앞 ‘A’는 `#cccccc`입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다.
- 지시: 요청서 전문을 주고, 질문하지 말고 구현을 마친 뒤 만든 파일과 판단이 필요했던 점을 보고하게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. 개발 에이전트는 화면을 브라우저로 열어 보지 못했고 코드로만 점검했다고 보고했습니다.
- 수정 요청: 이 화면에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 질문 버튼 | 질문마다 `h2` 안에 `button`을 두고, `aria-expanded`와 `aria-controls`로 답 영역을 가리킵니다. 누를 때마다 `aria-expanded`와 답의 `hidden`을 함께 바꿉니다. | [aria-expanded](https://www.w3.org/TR/wai-aria-1.2/#aria-expanded), [aria-controls](https://www.w3.org/TR/wai-aria-1.2/#aria-controls), [HTML hidden 속성](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute) |
| 답 영역 | 답은 `role="region"`이고 `aria-labelledby`로 질문 버튼을 이름으로 씁니다. | [region 역할](https://www.w3.org/TR/wai-aria-1.2/#region), [aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby) |
| 장식 글자와 아이콘 | ‘Q’, ‘A’ 글자와 +/− 아이콘에 `aria-hidden="true"`를 달았습니다. +/− 아이콘은 CSS로 그립니다. | [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 링크 목적 | 화면에는 ‘바로가기’만 보이고, 뒤에 숨김 텍스트로 ‘: 회원증 발급 안내’처럼 대상을 덧붙였습니다. | 해당 없음 |
| 고대비 모드 | `forced-colors: active`에서 +/− 아이콘 색을 `CanvasText`로 바꿉니다. | [forced-colors](https://www.w3.org/TR/mediaqueries-5/#forced-colors) |
| 초점 표시와 언어 | 질문 버튼과 답 링크의 `:focus-visible`에 3px 윤곽선을 그립니다. `<html lang="ko">`입니다. | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo), [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- ‘Q’, ‘A’의 색은 시안대로 칠하되, 장식 글자로 보고 `aria-hidden`을 달았습니다. 개발 에이전트는 두 색이 흰 배경에서 대비가 낮다고 보고했습니다.
- 요청서에 문구가 없어 답과 ‘바로가기’ 앞 문장을 직접 썼습니다. 대출 5권·14일, 좌석 예약 30분 같은 수치는 가상의 값입니다.
- 요청서에 없는 도서관 이름 머리글, `h1`, 안내 문장 한 줄을 더했습니다.

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 판정 보류 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 0 / 1 / 19 |
| 확장 검사: 첫 질문 펼침 | 0 / 1 / 24 |
| 위반·판정 보류 규칙 | 위반 없음. color-contrast 판정 보류(초기 5개 요소, 첫 질문 펼침 6개 요소) |
| 키보드 조작 | Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 초점 표시가 있었습니다. 질문에서 Enter를 누르면 `aria-expanded`가 `true`가 됐습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html` 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- 질문을 클릭하면 답이 펼쳐졌고, 다시 클릭하면 접혔습니다.
- 질문에 초점을 두고 Enter를 누르면 `aria-expanded`가 `true`로 바뀌었습니다.
- 확장 검사는 명도 대비를 위반으로 판정하지 않고 판정 보류로 남겼습니다. 판정 보류 요소는 첫 질문을 펼치자 5개에서 6개로 늘었습니다.

### 코드에서 확인한 사실

- 질문 앞 ‘Q’는 `#9ccc9c`, 답 앞 ‘A’는 `#ccc`이고, 두 글자 모두 `aria-hidden="true"`입니다.
- ‘바로가기’ 링크는 밑줄과 굵은 글씨를 쓰고, 크기를 따로 키우지 않았습니다.
- 질문마다 독립적으로 동작해 여러 질문을 동시에 펼칠 수 있습니다.

## 미검증 항목

- 스크린 리더 발화: 질문 버튼의 펼침 상태와 ‘바로가기: 회원증 발급 안내’ 같은 링크 이름을 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- Space 키로 펼치는 동작과 키보드로 다시 접는 동작은 기록하지 않았습니다.
- 고대비 모드에서 +/− 아이콘이 보이는지 확인하지 않았습니다.
