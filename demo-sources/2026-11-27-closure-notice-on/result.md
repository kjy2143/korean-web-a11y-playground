# 임시 휴관 안내 · 접근성 자료 적용 (on) 실행 결과

포스터 이미지로 게시한 ‘12월 임시 휴관 안내’ 공지 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 점검하고 고친 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-closure-notice-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선하게 했습니다.

확장 검사 결과는 off와 on이 같습니다(둘 다 0 / 0 / 12). on 개발 에이전트는 off 화면이 KWCAG를 이미 대부분 충족한다고 보고했고, `index.html`의 두 곳만 고쳤습니다. 작성일 앞에 ‘작성일’ 글자를 더했고, 포스터 `img`에 `width`와 `height` 속성을 넣었습니다. 색, 배경, 링크 크기를 정하는 `style.css`는 off와 같습니다.

## 사용 방법

- 화면을 열어 공지 제목, 작성일, 포스터를 읽습니다.
- 포스터 아래 ‘목록으로’ 링크는 요청서대로 주소가 `#`입니다.
- off 화면과 나란히 열어 작성일 표시를 비교합니다. on은 날짜 앞에 ‘작성일’ 글자가 있습니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 임시 휴관 안내’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 임시 휴관 안내 포스터를 게시합니다.
>
> 공지 상세 화면입니다. 제목 ‘12월 임시 휴관 안내’, 작성일 2026.11.27, 본문 포스터 이미지 한 장(`closure-notice.png`)과 아래 ‘목록으로’ 링크(주소 `#`)가 있습니다. 포스터 문구는 ‘푸른숲도서관 / 임시 휴관 / 12월 7일 월요일 / 전기 설비 점검’입니다. 제목 왼쪽에 장식 아이콘 이미지(`decoration.png`)를 32px로 둡니다.
>
> 디자인 시안: 공지 내용은 포스터 이미지로만 게시하고 같은 내용의 텍스트 본문은 두지 않습니다. 작성일은 `#aaaaaa`입니다.

개발 에이전트는 KWCAG 요구사항과 충돌해 조정한 시안이 없다고 보고했습니다. off 화면에서 바꾼 부분은 아래 두 곳입니다.

| off 화면 | on 화면 | 보고서에 적은 이유 |
| --- | --- | --- |
| 작성일에 날짜 `2026.11.27`만 있음 | 날짜 앞에 ‘작성일’ 글자를 더했습니다. | 날짜만 읽히면 무슨 날짜인지 알 수 없습니다. 읽은 자료에 직접 근거가 없어 자료 밖 근거(정보에 맥락 제공)로 분류했습니다. |
| 포스터 `img`에 크기 속성 없음 | `width="720" height="492"`를 넣었습니다. | 접근성과 무관한 기능 결함으로 구분했습니다. 속성이 없으면 이미지가 로드되면서 아래 내용이 밀린다는 이유입니다. |

시안대로 둔 부분과 보고서의 판단은 다음과 같습니다.

- 텍스트 본문 없이 포스터만 게시하는 시안은 그대로 두었습니다. 보고서는 포스터 문구가 짧아 `alt`에 같은 내용을 넣으면 5.1.1을 충족한다고 판단했습니다. 문구가 길어지면 숨김 텍스트 같은 별도 수단이 필요하다고 덧붙였습니다.
- 작성일 색 `#aaaaaa`는 그대로 두었습니다. 보고서는 배경이 `#1a2e22`라서 대비가 약 6.2:1이라고 적었습니다. 배경을 흰색 계열로 바꾸면 약 2.3:1이 되어 5.4.3에 미달한다고도 적었습니다.
- 빈 `alt`의 장식 아이콘(32px)과 ‘목록으로’ 링크(주소 `#`)는 요청대로 유지했습니다.
- 보고서는 같은 문구를 본문 텍스트로도 두면 텍스트 확대와 검색에 유리하다고 제안했습니다. 시안과 달라 적용하지 않았습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치게 했습니다.
- 자료 조회: 설정 확인, 절차 문서, 자료 목록, 레코드 순서로 읽었습니다. 자료 조회 명령은 17회였고 모두 주소 하나에 명령 하나인 같은 형태였습니다. 조회에 실패한 주소는 없었습니다. 화면 종류와 관계없이 고르는 12개 항목(5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1)에 5.1.1과 6.4.3을 더해 KWCAG 레코드 14개를 받았습니다. NIA 사례 레코드는 1.1.1의 적용 사례와 개선 필요 사례 2개를 받았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 이 세션에서는 셸 호출 2건이 거부됐습니다. 둘 다 명도 대비를 계산하는 Python 스크립트를 만들거나 실행하는 명령이었습니다. 개발 에이전트는 대비를 손으로 계산했다고 보고했습니다.
- 수정 요청: 이 화면에는 결함 보고를 보내지 않았습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행: 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후): 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(2026-11-27 밤): 개발 절차를 ‘설정 확인’ 문서와 ‘절차’ 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본입니다. 화면은 처음부터 다시 만들었습니다.

### NIA 제작기법 권장 사항

- 보고서는 5.1.1을 권장 사항으로도 분류했습니다. 이미지 항목인 5.1.1에 대해서는 NIA 1.1.1의 [적용 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-1.1.1-s4.json)와 [개선 필요 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-1.1.1-s5.json)를 읽었습니다. 이미지 안의 짧은 텍스트는 `alt`에 같은 내용을 쓰고 장식 이미지는 `alt=""`로 둔다는 내용을 반영했다고 적었습니다.

### 자료 밖 근거

- 작성일 이름표: 날짜 앞의 ‘작성일’ 글자입니다. 보고서는 읽은 자료에 직접 근거가 없다고 밝혔고, 근거로 든 표준은 없습니다.
- 이미지 크기 속성: 포스터 `img`의 `width`와 `height`입니다. 보고서는 HTML 표준을 따랐다고 적었습니다. [HTML 크기 속성](https://html.spec.whatwg.org/multipage/embedded-content-other.html#dimension-attributes)

### 브라우저에서 관찰한 결과

- 두 화면 모두 확장 검사에서 위반과 판정 보류로 나온 규칙이 없었습니다. 통과 규칙 수도 12개로 같았습니다.
- on의 작성일 문단에 보이는 글자는 ‘작성일 2026.11.27’이었습니다. off는 ‘2026.11.27’이었습니다.
- 두 화면 모두 포스터와 장식 아이콘 이미지가 불러와졌습니다. 포스터의 `alt`는 ‘푸른숲도서관 임시 휴관. 12월 7일 월요일. 전기 설비 점검.’이었고, 장식 아이콘의 `alt`는 빈 값이었습니다.
- 두 화면 모두 공지 내용을 담은 텍스트 본문이 없었습니다.
- 두 화면 모두 Tab을 누르면 ‘목록으로’ 링크가 초점을 받았고, 그다음은 `body`였습니다. 초점 표시가 없는 정지점은 없었습니다.
- ‘목록으로’ 링크의 크기는 두 화면 모두 97×46px이었습니다.
- 폭 320px에서 가로 넘침은 두 화면 모두 0px이었습니다.
- off의 초기 상태 콘솔에 404 응답이 1건 기록됐습니다. 응답 상태가 400 이상인 데모 폴더의 자원 요청은 없었습니다. off는 브라우저를 새로 띄운 뒤 처음 연 화면이었습니다. 브라우저의 파비콘 요청으로 추정하며 따로 확인하지 않았습니다. on의 콘솔 기록은 0건이었습니다.

### 코드에서 확인한 사실

- off와 on의 차이는 `index.html`의 두 줄입니다. `style.css`와 이미지 파일은 같습니다.
- on의 작성일은 `<p class="date">작성일 <time datetime="2026-11-27">2026.11.27</time></p>`입니다.
- on의 포스터는 `<img src="closure-notice.png" width="720" height="492" alt="…">`입니다. 포스터 PNG 파일의 크기는 720×492px로 속성 값과 같습니다.
- 작성일 색 `#aaaaaa`와 배경 `#1a2e22`는 두 화면이 같습니다. 이 두 색으로 WCAG 상대 휘도 공식을 계산하면 대비는 6.20:1입니다. on 보고서의 약 6.2:1과 같고, off 보고서의 약 6.6:1과 다릅니다.
- ‘목록으로’ 링크는 두 화면 모두 `display:inline-block; min-height:44px; padding:10px 20px`입니다. 초점 윤곽은 `outline:3px solid #ffd54a`입니다.

## 미검증 항목

on 보고서가 ‘브라우저에서 확인할 동작’으로 남긴 항목 가운데 아래는 브라우저 기록이 없습니다.

- ‘목록으로’ 링크의 초점 윤곽이 노란색으로 보이는지는 확인하지 않았습니다. 기록은 초점 표시가 있는지뿐입니다.
- ‘목록으로’ 링크를 눌렀을 때 화면 맨 위로 이동하는지 확인하지 않았습니다.
- 폭 320px에서 제목이 줄바꿈되는 모양과 포스터가 잘림 없이 줄어드는지는 확인하지 않았습니다. 기록은 가로 넘침 값뿐입니다.
- 스크린 리더 발화: ‘작성일 2026.11.27’, 포스터 대체 텍스트, ‘목록으로’ 링크 순으로 읽는지와 장식 아이콘을 건너뛰는지 확인하지 않았습니다.
- 이미지 크기 속성을 넣은 뒤 이미지가 로드되는 동안 아래 내용이 밀리지 않는지 확인하지 않았습니다.

그 밖의 미검증 항목입니다.

- 작성일의 측정 대비 값은 기록에 없습니다. 확장 검사 기록에는 위반과 판정 보류 요소의 대비만 남습니다.
- 포스터 이미지 안 글자의 명도 대비는 재지 않았습니다. 보고서도 수치로 측정하지 못했고 크림색 배경에 짙은 녹색 글자라는 시각적 판단만 했다고 적었습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 화면 확대나 글자 크기 키우기, 고대비 모드는 확인하지 않았습니다. 포스터 글자는 이미지라 글자 크기 설정을 따르지 않습니다.

### 개발 중 읽지 못한 자료

- 보고서는 요청한 검사항목 레코드 14개와 이미지 사례 2건을 모두 읽었고, 읽지 못한 주소가 없다고 적었습니다.
- 검사항목 14개의 레코드가 더 읽을 자료로 연결한 나머지 레코드(목적, 배경 및 필요성, 용어, 6.4.3 등의 사례)는 읽지 않았습니다. 사례는 이미지 항목(5.1.1)의 것만 읽었습니다.
- 링크 항목 6.4.1과 6.4.3의 사례는 화면의 링크가 하나뿐이라는 이유로 읽지 않았습니다. 6.4.3은 본문과 기본 규칙만 읽고 적용했습니다.
