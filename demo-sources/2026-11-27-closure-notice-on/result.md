# 임시 휴관 안내 · 접근성 자료 적용 (on) 실행 결과

포스터 이미지로 게시한 ‘12월 임시 휴관 안내’ 공지 화면을 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-closure-notice-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사에서 off의 명도 대비 위반(작성일, 2.32:1)이 사라졌습니다. 포스터만 게시하는 시안과 포스터의 대체 텍스트는 off와 같습니다. on은 작성일 앞에 ‘작성일’ 글자를 더하고 ‘목록으로’ 링크의 높이를 키웠습니다.

## 사용 방법

- 화면을 열어 공지 제목, 작성일, 포스터를 읽습니다.
- 포스터 아래 ‘목록으로’ 링크는 요청서대로 주소가 `#`입니다.
- off 화면과 나란히 열어 작성일 표시와 ‘목록으로’ 링크 크기를 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 임시 휴관 안내’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 임시 휴관 안내 포스터를 게시합니다.
>
> 공지 상세 화면입니다. 제목 ‘12월 임시 휴관 안내’, 작성일 2026.11.27, 본문 포스터 이미지 한 장(`closure-notice.png`)과 아래 ‘목록으로’ 링크(주소 `#`)가 있습니다. 포스터 문구는 ‘푸른숲도서관 / 임시 휴관 / 12월 7일 월요일 / 전기 설비 점검’입니다. 제목 왼쪽에 장식 아이콘 이미지(`decoration.png`)를 32px로 둡니다.
>
> 디자인 시안: 공지 내용은 포스터 이미지로만 게시하고 같은 내용의 텍스트 본문은 두지 않습니다. 작성일은 `#aaaaaa`입니다.

요청서와 다르게 구현한 부분은 아래와 같습니다.

| 요청서 내용 | 조정한 내용 | 이유 |
| --- | --- | --- |
| 작성일 `#aaaaaa` | `#595959`로 바꿨습니다. | off의 작성일은 흰 배경 대비가 2.32:1(확장 측정)이라 4.5:1에 못 미칩니다(5.4.3). |
| ‘목록으로’ 링크 | 링크를 높이 44px 이상(`min-height:44px`)으로 키우고, 위쪽 여백을 16px에서 8px로 줄였습니다. | 조작 영역을 키웠습니다(6.1.3). |
| 작성일 2026.11.27 | 날짜 앞에 ‘작성일’ 글자를 더했습니다. | 스크린 리더가 날짜만 읽으면 무슨 날짜인지 알 수 없다고 판단했습니다. 개발 에이전트는 검사항목 근거가 없는 판단이라고 밝혔습니다. |

텍스트 본문 없이 포스터 이미지만 게시하는 시안은 그대로 두었습니다. 개발 에이전트는 포스터의 `alt`가 포스터 문구 네 줄을 모두 담아 5.1.1을 충족한다고 판단했고, 이미지 파일을 열어 글자와 `alt`가 일치하는지 확인했다고 보고했습니다. 같은 내용을 텍스트로도 두는 방안은 시안과 달라 제안으로만 남겼습니다. 접근성과 무관한 기능 결함은 찾지 못했다고 보고했습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치고, 접근성과 무관한 기능 결함을 고쳤으면 따로 구분해 적게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 위반 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 11 | 0 / 0 / 12 |
| 주요 위반 규칙과 측정 대비 | color-contrast 1개 요소(작성일 `time`, 2.32:1) | 없음 |
| 키보드 조작 | Tab 이동과 초점 표시 있음 | Tab 이동과 초점 표시 있음 |
| 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | 0건 | 0건 |
| 이미지 대체 텍스트 | 포스터 `alt` 있음, 장식 아이콘 `alt=""` | off와 같음 |

### 브라우저에서 관찰한 결과

- on에서는 color-contrast 위반이 없어 통과 규칙이 11개에서 12개로 늘었습니다.
- 두 화면 모두 포스터의 `alt`가 ‘푸른숲도서관 임시 휴관. 12월 7일 월요일. 전기 설비 점검’이었고, 장식 아이콘의 `alt`는 빈 값이었습니다.
- 두 화면 모두 공지 내용을 담은 텍스트 본문이 없었습니다.
- 1280px에서 Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- on의 작성일은 `작성일 <time datetime="2026-11-27">2026.11.27</time>`이고 색은 `#595959`입니다.
- ‘목록으로’ 링크는 `display:inline-block; min-height:44px; padding:10px 4px; line-height:24px`입니다.

## 미검증 항목

- 스크린 리더 발화: ‘작성일 2026.11.27’과 포스터 대체 텍스트를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- ‘목록으로’ 링크의 실제 높이는 브라우저에서 재지 않았습니다.
- 화면 확대나 글자 크기 키우기, 고대비 모드는 확인하지 않았습니다. 포스터 글자는 이미지라 글자 크기 설정을 따르지 않습니다.

### 개발 중 읽지 못한 자료

- 개발 에이전트는 자료 목록과 14개 항목 레코드를 별도 하위 에이전트가 읽고 요약한 내용으로 확인했습니다. 레코드 본문 전문을 직접 읽지 않았고, 짧은 발췌나 의역을 근거로 판단했다고 밝혔습니다.
- NIA 적용 사례와 개선 필요 사례는 열어 보지 않았습니다. 이 화면에 모달, 표, 입력란이 없다는 이유였습니다.
- 자료 파일을 직접 내려받는 명령과 명도 대비 계산 스크립트는 셸 명령 제한으로 실행하지 못했습니다. 조회에 실패한 주소는 없었습니다.
