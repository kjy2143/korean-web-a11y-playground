# 공지 배너 · 기본 개발 (off) 실행 결과

도서관 공지 세 건이 6초마다 바뀌는 배너 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다.

같은 요청서로 접근성 자료를 적용해 개선한 화면은 [공지 배너 · 접근성 자료 적용 (on)](/?demo=2026-11-27-notice-carousel-on)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열면 배너가 ‘겨울 독서 교실 모집’ 공지를 보여 줍니다. 공지는 6초마다 바뀌고, 세 번째 공지 다음에는 첫 공지로 돌아갑니다.
2. 배너 좌우의 화살표 버튼으로 이전 공지와 다음 공지를 엽니다. 배너 아래 점 세 개를 누르면 해당 공지로 이동합니다.
3. 점 옆의 ‘자동 전환 정지’를 누르면 자동 전환이 멈춥니다. 버튼 글자는 ‘자동 전환 시작’으로 바뀌고, 다시 누르면 전환이 재개됩니다.
4. 화살표와 공지가 있는 배너 영역에 마우스를 올리거나 키보드 초점을 두면 자동 전환이 멈춥니다. 운영체제의 동작 줄이기 설정을 쓰면 정지 상태로 시작합니다.
5. Tab 키를 누르면 ‘본문 바로가기’, 이전 공지, ‘자세히’, 다음 공지, 점 세 개, ‘자동 전환 정지’ 순서로 초점이 이동합니다.

## 요청서

‘화면 요청서: 공지 배너’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 도서관 소식이 6초마다 바뀌는 배너입니다.
>
> 공지 세 개(‘겨울 독서 교실 모집’, ‘12월 휴관일 안내’, ‘전자책 신규 도서 입고’)를 배너로 보여 줍니다. 공지마다 제목, 한 줄 설명, ‘자세히’ 링크(주소 `#`)가 있습니다. 6초마다 다음 공지로 자동 전환하고, 마지막 다음에는 처음으로 돌아갑니다. 배너 아래에 짧은 페이지 본문을 둡니다.
>
> 디자인 시안: 배너 아래 가운데에 점 세 개를 두고 현재 공지의 점을 진하게 표시합니다. 점을 누르면 그 공지로 이동합니다. 배너 좌우 끝에 화살표 아이콘 버튼을 둡니다. 배너 배경은 공지마다 다른 파스텔색(`#bfe3d0`, `#f6d6c8`, `#cfd8f5`)이고 글씨는 흰색입니다.

## 개발 조건

- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 끄고 요청서대로 만들었습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 개발 중 확인: 개발 에이전트는 브라우저로 화면을 열지 않고 코드만 작성했다고 보고했습니다.
- 수정 요청: 화면에 기능 결함이 없어 수정 요청을 보내지 않았습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 아래 목록은 개발 에이전트가 일반 지식으로 넣은 처리를 코드에서 확인한 것입니다.

### 자료 밖 근거(HTML, WAI-ARIA)

- 배너 `section`에 `aria-roledescription="캐러셀"`과 `aria-label="도서관 소식"`을 붙였습니다. 공지마다 `article`에 `aria-roledescription="슬라이드"`와 ‘1 / 3’ 형식의 이름을 붙였습니다. [WAI-ARIA 1.2 aria-roledescription](https://www.w3.org/TR/wai-aria-1.2/#aria-roledescription)
- 공지 영역의 `aria-live`는 자동 전환 중에 `off`입니다. 정지 버튼, 마우스 올림, 초점 진입으로 전환이 멈추면 `polite`로 바뀝니다. [WAI-ARIA 1.2 aria-live](https://www.w3.org/TR/wai-aria-1.2/#aria-live)
- 현재 공지가 아닌 공지는 `hidden` 속성으로 숨깁니다. [HTML hidden 속성](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute)
- 화살표 버튼의 SVG는 `aria-hidden="true"`로 숨겼습니다. 버튼 이름은 `aria-label`의 ‘이전 공지’, ‘다음 공지’입니다. [WAI-ARIA 1.2 aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden), [WAI-ARIA 1.2 aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label)
- 점 버튼의 이름은 ‘1번 공지: 겨울 독서 교실 모집’ 형식입니다. 현재 공지의 점에는 `aria-current="true"`가 붙습니다. [WAI-ARIA 1.2 aria-current](https://www.w3.org/TR/wai-aria-1.2/#aria-current)
- ‘자세히’ 링크 뒤에 화면에서 숨긴 텍스트로 공지 제목을 붙였습니다. 링크 이름은 ‘자세히 - 겨울 독서 교실 모집’ 형식이 됩니다.
- 정지 버튼은 `aria-pressed` 값과 버튼 글자(‘자동 전환 정지’, ‘자동 전환 시작’)를 함께 바꿉니다. [WAI-ARIA 1.2 aria-pressed](https://www.w3.org/TR/wai-aria-1.2/#aria-pressed)
- 동작 줄이기 설정(`prefers-reduced-motion: reduce`)에서는 자동 전환을 멈춘 상태로 시작합니다. [Media Queries Level 5의 prefers-reduced-motion](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion)
- 문서 맨 앞에 ‘본문 바로가기’ 링크를 두었습니다. 평소에는 화면 밖에 있고 초점을 받으면 보입니다.
- 초점을 받은 요소에 `:focus-visible` 3px 윤곽선을 표시합니다. [Selectors Level 4의 :focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo)

### 요청서와 다르게 판단한 부분

- 파스텔 배경과 흰 글씨는 유지했습니다. 개발 에이전트는 흰 글씨의 대비가 부족하다고 판단해 글씨 뒤에 어두운 반투명 판(`rgba(20, 32, 26, 0.78)`)을 깔았습니다.
- 요청서에 없는 ‘자동 전환 정지’ 버튼을 점 옆에 추가했습니다.
- 점은 12px로 그리고, 누를 수 있는 영역은 32px로 잡았습니다. 현재 점은 시안대로 진한 채움 색으로만 구분합니다.
- 요청서에 내용이 없는 본문 문장 두 개와 푸터를 직접 썼습니다.
- 폭 400px 이하에서는 여백과 글자 크기를 줄였습니다.

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

### 확장 검사

초기 상태에서 위반 규칙은 0개, 판정 보류 규칙은 1개, 통과 규칙은 21개였습니다. 판정 보류 규칙은 `audit-skip-link`입니다.

### 브라우저에서 관찰한 결과

- 6초 뒤 다음 공지로 바뀌었습니다.
- 마우스로 세 번째 점을 누르자 세 번째 공지가 나왔습니다. 이어서 이전 화살표를 누르자 두 번째 공지가 나왔습니다.
- ‘자동 전환 정지’를 누른 뒤 6.6초 동안 공지가 바뀌지 않았습니다.
- 공지 영역의 `aria-live` 값은 `polite`로 관찰됐습니다.
- 폭 1280px에서 Tab 순서대로 초점이 이동했습니다. 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 폭 320px에서 페이지 가로 스크롤이 없었습니다.
- 마크업 검사 오류는 0건이었습니다.
- 초기 상태에서 콘솔 오류(pageerror)는 0건이었습니다.

### 코드에서 확인한 사실

- 자동 전환을 멈추는 마우스 올림과 초점 감지는 배너 `section`에만 연결돼 있습니다. 점과 정지 버튼은 이 영역 밖에 있어, 점에 초점을 두어도 자동 전환이 멈추지 않습니다.
- `aria-live`가 `polite`인 때는 자동 전환이 멈춘 상태입니다. 자동 전환 중에는 `off`입니다.
- 배너의 공지 제목(`h2`)이 본문 제목(`h1`)보다 문서에서 앞에 나옵니다.

## 미검증 항목

- 스크린 리더 발화: 공지 전환 안내, 정지 버튼의 상태, ‘자세히’ 링크 이름을 어떻게 읽는지 확인하지 않았습니다.
- 마우스 올림과 키보드 초점 진입으로 자동 전환이 멈추는지는 브라우저에서 확인하지 않았습니다.
- 동작 줄이기 설정에서 정지 상태로 시작하는지 확인하지 않았습니다.
- 실제 터치 기기, Chrome 외 브라우저, 화면 확대 상태는 확인하지 않았습니다.
