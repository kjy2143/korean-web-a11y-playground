# 공지 배너 · 기본 개발 (off) 실행 결과

푸른숲도서관 공지 세 건이 6초마다 바뀌는 배너와 짧은 본문이 있는 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-notice-carousel-on)에 있습니다.

확장 검사에서 위반과 판정 보류가 없었습니다. 개발 에이전트는 자료를 조회하지 않고도 요청서에 없는 자동 전환 정지 버튼과 건너뛰기 링크를 넣었고, 파스텔 배경 위 흰 글씨 뒤에 어두운 반투명 상자를 깔았습니다. 정지 버튼을 누른 뒤 초점과 마우스를 배너 밖에 둔 상태에서도, 배너에 마우스를 올린 상태에서도 6.6초 동안 공지가 바뀌지 않았습니다. 동작 줄이기 설정을 켠 브라우저에서는 정지 상태로 시작했습니다. 문서 순서에서는 배너 안의 공지 제목(`h2`) 세 개가 본문의 `h1`보다 앞에 있었습니다.

## 사용 방법

- 페이지를 열면 배너가 첫 공지를 보여 줍니다. 공지는 6초마다 바뀌고, 세 번째 공지 다음에는 첫 공지로 돌아갑니다.
- 배너 좌우의 화살표 버튼과 배너 아래의 점 세 개로 공지를 고릅니다. 현재 공지의 점은 더 크고 속이 채워져 있습니다.
- 점 왼쪽의 정지 버튼을 누르면 자동 전환이 멈추고, 다시 누르면 시작합니다.
- 배너나 그 아래 조작부에 마우스를 올리거나 키보드 초점을 두면 그동안 자동 전환이 멈춥니다.
- 운영체제의 동작 줄이기 설정이 켜져 있으면 정지 상태로 시작합니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 공지 배너’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 도서관 소식이 6초마다 바뀌는 배너입니다.
>
> 공지 세 개(‘겨울 독서 교실 모집’, ‘12월 휴관일 안내’, ‘전자책 신규 도서 입고’)를 배너로 보여 줍니다. 공지마다 제목, 한 줄 설명, ‘자세히’ 링크(주소 `#`)가 있습니다. 6초마다 다음 공지로 자동 전환하고, 마지막 다음에는 처음으로 돌아갑니다. 배너 아래에 짧은 페이지 본문을 둡니다.
>
> 디자인 시안: 배너 아래 가운데에 점 세 개를 두고 현재 공지의 점을 진하게 표시합니다. 점을 누르면 그 공지로 이동합니다. 배너 좌우 끝에 화살표 아이콘 버튼을 둡니다. 배너 배경은 공지마다 다른 파스텔색(`#bfe3d0`, `#f6d6c8`, `#cfd8f5`)이고 글씨는 흰색입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값만 읽었습니다. 자료 목록과 검사항목 레코드는 한 번도 받지 않았고, 실행 기록에서 자료 조회가 0회임을 확인했습니다.
- 지시: 화면 요청서만 주었습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 개발 에이전트는 `script.js`의 문법 검사만 통과시켰고, 브라우저에서 폭 320px 배치와 6초 전환은 확인하지 못했다고 보고했습니다.
- 셸 명령: 허용한 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 1건으로, 폴더를 옮긴 뒤 파일을 쓰는 복합 명령이었습니다. 파일 세 개는 모두 만들어졌습니다.
- 수정 요청: 이 화면에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 첫 실행에서는 on 화면을 만들지 않았습니다. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. 이때 off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 개발 에이전트 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 건너뛰기 링크 | `body`의 첫 요소가 `#main`으로 가는 ‘본문 바로가기’ 링크입니다. 평소에는 화면 밖에 있고 초점을 받으면 왼쪽 위에 나타납니다. | [HTML a 요소](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-a-element) |
| 캐러셀 영역 | 배너 `section`에 `aria-roledescription="carousel"`과 `aria-label="도서관 공지"`가 있습니다. 공지마다 `article`에 `role="group"`, `aria-roledescription="공지"`, `aria-label="1 / 3"` 형식의 이름을 달았습니다. | [aria-roledescription](https://www.w3.org/TR/wai-aria-1.2/#aria-roledescription), [group 역할](https://www.w3.org/TR/wai-aria-1.2/#group) |
| 숨은 공지 | 화면에 없는 공지는 `hidden` 속성으로 숨깁니다. | [HTML hidden 속성](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute) |
| 전환 안내 | 공지 영역의 `aria-live`를 자동 전환 중에는 `off`, 멈춘 동안에는 `polite`로 바꿉니다. | [aria-live](https://www.w3.org/TR/wai-aria-1.2/#aria-live) |
| 정지 버튼 | 점 왼쪽에 자동 전환 정지·시작 버튼을 두었습니다. 누를 때마다 `aria-label`이 ‘자동 전환 정지’와 ‘자동 전환 시작’으로 바뀌고 아이콘도 바뀝니다. | [aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label) |
| 마우스 올림과 초점 | 배너와 조작부의 `mouseenter`, `focusin`에서 전환을 멈추고 `mouseleave`, `focusout`에서 다시 진행합니다. | [focusin 이벤트](https://www.w3.org/TR/uievents/#event-type-focusin) |
| 동작 줄이기 | `prefers-reduced-motion: reduce`이면 정지 상태로 시작합니다. | [prefers-reduced-motion](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion) |
| 현재 점 | 현재 공지의 점에 `aria-current="true"`를 답니다. 다른 점은 14px 테두리 원이고 현재 점은 18px의 채운 원입니다. | [aria-current](https://www.w3.org/TR/wai-aria-1.2/#aria-current) |
| 버튼 이름과 크기 | 화살표 버튼은 `aria-label`이 ‘이전 공지’, ‘다음 공지’이고 아이콘 SVG는 `aria-hidden="true"`입니다. 점 버튼의 이름은 ‘1번 공지: 겨울 독서 교실 모집’ 형식입니다. 화살표, 정지, 점 버튼은 44×44px이고, 폭 360px 이하에서 화살표만 36×36px입니다. | [aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 링크 이름 | 보이는 ‘자세히’ 뒤에 화면에 보이지 않는 공지 제목(예: ‘ - 겨울 독서 교실 모집’)을 붙였습니다. 링크의 최소 높이는 44px이고 밑줄이 있습니다. | [HTML a 요소](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-a-element) |
| 초점 표시와 언어 | `:focus-visible`에 3px `#0b4fd1` 윤곽선을 그립니다. 어두운 상자 안의 링크는 흰 윤곽선에 파란 그림자를 더합니다. `<html lang="ko">`입니다. | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo), [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- 흰 글씨 대비: 파스텔 배경색과 흰 글씨는 시안대로 두고, 글 뒤에 반투명한 어두운 상자(`rgba(20,30,25,.72)`)를 깔았습니다. 개발 에이전트는 파스텔 배경 위 흰 글씨의 대비가 1.5:1 안팎이라 읽기 어렵다고 보고했습니다. 파스텔색은 상자 바깥 테두리로 보입니다.
- 정지 버튼: 요청서에 없지만 자동 전환이 6초마다 계속되므로 정지·시작 버튼을 더했다고 보고했습니다.
- 점 표시: 시안은 현재 점을 진하게 표시합니다. 색에 더해 크기와 채움으로도 구분했습니다.
- 화살표 위치: 폭이 좁아도 화살표가 글 위에 겹치지 않게 화살표, 공지, 화살표를 좌우 세 열로 나눠 배치했습니다.
- 문구: 공지의 한 줄 설명과 본문은 요청서에 없어 임의로 썼습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다. KWCAG 검사 0.1.17은 건너뛰기 링크가 예상 Tab 순서의 첫 항목이고 연결 대상이 있으면 통과로 처리합니다(0.1.16은 판정 보류로 남겼습니다).

### 브라우저에서 관찰한 결과

- 처음에는 ‘겨울 독서 교실 모집’이 보였고 공지 영역의 `aria-live`는 `off`였습니다. 6.6초 뒤에는 ‘12월 휴관일 안내’가 보였습니다.
- 세 번째 점을 클릭하면 ‘전자책 신규 도서 입고’로 바뀌었고, 그때 `aria-live`는 `polite`였습니다. 이전 화살표를 클릭하면 ‘12월 휴관일 안내’로 돌아갔습니다.
- 정지 버튼을 누른 뒤 6.6초 동안 공지가 그대로였습니다. 버튼 이름은 ‘자동 전환 시작’으로 바뀌었고 `aria-live`는 `polite`였습니다. 버튼에 `aria-pressed`는 없었습니다. 이때는 초점이 정지 버튼에 남아 있었습니다. 코드에서는 조작부에 초점이 있으면 정지 여부와 관계없이 전환이 멈추므로, 따로 한 번 더 확인했습니다. 정지 버튼을 클릭한 뒤 초점을 해제하고 마우스를 배너와 조작부 밖에 둔 상태에서도 6.6초 동안 공지가 바뀌지 않았습니다.
- 동작 줄이기 설정(`prefers-reduced-motion: reduce`)을 켠 브라우저로 열면 버튼 이름이 처음부터 ‘자동 전환 시작’이었고 6.6초 동안 첫 공지가 그대로였습니다.
- 버튼에서 Enter를 눌러 다시 시작한 뒤 초점을 해제하고 마우스를 배너와 조작부 밖에 두자 7초 안에 다음 공지로 바뀌었습니다.
- 공지 제목 위에 마우스를 올린 6.6초 동안 공지가 바뀌지 않았습니다.
- Tab 순서는 ‘본문 바로가기’, ‘이전 공지’, ‘자세히 - 겨울 독서 교실 모집’, ‘다음 공지’, ‘자동 전환 정지’, 점 버튼 세 개였고, 그다음은 `body`였습니다. 초점을 받은 요소마다 초점 표시가 있었습니다.
- 확장 검사는 배너를 사용자 조작 없이 바뀌는지, 정지할 수 있는지 직접 확인할 항목으로 표시했습니다.

### 코드에서 확인한 사실

- 문서 순서는 건너뛰기 링크, 머리글, 배너(이전 화살표, 공지 세 개, 다음 화살표), 조작부(정지 버튼, 점 세 개), 본문입니다.
- `h1` ‘푸른숲도서관 소식’은 배너 뒤의 본문(`main`) 안에 있습니다. 머리글의 기관명은 `p`입니다.
- 마우스 올림과 초점으로 멈추는 영역은 배너와 조작부 두 곳입니다. 정지 버튼은 조작부 안에 있습니다.
- 정지 버튼으로 멈춘 상태는 화살표나 점으로 이동해도 유지됩니다.
- 마지막 공지 다음은 첫 공지입니다(`(i + slides.length) % slides.length`).
- 공지를 바꿀 때 `hidden`만 바꾸며, 전환 애니메이션은 없습니다.
- 공지를 감싼 요소는 `article`에 `role="group"`을 준 형태입니다. on 개발 에이전트는 `article`이 `group` 역할을 허용하지 않는다고 보고 `div`로 바꿨습니다. 이 화면의 마크업 검사와 확장 검사에서는 이 점이 오류나 위반으로 나오지 않았습니다.

## 미검증 항목

- 스크린 리더 발화: 화살표나 점으로 이동할 때 새 공지를 읽는지, 자동 전환은 읽지 않는지, ‘자세히’ 링크와 점 버튼의 이름을 어떻게 읽는지 확인하지 않았습니다.
- 키보드 초점만으로 자동 전환이 멈추는지는 따로 기록하지 않았습니다. 마우스를 올렸다가 뗀 뒤 전환이 다시 진행되는지도 따로 기록하지 않았습니다.
- 건너뛰기 링크를 실행한 뒤 초점이 어디로 가는지 기록하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 흰 글씨와 어두운 상자의 대비 측정값은 기록에 없습니다. 확장 검사에서 `color-contrast`가 위반과 판정 보류에 나오지 않은 것만 확인했습니다.
- 폭 320px에서는 가로 스크롤만 확인했습니다. 화살표와 글 상자의 배치, 화면 200% 확대는 확인하지 않았습니다.
