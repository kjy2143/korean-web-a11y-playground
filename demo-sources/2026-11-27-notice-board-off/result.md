# 공지사항 · 기본 개발 (off) 실행 결과

강조 공지 한 건과 공지 다섯 건의 목록을 보여 주는 공지사항 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-notice-board-on)에 있습니다.

확장 검사에서 명도 대비 위반이 20개 요소에 나왔습니다. 요청서 시안의 글자색을 그대로 썼고, 본문 색 `#999999`가 기관명과 제목에도 적용됐습니다. 폭 480px 이하에서는 CSS `order`로 날짜와 제목의 화면 순서를 바꿉니다.

## 사용 방법

1. 페이지 위쪽에 강조 공지 상자가 있습니다. ‘12월 7일 임시 휴관’은 링크(주소 `#`)입니다.
2. 아래 목록에 공지 다섯 건이 있습니다. 공지마다 분류 배지(안내·행사·모집), 제목 링크(주소 `#`), 날짜가 있습니다.
3. Tab 키로 강조 공지 링크와 제목 링크 다섯 개를 차례로 이동합니다.
4. 폭 480px 이하에서는 배지와 날짜가 윗줄에, 제목이 아랫줄에 놓이도록 작성돼 있습니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 공지사항’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 공지사항 목록과 강조 공지를 확인합니다.
>
> 위쪽에 강조 공지 상자(‘12월 7일 임시 휴관’) 하나, 아래에 공지 다섯 건의 목록이 있습니다. 목록은 분류(안내·행사·모집), 제목, 날짜를 보여 주고 제목은 링크입니다(주소 `#`).
>
> 디자인 시안: 브랜드 톤에 맞춰 본문 글자는 `#999999`, 날짜는 `#bbbbbb`입니다. 분류 배지는 연두 배경 `#c8e6a0`에 흰 글씨 12px입니다. 강조 공지 상자는 연한 노랑 배경 `#fff7d6`에 글씨 `#c9a227`입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다. 개발 에이전트는 화면 요청서만 받았습니다. 절차의 설정을 확인하는 문서와 설정 값만 읽었고, 자료 목록과 검사항목 레코드는 한 번도 받지 않았습니다. 실행 기록에서 이 세션의 자료 조회가 0회임을 확인했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 1건으로, `cat`의 출력을 파일로 보내 `index.html`을 쓰려던 명령이었습니다. 파일은 모두 만들어졌습니다. 개발 에이전트는 화면을 브라우저에서 열어 보거나 폭 320px로 확인하지 않았다고 보고했습니다.
- 수정 요청: 조작 확인에서 기능 결함이 나오지 않아 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행: 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었습니다. 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후): 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(이 문서, 2026-11-27 밤): 개발 절차를 ‘설정 확인’ 문서와 ‘절차’ 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했습니다. 자료 조회 명령은 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본입니다. 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 HTML 접근성 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 제목 구조 | 페이지 제목 ‘공지사항’은 `h1`, ‘강조 공지’와 ‘공지 목록’은 `h2`입니다. 두 `h2`는 화면에 보입니다. | [HTML 제목 요소](https://html.spec.whatwg.org/multipage/sections.html#the-h1,-h2,-h3,-h4,-h5,-and-h6-elements) |
| 영역 이름 | 강조 공지와 목록을 `section`으로 나누고 `aria-labelledby`로 각 `h2`와 연결했습니다. | [aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby) |
| 목록 | 공지 다섯 건은 `ul`의 `li`입니다. | [HTML ul 요소](https://html.spec.whatwg.org/multipage/grouping-content.html#the-ul-element) |
| 날짜 | 날짜는 `time` 요소이고 `datetime` 속성이 있습니다. | [HTML time 요소](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-time-element) |
| 링크 표시 | 제목 링크는 `color: inherit`로 본문과 같은 색입니다. 링크의 밑줄을 없애는 규칙은 없습니다. | 해당 없음 |
| 초점 표시 | `a:focus-visible`에서 `3px solid #333333` 윤곽선을 그립니다. | [Selectors Level 4의 :focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo) |
| 기본 언어 | `<html lang="ko">`입니다. | [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- 시안 색은 그대로 썼습니다. 개발 에이전트는 본문과 날짜, 분류 배지, 강조 공지의 색 조합이 대비가 낮아 읽기 어려울 수 있다고 보고했습니다. 대비 비율은 계산하지 않았고, 접근성 절차가 꺼져 있어 색을 바꾸지 않았다고 적었습니다. 디자인 쪽 확인이 필요하다고 남겼습니다.
- 요청서에 없는 공지 다섯 건의 제목과 날짜(2026.11.05~11.25)는 임의로 정했습니다. 분류는 안내 2건, 행사 1건, 모집 2건입니다.
- 제목이 링크라는 규칙을 강조 공지에도 적용해 ‘12월 7일 임시 휴관’을 `#` 링크로 두었습니다.
- 요청서에 없는 기관명 머리글과 영역 제목 두 개(‘강조 공지’, ‘공지 목록’)를 더했습니다.
- 폭 480px 이하에서는 CSS `order`로 날짜를 배지와 같은 윗줄에, 제목을 아랫줄에 두었습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 17 |
| 위반 규칙과 측정 대비 | `color-contrast` 20개 요소. 기록된 앞 4개는 `.site-name` 2.84:1, `h1` 2.84:1, `#highlight-title` 2.24:1, `.highlight-text > a` 2.24:1 |
| 키보드 조작 | Tab 정지점은 6곳(강조 공지 링크, 제목 링크 5개)이고 모두 초점 표시가 있었습니다. |
| 320px 가로 스크롤 | 페이지 가로 스크롤 없음 |
| 320px 순서 | 공지 5건 모두 제목에 `order: 2`, 날짜에 `order: 1`이 적용됨 |
| 마크업 오류 | `index.html` 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- 링크는 6개였고 목록에는 공지 다섯 건이 표시됐습니다.
- Tab 순서는 ‘12월 7일 임시 휴관’, ‘겨울철 열람실 운영 시간 변경 안내’, ‘푸른숲미술관 겨울 전시 연계 독서 강연’, ‘어린이 독서 교실 참가자 모집’, ‘장기 연체 도서 반납 안내’, ‘도서관 자원봉사자 신규 모집’이었습니다.
- 계산된 글자색은 본문과 제목 링크 `rgb(153, 153, 153)`, 날짜 `rgb(187, 187, 187)`, 강조 공지 `rgb(201, 162, 39)`, 분류 배지 `rgb(255, 255, 255)`(배경 `rgb(200, 230, 160)`)였습니다.
- `h1`(24px 굵은 글씨)과 강조 공지 링크(20px 굵은 글씨)는 큰 글자 기준 3:1을 적용받았습니다. 측정 대비는 2.84:1과 2.24:1로 그 기준에도 못 미쳤습니다.
- 창 폭 1280px에서는 목록 안에 `order`가 0이 아닌 요소가 없었습니다. 폭 320px에서는 공지 5건 모두 제목의 `order`가 2, 날짜의 `order`가 1이었습니다.

### 코드에서 확인한 사실

- `body`의 글자색이 `#999999`라 기관명, `h1`, ‘공지 목록’ 제목, 제목 링크가 모두 같은 색입니다.
- 분류 배지는 배경 `#c8e6a0`에 `#ffffff` 글씨 12px, 날짜는 `#bbbbbb` 14px입니다. 강조 공지는 배경 `#fff7d6`에 `#c9a227` 글씨이고 테두리가 없습니다.
- 화면에 글자를 담은 요소는 20개입니다(기관명 1, `h1` 1, `h2` 2, 강조 공지 링크 1, 배지·제목·날짜 15). 확장 검사의 위반 요소 수와 같습니다.
- 문서 순서는 배지, 제목, 날짜입니다. `@media (max-width: 480px)`에서 제목은 `flex-basis: 100%; order: 2`, 날짜는 `order: 1; margin-left: auto`입니다. 그래서 화면 배치 순서는 배지, 날짜, 제목이 됩니다.
- 본문 바로가기 링크는 없습니다. 파일은 `index.html`과 `style.css` 두 개이고 스크립트는 없습니다.

## 미검증 항목

- 스크린 리더 발화: 영역 제목, 분류 배지, 날짜를 어떻게 읽는지 확인하지 않았습니다.
- 폭 320px에서는 `order` 값만 기록했습니다. 배지, 날짜, 제목이 화면에 실제로 놓인 위치는 기록하지 않았습니다.
- 화면 순서와 문서 순서가 다른 점이 보조기술 사용자에게 주는 영향은 확인하지 않았습니다.
- 위반 요소 20개 가운데 측정 대비가 기록된 것은 앞 4개입니다. 날짜와 배지의 개별 측정 대비는 기록하지 않았습니다.
- 초점 표시는 있고 없음만 기록했습니다. 윤곽선의 잘림 여부는 기록하지 않았습니다.
- 실제 터치 기기, Chrome 이외의 브라우저, 화면 확대 상태, 고대비 모드는 확인하지 않았습니다.
