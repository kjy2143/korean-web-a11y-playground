# 공지사항 · 기본 개발 (off) 실행 결과

강조 공지 한 건과 공지 다섯 건의 목록을 보여 주는 공지사항 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다.

같은 요청서로 접근성 자료를 적용해 개선한 화면은 [공지사항 · 접근성 자료 적용 (on)](/?demo=2026-11-27-notice-board-on)에서 볼 수 있습니다.

## 사용 방법

1. 페이지 위쪽에 강조 공지 상자 ‘12월 7일 임시 휴관’이 있습니다.
2. 아래 목록에 공지 다섯 건이 있습니다. 공지마다 분류 배지(안내·행사·모집), 제목 링크(주소 `#`), 날짜가 있습니다.
3. Tab 키로 제목 링크 다섯 개를 차례로 이동합니다.
4. 폭 480px 이하에서는 제목이 한 줄 전체를 차지하고, 배지와 날짜가 그 위에 놓입니다.

## 요청서

‘화면 요청서: 공지사항’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 공지사항 목록과 강조 공지를 확인합니다.
>
> 위쪽에 강조 공지 상자(‘12월 7일 임시 휴관’) 하나, 아래에 공지 다섯 건의 목록이 있습니다. 목록은 분류(안내·행사·모집), 제목, 날짜를 보여 주고 제목은 링크입니다(주소 `#`).
>
> 디자인 시안: 브랜드 톤에 맞춰 본문 글자는 `#999999`, 날짜는 `#bbbbbb`입니다. 분류 배지는 연두 배경 `#c8e6a0`에 흰 글씨 12px입니다. 강조 공지 상자는 연한 노랑 배경 `#fff7d6`에 글씨 `#c9a227`입니다.

## 개발 조건

- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 끄고 요청서대로 만들었습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. 개발 에이전트는 스크립트 실행이 승인되지 않아 명도 대비를 손으로 계산했다고 보고했습니다.
- 개발 중 확인: 개발 에이전트는 브라우저로 화면을 열지 않고 코드로만 레이아웃을 검토했다고 보고했습니다.
- 수정 요청: 개발 에이전트는 시안 색을 어둡게 조정할지 물었습니다. 화면에 기능 결함이 없어 수정 요청을 보내지 않았습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 아래 목록은 개발 에이전트가 일반 지식으로 넣은 처리를 코드에서 확인한 것입니다.

### 자료 밖 근거(HTML, WAI-ARIA)

- 페이지 제목을 `h1`로, 강조 공지 제목과 목록 제목을 `h2`로 두었습니다. 목록 제목 ‘공지 목록’은 화면에서 숨겼습니다.
- 강조 공지와 목록을 `section`으로 나누고 `aria-labelledby`로 각 제목과 연결했습니다. [WAI-ARIA 1.2 aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby)
- 날짜는 `time` 요소와 `datetime` 속성으로 표시했습니다. [HTML time 요소](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-time-element)
- 제목 링크는 본문과 같은 색이라 밑줄로 링크임을 구분했습니다.
- 제목 링크에 `:focus-visible` 3px 어두운 윤곽선(`#333333`)을 표시합니다. [Selectors Level 4의 :focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo)

### 요청서와 다르게 판단한 부분

- 시안 색은 그대로 썼습니다. 개발 에이전트는 본문, 날짜, 배지, 강조 상자 글씨가 모두 대비 기준 4.5:1에 못 미친다고 보고했습니다. 색 조정 값은 사용자가 확정할 일이라고 보고 바꾸지 않았습니다.
- 요청서에 없는 공지 제목과 날짜(2026년 기준)는 임의로 만들었습니다.
- 강조 공지 상자에는 제목만 넣었습니다.
- 폭 480px 이하에서는 CSS `order`로 제목을 배지와 날짜 아래로 내렸습니다.

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

### 확장 검사

초기 상태에서 위반 규칙은 1개, 판정 보류 규칙은 0개, 통과 규칙은 17개였습니다. 위반 규칙은 `color-contrast`이고 대상은 18개 요소입니다. 본문 문단(`p`)과 페이지 제목(`h1`) 등의 측정 대비는 2.84:1이었습니다.

### 브라우저에서 관찰한 결과

- 공지 다섯 건이 표시됐습니다.
- 폭 1280px에서 Tab 순서대로 초점이 이동했습니다. 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 폭 320px에서 페이지 가로 스크롤이 없었습니다.
- 마크업 검사 오류는 0건이었습니다.
- 초기 상태에서 콘솔 오류(pageerror)는 0건이었습니다.

### 코드에서 확인한 사실

- 본문 전체 글자색이 `#999999`라 페이지 제목과 기관명도 같은 색입니다.
- 분류 배지는 연두 배경 `#c8e6a0`에 흰 글씨 12px, 날짜는 `#bbbbbb`, 강조 공지는 `#fff7d6` 배경에 `#c9a227` 글씨입니다.
- 폭 480px 이하에서 화면에 보이는 순서는 배지, 날짜, 제목입니다. 문서 순서는 배지, 제목, 날짜입니다.
- 본문 바로가기 링크는 없습니다.

## 미검증 항목

- 스크린 리더 발화: 숨긴 목록 제목, 분류 배지, 날짜를 어떻게 읽는지 확인하지 않았습니다.
- 폭 480px 이하에서 화면 순서와 읽는 순서가 다른 점이 보조기술 사용자에게 주는 영향은 확인하지 않았습니다.
- 날짜와 배지의 개별 측정 대비는 기록하지 않았습니다.
- 실제 터치 기기, Chrome 외 브라우저, 화면 확대 상태는 확인하지 않았습니다.
