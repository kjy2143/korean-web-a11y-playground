# 이용 안내 창 · 기본 개발 (off) 실행 결과

푸른숲도서관 소개 페이지에 들어오면 ‘12월 이용 안내’ 창이 자동으로 열리는 화면입니다. 창을 읽고 닫은 뒤 ‘이용 안내 보기’ 버튼으로 다시 열 수 있습니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-modal-layer-on)에 있습니다.

확장 검사에서 창이 열린 상태와 닫힌 상태 모두 위반과 판정 보류가 없었습니다. 진입하면 창이 열리고 초점이 닫기 버튼으로 갔으며, Esc로 닫으면 초점이 ‘이용 안내 보기’ 버튼으로 돌아왔습니다.

## 사용 방법

- 페이지에 들어오면 안내 창이 자동으로 열립니다.
- 창 오른쪽 위의 X 버튼, Esc 키, 창 바깥 누르기로 창을 닫습니다.
- ‘오늘 하루 보지 않기’를 선택하고 닫으면 그날은 창이 자동으로 열리지 않습니다.
- ‘이용 안내 보기’ 버튼으로 언제든 창을 다시 엽니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 이용 안내 창’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 안내 창을 열어 읽고 닫습니다.
>
> 도서관 소개 본문 두 문단과 ‘이용 안내 보기’ 버튼이 있는 페이지입니다. 페이지에 들어오면 ‘12월 이용 안내’ 창이 자동으로 열립니다. 창에는 제목, 안내 세 줄(연말 휴관, 대출 기간 연장, 무인 반납함 이용), ‘오늘 하루 보지 않기’ 체크, 닫기가 있습니다. ‘오늘 하루 보지 않기’를 체크하고 닫으면 그날은 자동으로 열리지 않습니다. ‘이용 안내 보기’ 버튼으로는 언제든 다시 엽니다.
>
> 디자인 시안: 닫기는 창 오른쪽 위의 X 아이콘만 둡니다. 뒤 화면은 반투명 검정으로 덮습니다. 창 바깥을 누르면 닫힙니다. ‘오늘 하루 보지 않기’ 글씨는 12px `#aaaaaa`입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다.
- 지시: 요청서 전문을 주고, 질문하지 말고 구현을 마친 뒤 만든 파일과 판단이 필요했던 점을 보고하게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. 개발 에이전트는 화면을 브라우저로 실행해 보지 않았다고 보고했습니다.
- 수정 요청: 이 화면에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

국내 접근성 자료를 조회해 적용하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 HTML 표준 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 모달 창 | 네이티브 `dialog` 요소를 `showModal()`로 엽니다. 개발 에이전트는 뒤 화면 조작 차단과 초점 가두기를 브라우저에 맡겼다고 보고했습니다. 뒤 화면은 `::backdrop`의 `rgba(0,0,0,.6)`으로 덮습니다. | [HTML dialog 요소](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element) |
| 창 이름 | `dialog`에 `aria-labelledby`로 창 제목 ‘12월 이용 안내’(`h2`)를 연결했습니다. | [aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby) |
| X 버튼 | 보이는 글자 없이 `aria-label="닫기"`를 달았고, 아이콘 SVG는 `aria-hidden="true"`입니다. 버튼 크기는 44×44px입니다. | [aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| Esc 키 | `cancel` 이벤트에서 기본 동작을 막고, ‘오늘 하루 보지 않기’ 상태를 저장한 뒤 창을 닫습니다. | [cancel 이벤트](https://html.spec.whatwg.org/multipage/indices.html#event-cancel) |
| 초점 복귀 | `close` 이벤트에서 초점을 ‘이용 안내 보기’ 버튼으로 옮깁니다. 자동으로 열린 창을 닫을 때도 같습니다. | [close 이벤트](https://html.spec.whatwg.org/multipage/indices.html#event-close) |
| 체크 상자 | ‘오늘 하루 보지 않기’ 체크 상자에 `label for`를 연결했습니다. | [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element) |
| 날짜 저장 | 선택한 날짜를 `localStorage`에 저장하고, 날짜가 바뀌면 다시 자동으로 엽니다. | [localStorage](https://html.spec.whatwg.org/multipage/webstorage.html#dom-localstorage) |
| 초점 표시와 언어 | 버튼과 입력의 `:focus-visible`에 3px 윤곽선을 그립니다. `<html lang="ko">`입니다. | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo), [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- ‘오늘 하루 보지 않기’ 글자색: 12px은 유지하고 시안의 `#aaaaaa`를 `#666666`으로 바꿨습니다. 개발 에이전트는 흰 배경에서 대비가 낮아 읽기 어렵다고 보고했습니다.
- Esc 키: 요청서에 없지만 Esc로도 닫히게 했습니다.
- 초점 복귀: 창을 닫으면 초점을 ‘이용 안내 보기’ 버튼으로 옮깁니다.
- 다시 열 때: 버튼으로 다시 열면 ‘오늘 하루 보지 않기’는 선택 해제 상태로 시작합니다.
- 안내 문구: 세 줄의 날짜와 기간(12월 31일·1월 1일 휴관, 7일 연장, 24시간 반납)은 요청서에 없어 임의로 정했습니다.

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태(창 열림) | 0 / 0 / 20 |
| 확장 검사: 창 닫음 | 0 / 0 / 12 |
| 위반·판정 보류 규칙 | 없음 |
| 키보드 조작 | 진입 시 초점이 닫기 버튼으로 갔고, Esc로 닫으면 초점이 ‘이용 안내 보기’ 버튼으로 돌아왔습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html` 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- 진입하면 창이 자동으로 열렸습니다.
- 마우스로 X를 누르면 창이 닫혔고, ‘이용 안내 보기’ 버튼으로 다시 열렸습니다. 창 바깥을 클릭해도 닫혔습니다.
- 진입 시 초점은 닫기 버튼에 있었고, Esc로 닫으면 초점이 ‘이용 안내 보기’ 버튼으로 돌아왔습니다.
- 1280px에서 Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- `dialog`는 문서에서 본문(`main`) 뒤에 있습니다.
- ‘오늘 하루 보지 않기’ 저장은 X 버튼, Esc의 `cancel` 처리, 바깥 클릭 처리에서 각각 부르는 닫기 함수 안에서만 합니다. `close` 이벤트에서는 초점만 옮깁니다.
- 바깥 클릭은 `click` 이벤트의 좌표가 창 영역 밖인지로 판단합니다.

## 미검증 항목

- 스크린 리더 발화: 창이 열릴 때 대화상자 역할과 제목을 읽는지, 뒤 본문을 읽지 않는지, X 버튼을 ‘닫기’로 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- ‘오늘 하루 보지 않기’를 선택하고 닫은 뒤 새로고침했을 때 창이 열리지 않는지 확인하지 않았습니다.
- Tab과 Shift+Tab이 창 안에서만 순환하는지, 창 안에서 글자를 끌어 바깥에서 놓을 때 창이 닫히는지 기록하지 않았습니다.
- 화면 확대와 고대비 모드는 확인하지 않았습니다.
