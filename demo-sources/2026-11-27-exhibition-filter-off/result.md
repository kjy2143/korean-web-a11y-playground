# 전시 일정 · 기본 개발 (off) 실행 결과

푸른숲미술관 전시 네 건을 전시 이름과 관람 요일로 찾는 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다.

같은 요청서로 접근성 자료를 적용해 개선한 화면은 [전시 일정 · 접근성 자료 적용 (on)](/?demo=2026-11-27-exhibition-filter-on)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열면 전시 네 건과 결과 건수 ‘총 4건’이 보입니다.
2. ‘전시 이름 검색’ 입력란에 이름 일부를 쓰거나 요일 선택에서 수·토·일 중 하나를 고릅니다. 첫 항목 ‘요일’은 전체를 뜻합니다.
3. 돋보기 버튼을 누르거나 입력란에서 Enter를 누르면 결과와 건수가 바뀝니다. 이름은 공백과 대소문자를 무시하고 부분 일치로 찾습니다.
4. 결과가 없으면 ‘총 0건’과 ‘조건에 맞는 전시가 없습니다’가 나옵니다.
5. ↺ 버튼을 누르면 조건을 비우고 네 건을 다시 보여 준 뒤 이름 입력란으로 초점을 옮깁니다.

## 요청서

‘화면 요청서: 전시 일정’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 전시 이름과 관람 요일로 전시 일정을 찾습니다.
>
> 전시 네 개를 보여 주고 이름과 요일로 찾습니다. 전시는 ‘종이로 만든 풍경’(수 14:00, 제1전시실), ‘색으로 읽는 도시’(토 11:00, 제2전시실), ‘종이 위의 정원’(토 15:00, 열린 작업실), ‘주말에 만나는 판화’(일 13:00, 제1전시실)입니다. 이름 검색란, 요일 선택(전체·수·토·일), 검색 버튼, 초기화 버튼이 있습니다. 결과 건수를 표시하고, 결과가 없으면 ‘조건에 맞는 전시가 없습니다’를 보여 줍니다.
>
> 디자인 시안: 검색란은 안내 문구 ‘전시 이름 검색’만 둡니다. 요일 선택은 제목 없이 첫 항목을 ‘요일’로 둡니다. 검색 버튼은 돋보기 아이콘, 초기화는 ↺ 아이콘입니다. 결과 건수 ‘총 4건’은 13px `#aaaaaa`입니다.

## 개발 조건

- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 끄고 요청서대로 만들었습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 개발 중 확인: 개발 에이전트는 스크립트 문법 검사만 통과시켰고 브라우저에서는 실행하지 않았다고 보고했습니다.
- 수정 요청: 화면에 기능 결함이 없어 수정 요청을 보내지 않았습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 아래 목록은 개발 에이전트가 일반 지식으로 넣은 처리를 코드에서 확인한 것입니다.

### 자료 밖 근거(HTML, WAI-ARIA)

- 이름 입력란과 요일 선택에 화면에서 숨긴 `label`(‘전시 이름 검색’, ‘관람 요일’)을 `for`로 연결했습니다. [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element)
- 아이콘 버튼 두 개에 `aria-label`(‘검색’, ‘초기화’)을 주고, 돋보기 SVG와 ↺ 글자는 `aria-hidden="true"`로 숨겼습니다. [WAI-ARIA 1.2 aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [WAI-ARIA 1.2 aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden)
- 검색 양식에 `role="search"`와 `aria-label="전시 검색"`을 주었습니다. [WAI-ARIA 1.2 search 역할](https://www.w3.org/TR/wai-aria-1.2/#search)
- 결과 건수 문단에 `role="status"`를 주어 건수 변경을 보조기술에 알립니다. [WAI-ARIA 1.2 status 역할](https://www.w3.org/TR/wai-aria-1.2/#status)
- 검색은 양식을 제출할 때(버튼 또는 Enter)만 실행됩니다. 요일을 바꾸는 것만으로는 결과가 바뀌지 않습니다.
- 초기화 버튼은 `type="reset"`이고, 초기화 뒤 초점을 이름 입력란으로 옮깁니다.
- 결과 없음 문구는 `hidden` 속성으로 보이고 숨깁니다. [HTML hidden 속성](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute)
- 입력란, 선택, 버튼의 최소 높이를 44px로 두고 `:focus-visible` 3px 윤곽선을 표시합니다. [Selectors Level 4의 :focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo)

### 요청서와 다르게 판단한 부분

- 결과 건수는 시안대로 13px `#aaaaaa`를 썼습니다. 개발 에이전트는 흰 배경에서 읽기 어렵다고 보고했지만 바꾸지 않았습니다.
- 요청서의 요일 선택 항목 ‘전체’는 별도 항목 없이 시안의 첫 항목 ‘요일’이 대신합니다.
- 시안에 없는 검색란 제목과 요일 제목은 화면에 보이지 않는 레이블로 처리했습니다.

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

### 확장 검사

| 상태 | 위반 규칙 수 | 판정 보류 규칙 수 | 통과 규칙 수 |
|---|---|---|---|
| 초기 | 1 | 1 | 26 |
| 검색 0건 | 1 | 1 | 25 |

- 두 상태 모두 위반 규칙은 `color-contrast`이고, 대상은 결과 건수(`#count`) 1개 요소입니다. 측정 대비는 2.32:1이었습니다.
- 판정 보류 대상 요소는 `color-contrast` 1개와 `label-content-name-mismatch` 1개입니다. `color-contrast`는 위반 규칙에도 들어 있습니다.

### 브라우저에서 관찰한 결과

- ‘없는전시’로 검색하자 ‘총 0건’과 안내 문구가 나왔습니다.
- 초기화하자 네 건이 다시 나왔습니다.
- ‘종이’를 입력하고 토요일을 골라 검색하자 한 건이 나왔습니다.
- 보이는 레이블은 없었고, 입력란과 선택의 이름은 안내 문구와 숨긴 레이블에서 왔습니다.
- 결과 건수는 상태 영역(`p`)에 표시됐습니다.
- 폭 1280px에서 Tab 순서대로 초점이 이동했습니다. 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.
- 폭 320px에서 페이지 가로 스크롤이 없었습니다.
- 마크업 검사 오류는 0건이었습니다.
- 초기 상태에서 콘솔 오류(pageerror)는 0건이었습니다.

### 코드에서 확인한 사실

- 결과 없음 문구는 상태 영역 밖의 별도 문단입니다. 상태 영역에는 ‘총 0건’만 들어갑니다.
- 결과 건수 문단은 13px `#aaaaaa` 글자입니다.

## 미검증 항목

- 스크린 리더 발화: 아이콘 버튼 이름, 숨긴 레이블, 건수 변경 안내를 어떻게 읽는지 확인하지 않았습니다.
- 같은 조건으로 다시 검색해 건수 문구가 같을 때 안내가 반복되는지 확인하지 않았습니다.
- 판정 보류 두 건의 대상 요소는 이 문서에서 특정하지 않았습니다.
- 실제 터치 기기, Chrome 외 브라우저, 화면 확대 상태는 확인하지 않았습니다.
