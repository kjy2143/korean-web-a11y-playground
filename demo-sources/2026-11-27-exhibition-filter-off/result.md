# 전시 일정 · 기본 개발 (off) 실행 결과

푸른숲미술관 전시 네 건을 전시 이름과 관람 요일로 찾는 화면입니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 화면 요청서만 주고 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-exhibition-filter-on)에 있습니다.

확장 검사에서 결과 건수 ‘총 4건’이 명도 대비 위반(2.32:1)으로 나왔습니다. 처음 만든 화면은 초기화 버튼이 동작하지 않았습니다. 같은 개발 세션에 한 번 보고해 수정본을 받았고, 이 문서의 검사 수치는 수정본에서 잰 것입니다.

## 사용 방법

- 검색란에 전시 이름의 일부를 입력하거나 요일을 고른 뒤 돋보기 버튼을 누르거나 Enter를 누릅니다. 목록과 결과 건수가 바뀝니다.
- 요일을 바꾸기만 해서는 결과가 바뀌지 않습니다. 검색을 실행해야 바뀝니다.
- 이름 검색은 공백을 무시하고 부분 일치로 찾습니다.
- ↺ 버튼을 누르면 조건이 지워지고 전시 네 건이 다시 보입니다.
- 조건에 맞는 전시가 없으면 ‘총 0건’과 ‘조건에 맞는 전시가 없습니다’가 표시됩니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 전시 일정’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 전시 이름과 관람 요일로 전시 일정을 찾습니다.
>
> 전시 네 개를 보여 주고 이름과 요일로 찾습니다. 전시는 ‘종이로 만든 풍경’(수 14:00, 제1전시실), ‘색으로 읽는 도시’(토 11:00, 제2전시실), ‘종이 위의 정원’(토 15:00, 열린 작업실), ‘주말에 만나는 판화’(일 13:00, 제1전시실)입니다. 이름 검색란, 요일 선택(전체·수·토·일), 검색 버튼, 초기화 버튼이 있습니다. 결과 건수를 표시하고, 결과가 없으면 ‘조건에 맞는 전시가 없습니다’를 보여 줍니다.
>
> 디자인 시안: 검색란은 안내 문구 ‘전시 이름 검색’만 둡니다. 요일 선택은 제목 없이 첫 항목을 ‘요일’로 둡니다. 검색 버튼은 돋보기 아이콘, 초기화는 ↺ 아이콘입니다. 결과 건수 ‘총 4건’은 13px `#aaaaaa`입니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행). 개발 세션은 대화 턴 11회, 45초였습니다.
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 꺼 두었습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값(off)만 읽었습니다. 절차 본문, 자료 목록, 검사항목 레코드는 한 번도 받지 않았습니다. 실행 기록에서 자료 조회가 0회임을 확인했고, 이번 실행의 off 세션 13개가 모두 같았습니다.
- 지시: 화면 요청서만 주었습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 폴더를 옮긴 뒤 다른 명령을 잇는 복합 명령 1건이 거부됐고, 그 뒤에도 파일 세 개는 모두 만들어졌습니다. 개발 에이전트는 화면을 브라우저에서 열어 보지 못했고 `script.js` 문법 검사만 통과시켰다고 보고했습니다. 320px 폭 확인과 동작 시험도 하지 않았다고 보고했습니다.
- 수정 요청: 마우스 확인에서 초기화 버튼이 동작하지 않아, 같은 개발 세션에 재현 절차와 관찰 결과를 한 번 보고하고 수정본을 받았습니다. 수정 전후는 검증 결과에 적었습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면(수정본)의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 숨김 레이블 | 검색란과 요일 선택에 `label for`(‘전시 이름 검색’, ‘관람 요일’)를 연결하고 `.sr-only`로 화면에서만 숨겼습니다(`index.html`, `style.css`). | [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element) |
| 아이콘 버튼의 이름 | 두 버튼에 `aria-label`(‘검색’, ‘초기화’)을 달았습니다. 돋보기 SVG와 ↺ 글자는 `aria-hidden="true"`입니다(`index.html`). | [aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 검색 영역 | 검색 양식에 `role="search"`와 `aria-label="전시 검색"`을 주었습니다(`index.html`). | [search 역할](https://www.w3.org/TR/wai-aria-1.2/#search) |
| 결과 건수 알림 | 결과 건수 문단에 `role="status"`를 주었습니다. 개발 에이전트는 결과가 바뀔 때 스크린 리더가 읽게 하려는 처리라고 보고했습니다(`index.html`). | [status 역할](https://www.w3.org/TR/wai-aria-1.2/#status) |
| 검색 실행 시점 | 양식을 제출할 때(검색 버튼 또는 Enter)만 목록을 다시 그립니다. 요일 선택의 `change`에는 처리가 없습니다(`script.js`). | 해당 없음 |
| 초기화 뒤 초점 | 초기화 버튼을 누르면 양식을 비우고 목록을 다시 그린 뒤 검색란으로 초점을 옮깁니다(`script.js`). | 해당 없음 |
| 결과 없음 문구 | ‘조건에 맞는 전시가 없습니다’ 문단을 `hidden` 속성으로 보이고 숨깁니다(`index.html`, `script.js`). | [HTML hidden 속성](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute) |
| 조작 크기와 초점 표시 | 검색란, 요일 선택, 버튼의 높이가 44px이고 아이콘 버튼은 44×44px입니다. `:focus-visible`에 3px 윤곽선을 그립니다(`style.css`). | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo) |
| 기본 언어 | `<html lang="ko">`입니다. | [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- 결과 건수는 시안대로 13px `#aaaaaa`를 썼습니다. 개발 에이전트는 흰 배경에서 글자 대비가 부족하다고(약 2.3:1) 보고했지만 시안 값이라 바꾸지 않았고, 확정 전에 색 조정을 검토해야 한다고 적었습니다.
- 시안에 제목이 없어 검색란과 요일 선택에 보이는 레이블을 두지 않았고, 화면에 보이지 않는 레이블을 달았습니다.
- 요청서 본문의 요일 선택 항목 ‘전체’는 따로 없습니다. 시안의 첫 항목 ‘요일’이 값이 빈 항목으로 들어가 전체 전시를 보여 줍니다.
- 요청서에 없는 카드 표시 형식은 ‘수요일 14:00 · 제1전시실’로 정했고, 색은 녹색 계열로 골랐다고 보고했습니다.
- 이름 검색은 공백을 무시하고 부분 일치로 찾게 했습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다. 아래 수치는 모두 초기화 버튼을 고친 수정본에서 잰 것입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 1 / 1 / 26 |
| 확장 검사: 검색 0건 | 1 / 1 / 25 |
| 위반 규칙과 측정 대비 | color-contrast 1개 요소(결과 건수 `#count`, `#aaaaaa` 13px, 2.32:1). 두 상태에서 같습니다. |
| 판정 보류 요소 | color-contrast 1개 요소(초기화 버튼의 ↺ 글자, 비텍스트 문자만 있어 판단하지 못함)와 label-content-name-mismatch 1개 요소(초기화 버튼 `#clear-btn`). color-contrast는 위반에도 들어 있어 판정 보류 규칙 수는 1로 집계됐습니다. |
| 키보드 조작 | Tab 정지점은 검색란, 요일 선택, 검색 버튼, 초기화 버튼 순서였습니다. 초점 표시가 없는 정지점은 없었습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html` 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 초기화 버튼 결함과 수정

- 수정 전: ‘없는전시’를 검색해 ‘총 0건’이 나온 상태에서 ↺ 버튼을 마우스로 눌렀습니다. 검색란에 ‘없는전시’가 그대로 남았고 결과도 ‘총 0건’ 그대로였습니다. 콘솔에는 `TypeError: form.reset is not a function`이 기록됐습니다.
- 보고: 같은 개발 세션에 재현 절차, 관찰한 결과, 요청서가 기대하는 동작만 적어 한 번 보냈습니다. 원인은 적지 않았습니다.
- 개발 에이전트의 답: 초기화 버튼의 `id="reset"`이 원인이라고 답했습니다. 폼 안에 `id`가 `reset`인 요소가 있으면 `form.reset`이 그 요소를 가리켜 `reset()` 메서드가 가려진다는 설명입니다. 버튼 `id`를 `clear-btn`으로 바꾸고 `index.html`, `style.css`, `script.js`의 해당 이름을 함께 고쳤습니다. 브라우저에서 다시 눌러 보지는 못했다고 보고했습니다.
- 수정 후: 같은 절차에서 ↺ 버튼을 누르면 검색란이 비워지고 ‘총 4건’과 전시 네 건이 다시 보였습니다. 초점은 검색란으로 갔습니다. 조작 중 콘솔 오류는 기록되지 않았습니다.

### 브라우저에서 관찰한 결과

- ‘없는전시’를 입력하고 Enter를 누르면 목록이 비고 ‘총 0건’과 ‘조건에 맞는 전시가 없습니다’가 표시됐습니다. 초점은 검색란에 남았습니다.
- ‘종이’를 입력하고 토요일을 고른 뒤 검색 버튼을 누르면 전시 한 건과 ‘총 1건’이 표시됐습니다.
- 레이블 ‘전시 이름 검색’과 ‘관람 요일’은 화면에서 숨겨져 있었습니다. 검색란에는 placeholder ‘전시 이름 검색’만 보였습니다.
- 조작 요소의 이름은 검색란 ‘전시 이름 검색’, 요일 선택 ‘관람 요일’, 버튼 ‘검색’과 ‘초기화’였습니다.

### 코드에서 확인한 사실

- 결과 없음 문구는 상태 영역 밖의 별도 문단입니다. `role="status"`인 문단에는 ‘총 N건’만 들어갑니다.
- 결과 건수 문단은 13px, `#aaaaaa`입니다.
- 검색란의 숨김 레이블과 placeholder는 같은 문장(‘전시 이름 검색’)입니다.
- 요일 선택의 항목은 ‘요일’(값 없음), ‘수’, ‘토’, ‘일’ 네 개입니다.
- 수정본의 초기화 버튼은 `type="button"`, `id="clear-btn"`이고, 누르면 `form.reset()`을 부른 뒤 목록을 다시 그리고 검색란에 초점을 둡니다.

## 미검증 항목
