# 도서관 운영 시간 · 접근성 자료 적용 (on) 실행 결과

푸른숲도서관 분관별 운영 시간 표를 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-library-hours-table-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사에서 off의 명도 대비 위반(‘2026년 11월 기준’ 문구, 2.32:1)이 사라졌습니다. 휴관 칸에는 화면에 보이는 글자 ‘휴관’이 생겼습니다. 표 구조, 키보드 조작, 320px 화면, 마크업 검사 결과는 off와 같았습니다.

## 사용 방법

- 표에서 분관(행)과 요일(열)이 만나는 칸의 운영 시간을 읽습니다. 휴관일 칸에는 연한 빨강 배경과 ‘휴관’ 글자가 함께 있습니다.
- 화면 폭이 좁으면 표 영역만 가로로 스크롤됩니다. 키보드로는 Tab으로 표 영역에 초점을 둔 뒤 방향키로 스크롤합니다.
- off 화면과 나란히 열어 휴관 칸 표시와 기준일 문구의 색을 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 도서관 운영 시간’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 분관별 요일 운영 시간과 휴관일을 비교합니다.
>
> 분관 세 곳의 월요일~일요일 운영 시간을 표로 보여 줍니다. 중앙관은 월요일 휴관, 화~금 09:00–22:00, 토·일 09:00–18:00입니다. 숲속분관은 월요일 휴관, 화~일 10:00–19:00입니다. 어린이분관은 월·화요일 휴관, 수~일 10:00–18:00입니다.
>
> 디자인 시안: 첫 줄(요일)과 첫 칸(분관 이름)은 회색 배경에 굵은 글씨입니다. 휴관일 칸은 연한 빨강 배경으로 표시하고 시안처럼 글자는 넣지 않습니다. 좁은 화면에서는 표 영역만 가로로 스크롤합니다. 표 아래 ‘2026년 11월 기준’은 `#aaaaaa`로 작게 둡니다.

요청서 시안과 다르게 구현한 부분은 두 곳이고, 둘 다 요청자가 미리 승인한 조정입니다.

| 요청서 시안 | 조정한 내용 | 이유 |
| --- | --- | --- |
| 휴관일 칸은 연한 빨강 배경, 글자 없음 | 칸마다 보이는 글자 ‘휴관’을 굵게 넣었습니다(글자색 `#7a1010`). 연한 빨강 배경은 유지했습니다. | off는 숨김 글자만 넣어, 눈으로 보는 사용자에게는 색만으로 휴관을 알렸습니다(5.4.1). |
| ‘2026년 11월 기준’ 작은 글씨 `#aaaaaa` | 작은 글자 크기는 유지하고 색을 `#595959`로 바꿨습니다. | off의 문구는 흰 배경 대비가 2.32:1(확장 측정)이라 4.5:1에 못 미칩니다(5.4.3). |

시안과 충돌하지 않는 변경이 하나 더 있습니다. 표 테두리를 `#bbb`에서 `#767676`으로 진하게 했습니다. 개발 에이전트는 5.4.4의 ‘테두리로 구분’ 방법을 따른 변경이며, 수치 기준이 없는 판단이라고 보고했습니다. 첫 줄과 첫 칸의 회색 배경과 굵은 글씨, 표 영역만 가로로 스크롤하는 시안은 그대로입니다. 접근성과 무관한 기능 결함은 찾지 못했다고 보고했습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치고, 접근성과 무관한 기능 결함을 고쳤으면 따로 구분해 적게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 위반 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 18 | 0 / 0 / 19 |
| 주요 위반 규칙과 측정 대비 | color-contrast 1개 요소(`.note`, 2.32:1) | 없음 |
| 키보드 조작 | Tab 이동과 초점 표시 있음. 스크롤 영역 `tabindex="0"` | off와 같음 |
| 320px 가로 스크롤 | 페이지 가로 스크롤 없음 | 페이지 가로 스크롤 없음 |
| 마크업 오류 | 0건 | 0건 |
| 표 구조 | `th` 11개(`scope` col/row), `caption`, 휴관 칸 텍스트 ‘휴관’ 4개 | off와 같음 |

### 브라우저에서 관찰한 결과

- on에서는 color-contrast 위반이 없어 통과 규칙이 18개에서 19개로 늘었습니다.
- 두 화면 모두 `th` 11개에 `scope`(col 또는 row)가 있었고, `caption`과 휴관 칸 텍스트 ‘휴관’ 4개가 있었습니다. 스크롤 영역은 `role="region"`, `tabindex="0"`이었습니다.
- 브라우저 확인에서 두 화면의 차이는 기준일 문구의 대비였습니다.
- 1280px에서 Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- off의 ‘휴관’은 `.sr-only`로 숨긴 글자이고, on의 ‘휴관’은 칸에 보이는 글자입니다. 그래서 접근성 트리의 텍스트는 같고 화면 표시만 다릅니다.
- on의 휴관 칸은 `#fde0e0` 배경에 `#7a1010` 굵은 글자입니다.
- 기준일 문구는 `#595959`, 표 테두리는 `#767676`입니다.

## 미검증 항목

- 스크린 리더 발화: 표 제목과 행·열 제목을 칸과 함께 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 320px에서 표 영역이 실제로 가로 스크롤되는지, 방향키로 스크롤되는지는 기록하지 않았습니다.
- ‘휴관’ 글자가 연한 빨강 배경 위에서 읽히는지는 확장 검사 결과 외에 눈으로 따로 판단하지 않았습니다. 고대비 모드에서 배경색이 사라질 때의 표시도 확인하지 않았습니다.

### 개발 중 읽지 못한 자료

- 6.1.2와 6.4.2의 본문은 긴 줄이 발췌에서 생략돼 끝까지 읽지 못했습니다.
- 6.5.3, 7.1.1, 7.2.1, 8.1.1은 레코드를 내려받았지만 본문을 읽지 않았습니다.
- 5.3.1, 5.4.1, 5.4.3, 6.1.1의 적용 사례와 개선 필요 사례는 읽지 않았습니다.
- 명도 대비를 스크립트로 계산하려 했지만 셸 명령 제한으로 실행하지 못했습니다. 접속하지 못한 주소는 없었습니다.
