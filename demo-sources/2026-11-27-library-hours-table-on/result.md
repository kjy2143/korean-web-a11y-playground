# 도서관 운영 시간 · 접근성 자료 적용 (on) 실행 결과

푸른숲도서관 분관별 운영 시간 표를 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)에 맞춰 개선한 결과입니다. [기본 개발 (off)](/?demo=2026-11-27-library-hours-table-off) 화면을 복사한 뒤, 자료를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 고쳤습니다.

확장 검사에서 off의 명도 대비 위반(‘2026년 11월 기준’ 문구, 2.32:1)이 사라졌습니다. 휴관 칸 4곳에는 화면에 보이는 글자 ‘휴관’이 생겼습니다. 표 구조, Tab 순서, 320px 화면의 페이지 가로 스크롤, 마크업 검사 결과는 off와 같았습니다.

## 사용 방법

- 표에서 분관(행)과 요일(열)이 만나는 칸의 운영 시간을 읽습니다. 휴관일 칸에는 연한 빨강 배경과 ‘휴관’ 글자가 함께 있습니다.
- 화면 폭이 좁으면 표 영역만 가로로 스크롤되도록 만들었습니다. 키보드로는 Tab으로 표 영역에 초점을 둔 뒤 방향키로 스크롤합니다.
- off 화면과 나란히 열어 휴관 칸 표시와 기준일 문구의 색을 비교합니다.

## 요청서와 조정한 부분

개발 에이전트에게 준 ‘화면 요청서: 도서관 운영 시간’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 분관별 요일 운영 시간과 휴관일을 비교합니다.
>
> 분관 세 곳의 월요일~일요일 운영 시간을 표로 보여 줍니다. 중앙관은 월요일 휴관, 화~금 09:00–22:00, 토·일 09:00–18:00입니다. 숲속분관은 월요일 휴관, 화~일 10:00–19:00입니다. 어린이분관은 월·화요일 휴관, 수~일 10:00–18:00입니다.
>
> 디자인 시안: 첫 줄(요일)과 첫 칸(분관 이름)은 회색 배경에 굵은 글씨입니다. 휴관일 칸은 연한 빨강 배경으로 표시하고 시안처럼 글자는 넣지 않습니다. 좁은 화면에서는 표 영역만 가로로 스크롤합니다. 표 아래 ‘2026년 11월 기준’은 `#aaaaaa`로 작게 둡니다.

요청서 시안과 다르게 구현한 부분은 두 곳이고, 둘 다 요청자가 미리 승인한 조정입니다.

| 요청서 시안 | 조정한 내용 | 이유 |
| --- | --- | --- |
| 휴관일 칸은 연한 빨강 배경, 글자 없음 | 칸마다 보이는 글자 ‘휴관’을 넣었습니다(글자색 `#222`). 연한 빨강 배경 `#fbdcdc`는 유지했습니다. | off는 숨김 글자만 있어, 눈으로 보는 사용자에게는 색만으로 휴관을 알렸습니다(5.4.1). |
| ‘2026년 11월 기준’ 작은 글씨 `#aaaaaa` | 글자 크기(0.8125rem)는 유지하고 색을 `#595959`로 바꿨습니다. | 개발 에이전트는 `#aaaaaa`와 흰 배경의 대비를 약 2.3:1로 계산했고, 4.5:1에 못 미친다고 판단했습니다(5.4.3). `#595959`는 약 7.0:1로 계산했습니다. |

- 개발 에이전트는 더 쓰이지 않는 숨김 글자용 `.sr-only` 규칙을 CSS에서 지웠습니다.
- 첫 줄과 첫 칸의 회색 배경과 굵은 글씨, 표 영역만 가로로 스크롤하는 시안은 그대로입니다.
- 개발 에이전트는 운영 시간 3행을 요청서와 대조해 모두 일치했고, 접근성과 무관한 기능 결함은 찾지 못했다고 보고했습니다.
- 개발 에이전트는 휴관 칸의 표시 방법을 설명하는 안내 한 줄을 제안했습니다. 요청에 없어 화면에는 넣지 않았습니다.

## 개발 조건

- 모델과 실행 도구: off와 같은 Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: off 화면을 복사한 폴더에서 국내 접근성 자료를 조회해 적용하는 절차를 켰습니다.
- 지시: 같은 요청서 기준으로 화면을 개선하게 했습니다. 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다. 질문하지 말고 개선까지 마치게 했습니다.
- 자료 조회: 설정 확인, 절차 문서, 자료 목록, 레코드 순서로 읽었습니다. 자료 조회 명령은 16회였고 모두 주소 하나에 명령 하나인 같은 형태였습니다. 조회에 실패한 주소는 없었습니다. KWCAG 레코드 13개와 NIA 사례 레코드 2개를 받았습니다. KWCAG 13개는 화면 종류와 관계없이 고르는 12개 항목(5.3.2, 5.4.1, 5.4.3, 5.4.4, 6.1.1, 6.1.2, 6.1.3, 6.4.2, 6.5.3, 7.1.1, 7.2.1, 8.1.1)과 5.3.1입니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 그래서 개발 에이전트는 코드와 명령으로만 확인했습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 그 밖의 명령과 일부 복합 명령은 거부됐습니다. 이 세션에서 거부된 호출은 3건(`grep`, `python3`, `sed`)입니다. 개발 에이전트는 마크업과 명도 대비를 계산하는 스크립트를 실행하지 못해 대비를 손으로 계산했다고 보고했습니다.
- 수정 요청: 검증에서 기능 결함이 나오지 않아 수정 요청을 보내지 않았습니다.
- 보존: on 개발 뒤에도 off 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행: 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었습니다. 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후): 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(이 문서, 2026-11-27 밤): 개발 절차를 ‘설정 확인’ 문서와 ‘절차’ 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했습니다. 자료 조회 명령은 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본입니다. 화면은 처음부터 다시 만들었습니다.

### NIA 제작기법 권장 사항

- 화면에 표가 있어 5.3.1의 사례 레코드 두 개를 읽었습니다. [NIA 1.3.1 적용 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-1.3.1-s4.json) · [NIA 1.3.1 개선 필요 사례](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-1.3.1-s5.json)
- 개발 에이전트는 이 사례를 기준으로 `caption`을 그대로 두었습니다. off가 `caption`을 `display: none`이 아니라 화면 밖 숨김 방식으로 제공하고 있었기 때문이라고 보고했습니다.

### 자료 밖 근거

- 가로 스크롤 영역의 `role="region"`, `aria-labelledby`, `tabindex="0"`은 WAI-ARIA와 HTML 표준 지식에 따른 것입니다. off 코드에 이미 있었고 on에서 바꾸지 않았습니다. [region 역할](https://www.w3.org/TR/wai-aria-1.2/#region) · [aria-labelledby](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby) · [HTML tabindex](https://html.spec.whatwg.org/multipage/interaction.html#attr-tabindex)

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
| --- | --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 18 | 0 / 0 / 19 |
| 주요 위반 규칙과 측정 대비 | `color-contrast` 1개 요소(`.basis`, 2.32:1) | 없음 |
| 휴관 칸 | ‘휴관’ 글자가 든 칸 4곳, 화면에 보이는 칸 0곳 | ‘휴관’ 글자가 든 칸 4곳, 화면에 보이는 칸 4곳 |
| 표 구조 | `caption`, `th` 11개(`scope` col 8개, row 3개), 본문 3행 | off와 같음 |
| 키보드 조작 | Tab 정지점 1곳(스크롤 영역), 초점 표시 있음 | off와 같음 |
| 320px 가로 스크롤 | 페이지 가로 스크롤 없음 | 페이지 가로 스크롤 없음 |
| 마크업 오류 | 0건 | 0건 |
| 콘솔 오류(초기 상태) | 0건 | 0건 |

### 브라우저에서 관찰한 결과

- on에서는 `color-contrast` 위반이 없었습니다. 통과 규칙은 18개에서 19개로 늘었습니다.
- ‘휴관’ 글자가 든 칸은 두 화면 모두 4곳이었습니다. 그 글자가 화면에 보이는 칸은 off 0곳, on 4곳이었습니다.
- 두 화면 모두 `caption` ‘분관별 요일 운영 시간’과 `th` 11개(`scope` col 8개, row 3개)가 있었고 본문은 3행이었습니다.
- 두 화면 모두 스크롤 영역은 `tabindex="0"`이었고 `aria-labelledby`가 `table-caption`을 가리켰습니다.
- 두 화면의 Tab 순서는 같았습니다. Tab을 한 번 누르면 표 스크롤 영역이 초점을 받았고 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- off와 on의 `index.html`은 휴관 칸 4줄만 다릅니다. off는 `<td class="closed"><span class="sr-only">휴관</span></td>`, on은 `<td class="closed">휴관</td>`입니다.
- `style.css`는 세 곳이 다릅니다. `td.closed`에 `color: #222`가 더해졌습니다. `.sr-only` 규칙이 없어졌습니다. `.basis`의 색이 `#aaaaaa`에서 `#595959`로 바뀌었습니다.
- 휴관 칸의 배경 `#fbdcdc`, 제목 셀 배경 `#e6e6e6`, 칸 테두리 `1px solid #ccc`, `caption`의 숨김 방식, 스크롤 영역의 속성과 윤곽선 규칙은 off와 같습니다.
- 개발 에이전트는 휴관 칸의 `#222`와 `#fbdcdc`를 약 12:1, 기준일 문구의 `#595959`와 흰 배경을 약 7.0:1로 손으로 계산했다고 보고했습니다.

## 미검증 항목

on 보고서가 브라우저에서 확인하라고 남긴 동작 가운데 기록이 없는 항목입니다.

- 320px에서 페이지 가로 스크롤이 없는 것은 확인했습니다. 표 영역이 실제로 가로 스크롤되는지는 기록하지 않았습니다.
- 표 영역이 Tab으로 초점을 받고 초점 표시가 있는 것은 확인했습니다. 윤곽선의 색과 방향키 스크롤은 기록하지 않았습니다.
- ‘휴관’ 글자가 화면에 보이는 것은 확인했습니다. 글자가 칸 안에서 잘리지 않고 한 줄로 보이는지는 기록하지 않았습니다.
- 스크린 리더 발화: 표가 표 제목으로 안내되는지, 휴관 칸을 행·열 제목과 함께 읽는지 확인하지 않았습니다.

그 밖에 확인하지 않은 항목입니다.

- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 고대비 모드에서 배경색이 사라질 때의 표시는 확인하지 않았습니다.

### 개발 중 읽지 못한 자료

- 보고서는 읽지 못한 주소가 없고, 읽은 레코드는 요약이나 잘라 읽기 없이 전문을 받았다고 적었습니다.
- 5.3.1 외 항목의 사례 레코드는 읽지 않았습니다. 보고서는 사례를 읽을 대상 요소가 이 화면에는 표뿐이라고 판단했습니다.
- 마크업과 명도 대비를 계산하는 스크립트는 실행하지 못했습니다. 보고서의 대비 수치는 손으로 계산한 값입니다.
