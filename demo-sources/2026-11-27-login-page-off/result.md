# 로그인 · 기본 개발 (off) 실행 결과

푸른숲도서관 회원 로그인 화면입니다. 예시 계정으로 로그인한 뒤 환영 화면에서 로그아웃합니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 요청서대로 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-login-page-on)에 있습니다.

확장 검사에서 보조 링크 세 개가 명도 대비 위반(2.32:1)으로 나왔습니다. 입력란에는 보이는 레이블이 없고 입력란 안의 안내 문구(placeholder)만 보입니다. 마크업 오류와 320px 화면의 가로 스크롤은 없었습니다.

## 사용 방법

- 아이디 `reader01`, 비밀번호 `green1234`를 입력하고 ‘로그인’을 누르면 환영 화면(`welcome.html`)으로 이동합니다.
- 환영 화면에서 ‘로그아웃’을 누르면 로그인 화면으로 돌아갑니다.
- 빈 칸으로 제출하거나 틀린 비밀번호를 넣으면 입력란 아래에 오류 문구가 나타납니다.
- 비밀번호 칸 오른쪽의 눈 모양 버튼으로 비밀번호를 보이거나 숨깁니다.
- 로그인 화면 아래의 ‘아이디 찾기 · 비밀번호 찾기 · 회원가입’ 링크는 요청서대로 주소가 `#`입니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 로그인’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 예시 계정으로 로그인하고 로그아웃합니다.
>
> 푸른숲도서관 회원 로그인 화면을 만들어 주세요. 예시 계정은 아이디 `reader01`, 비밀번호 `green1234`이고 화면 아래에 예시 계정을 안내합니다. 아이디나 비밀번호가 비었거나 틀리면 오류를 보여 주고, 맞으면 환영 화면(`welcome.html`)으로 이동합니다. 환영 화면의 ‘로그아웃’을 누르면 로그인 화면으로 돌아갑니다.
>
> 디자인 시안: 입력란 위에 별도 제목을 두지 않고 입력란 안의 안내 문구(‘아이디’, ‘비밀번호’)로 표시합니다. 비밀번호 칸 오른쪽 안쪽에 눈 모양 아이콘 버튼을 두어 비밀번호를 보이거나 숨깁니다. 로그인 버튼 아래 ‘아이디 찾기 · 비밀번호 찾기 · 회원가입’ 링크는 13px, `#aaaaaa`로 작게 둡니다. 이동할 페이지는 아직 없으니 주소는 `#`으로 둡니다. 오류가 나면 해당 입력란의 테두리를 빨간색으로 바꾸고 아래에 짧은 빨간 문구를 표시합니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행)
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 껐습니다.
- 지시: 요청서 전문을 주고, 질문하지 말고 구현을 마친 뒤 만든 파일과 판단이 필요했던 점을 보고하게 했습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. 개발 에이전트는 화면을 브라우저로 열어 보지 못했다고 보고했습니다.
- 수정 요청: 이 화면에서 기능 결함을 찾지 못해 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 자료 목록: 개발 에이전트는 개발 절차의 설정을 읽는 셸 명령과 같은 명령에서 국내 접근성 자료의 목록 페이지(KWCAG 2.2 검사항목 33개의 제목과 레코드 주소)를 한 번 받았습니다. 설정이 꺼져 있음을 확인한 뒤에는 검사항목 레코드를 읽지 않았습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 숨김 레이블 | 아이디와 비밀번호 입력란에 `label for`를 하나씩 연결하고, `.sr-only`로 화면에서만 숨겼습니다(`index.html`). | [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element) |
| 눈 모양 버튼의 이름과 상태 | 버튼에 `aria-label="비밀번호 표시"`를 달았고, 누를 때마다 `aria-pressed`를 `true`와 `false`로 바꿉니다. 아이콘 SVG는 `aria-hidden="true"`입니다(`index.html`, `login.js`). | [aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [aria-pressed](https://www.w3.org/TR/wai-aria-1.2/#aria-pressed), [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 오류 문구 연결 | 입력란마다 `aria-describedby`로 오류 문구 요소를 연결했고, 오류가 나면 `aria-invalid="true"`를 붙입니다(`index.html`, `login.js`). | [aria-describedby](https://www.w3.org/TR/wai-aria-1.2/#aria-describedby), [aria-invalid](https://www.w3.org/TR/wai-aria-1.2/#aria-invalid) |
| 오류 뒤 초점 이동 | 아이디가 비었거나 계정이 틀리면 아이디 칸으로, 비밀번호만 비었으면 비밀번호 칸으로 초점을 옮깁니다(`login.js`). | 해당 없음 |
| 자동 완성 | 아이디에 `autocomplete="username"`, 비밀번호에 `autocomplete="current-password"`를 지정했습니다(`index.html`). | [HTML 자동 완성](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill) |
| 초점 표시 | 입력란, 버튼, 링크의 `:focus-visible`에 3px 윤곽선을 그립니다(`style.css`). | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo) |
| 기본 언어 | 두 화면 모두 `<html lang="ko">`입니다. | [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- 계정이 틀리면 두 입력란을 모두 오류로 표시(빨간 테두리, `aria-invalid`)하고, 문구는 비밀번호 칸 아래에 한 번만 보여 줍니다. 개발 에이전트는 어느 쪽이 틀렸는지 알려 주지 않으려는 판단이라고 보고했습니다. 요청서는 해당 입력란의 테두리와 그 아래 문구를 요구했습니다.
- 입력란 위에 제목을 두지 않는 시안은 지켰고, 보조기술용 숨김 레이블을 더했습니다.
- 요청서에 없는 환영 화면의 페이지 제목(‘환영합니다 - 한국 웹 접근성 플레이그라운드’)과 설명 문장을 정했습니다.
- 로그인 상태는 `sessionStorage`에 저장합니다. 로그인하지 않고 `welcome.html`을 열면 `index.html`로 돌려보내도록 만들었습니다.

보조 링크의 13px, `#aaaaaa`는 요청서대로 두었습니다. 개발 에이전트는 흰 배경에서 대비가 낮다고 보고했지만 색을 바꾸지 않았습니다.

## 검증 결과

Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6(창 크기 1280×900)에 KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 위반 상세의 숫자는 그 규칙에 걸린 요소 수입니다.

| 확인 항목 | 결과 |
| --- | --- |
| 확장 검사: 초기 상태 | 1 / 0 / 24 |
| 확장 검사: 빈 값 제출 | 1 / 0 / 24 |
| 위반 규칙과 측정 대비 | color-contrast 3개 요소(보조 링크, 2.32:1). 두 상태에서 같습니다. |
| 키보드 조작 | Tab으로 초점이 차례로 이동했고, 초점을 받은 요소마다 초점 표시가 있었습니다. |
| 320px 가로 스크롤 | 없음 |
| 마크업 오류 | `index.html`, `welcome.html` 모두 0건 |
| 콘솔 오류 | 초기 상태 0건 |

### 브라우저에서 관찰한 결과

- 빈 값으로 제출하면 오류 문구가 나타났고, 초점이 아이디 칸으로 갔으며, 두 칸에 `aria-invalid`가 붙었습니다.
- 틀린 비밀번호로 제출하면 로그인 화면에 머물렀습니다.
- `reader01`, `green1234`로 로그인하면 `welcome.html`로 이동했습니다. ‘로그아웃’을 누르면 `index.html`로 돌아왔습니다. 이 흐름은 마우스로 확인했습니다.
- 입력란에는 보이는 레이블이 없고 placeholder만 보였습니다.

### 코드에서 확인한 사실

- 보조 링크는 `#aaaaaa`, 13px이고 평소에는 밑줄이 없습니다. 마우스를 올릴 때만 밑줄이 생깁니다.
- 계정이 틀리면 아이디 칸에도 `aria-invalid="true"`가 붙지만, 아이디 칸 아래 오류 문구는 비어 있습니다.
- 오류 문구 요소는 비어 있을 때 `display:none`으로 숨깁니다.

## 미검증 항목

- 스크린 리더 발화: 숨김 레이블, 눈 모양 버튼의 이름과 상태, 오류 문구를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 로그인하지 않고 `welcome.html`을 직접 열 때 로그인 화면으로 돌려보내는 동작은 확인하지 않았습니다.
- 브라우저 자동 완성과 비밀번호 관리자 연동, 화면 확대, 고대비 모드는 확인하지 않았습니다.
