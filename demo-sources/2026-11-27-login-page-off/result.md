# 로그인 · 기본 개발 (off) 실행 결과

푸른숲도서관 회원 로그인 화면입니다. 예시 계정으로 로그인한 뒤 환영 화면에서 로그아웃합니다. 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 끈 상태에서 화면 요청서만 주고 만들었습니다. 같은 요청서로 개선한 화면은 [접근성 자료 적용 (on)](/?demo=2026-11-27-login-page-on)에 있습니다.

확장 검사에서 보조 링크 세 개가 명도 대비 위반(2.32:1)으로 나왔습니다. 입력란의 레이블은 화면에서 숨겨져 있고 입력란 안의 안내 문구(placeholder)만 보입니다. 마크업 오류와 320px 화면의 가로 스크롤은 없었습니다.

## 사용 방법

- 아이디 `reader01`, 비밀번호 `green1234`를 입력하고 ‘로그인’을 누르면 환영 화면(`welcome.html`)으로 이동합니다. 예시 계정은 로그인 화면 아래에 적혀 있습니다.
- 환영 화면에서 ‘로그아웃’을 누르면 로그인 화면으로 돌아갑니다.
- 빈 칸으로 제출하거나 틀린 비밀번호를 넣으면 입력란 테두리가 빨간색으로 바뀌고 아래에 오류 문구가 나타납니다.
- 비밀번호 칸 오른쪽의 눈 모양 버튼으로 비밀번호를 보이거나 숨깁니다.
- 로그인 버튼 아래의 ‘아이디 찾기 · 비밀번호 찾기 · 회원가입’ 링크는 요청서대로 주소가 `#`입니다.

## 요청서

개발 에이전트에게 준 ‘화면 요청서: 로그인’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 예시 계정으로 로그인하고 로그아웃합니다.
>
> 푸른숲도서관 회원 로그인 화면을 만들어 주세요. 예시 계정은 아이디 `reader01`, 비밀번호 `green1234`이고 화면 아래에 예시 계정을 안내합니다. 아이디나 비밀번호가 비었거나 틀리면 오류를 보여 주고, 맞으면 환영 화면(`welcome.html`)으로 이동합니다. 환영 화면의 ‘로그아웃’을 누르면 로그인 화면으로 돌아갑니다.
>
> 디자인 시안: 입력란 위에 별도 제목을 두지 않고 입력란 안의 안내 문구(‘아이디’, ‘비밀번호’)로 표시합니다. 비밀번호 칸 오른쪽 안쪽에 눈 모양 아이콘 버튼을 두어 비밀번호를 보이거나 숨깁니다. 로그인 버튼 아래 ‘아이디 찾기 · 비밀번호 찾기 · 회원가입’ 링크는 13px, `#aaaaaa`로 작게 둡니다. 이동할 페이지는 아직 없으니 주소는 `#`으로 둡니다. 오류가 나면 해당 입력란의 테두리를 빨간색으로 바꾸고 아래에 짧은 빨간 문구를 표시합니다.

## 개발 조건

- 모델과 실행 도구: Claude Sonnet 5.5, Claude Code 2.1.332(헤드리스 실행). 개발 세션은 대화 턴 10회, 48초였습니다.
- 실행 위치: 이 저장소 밖의 빈 폴더입니다. 그래서 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 개발 절차: 국내 접근성 자료를 조회해 적용하는 절차를 꺼 두었습니다. 개발 에이전트는 절차의 설정을 확인하는 문서와 설정 값(off)만 읽었습니다. 절차 본문, 자료 목록, 검사항목 레코드는 한 번도 받지 않았습니다. 실행 기록에서 자료 조회가 0회임을 확인했고, 이번 실행의 off 세션 13개가 모두 같았습니다.
- 지시: 화면 요청서만 주었습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었고, 디자인 검사 플러그인을 껐습니다. 허용한 셸 명령은 `node`, `ls`, `cat`, `curl`, `mkdir`, `cp`입니다. 폴더를 옮긴 뒤 다른 명령을 잇는 복합 명령 1건이 거부됐고, 그 뒤에도 파일 네 개는 모두 만들어졌습니다. 개발 에이전트는 화면을 브라우저에서 실행해 확인하지 않았다고 보고했습니다.
- 수정 요청: 이 화면에는 기능 결함 수정 요청을 보내지 않았습니다.
- 보존: on 화면을 개발한 뒤에도 이 화면의 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 이 문서는 세 번째 실행의 결과입니다.
  1. 첫 실행에서는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침과 일반 지식에 따라 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. on 화면은 만들지 않았습니다.
  2. 두 번째 실행(2026-11-27 오후)에서는 모델과 실행 위치를 바꿔 다시 만들었습니다. off 개발 에이전트 13개 중 12개가 절차의 설정을 읽는 명령에서 자료 목록(검사항목 33개의 제목과 주소)을 함께 받았습니다. on 13개는 모두 일괄 내려받기 명령이 거부됐고, 일부는 필수 항목의 본문을 끝까지 읽지 못했습니다.
  3. 세 번째 실행(2026-11-27 밤)에서는 개발 절차를 설정 확인 문서와 절차 문서로 나눠 off 세션이 절차와 자료를 보지 않게 했고, 자료 조회 명령을 한 형태로 고정했습니다. 요청서는 두 번째 실행과 같은 확정본이고, 화면은 처음부터 다시 만들었습니다.

## 적용 기준

검사항목 레코드를 조회하지 않았으므로 KWCAG 항목을 근거로 적용한 처리는 없습니다. 개발 에이전트는 일반 지식으로 아래 처리를 넣었고, 모두 코드에서 확인했습니다. 근거 구분은 모두 자료 밖 근거(HTML, WAI-ARIA 등 웹 표준)입니다.

| 처리 | 코드에서 확인한 내용 | 웹 표준 |
| --- | --- | --- |
| 숨김 레이블 | 아이디와 비밀번호 입력란에 `label for`를 하나씩 연결하고, `.sr-only`로 화면에서만 숨겼습니다(`index.html`, `style.css`). | [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element) |
| 눈 모양 버튼의 이름과 상태 | 버튼에 `aria-label="비밀번호 표시"`와 `aria-pressed="false"`를 달았습니다. 누를 때마다 `aria-pressed`를 바꾸고 이름도 ‘비밀번호 숨기기’와 ‘비밀번호 표시’로 바꿉니다. 아이콘 SVG는 `aria-hidden="true"`입니다(`index.html`, `script.js`). | [aria-label](https://www.w3.org/TR/wai-aria-1.2/#aria-label), [aria-pressed](https://www.w3.org/TR/wai-aria-1.2/#aria-pressed), [aria-hidden](https://www.w3.org/TR/wai-aria-1.2/#aria-hidden) |
| 오류 문구 연결 | 입력란마다 `aria-describedby`로 오류 문구 요소를 연결했고, 오류가 나면 `aria-invalid="true"`를 붙입니다. 비밀번호 칸의 오류 문구 요소에는 `role="alert"`가 있습니다(`index.html`, `script.js`). | [aria-describedby](https://www.w3.org/TR/wai-aria-1.2/#aria-describedby), [aria-invalid](https://www.w3.org/TR/wai-aria-1.2/#aria-invalid), [alert 역할](https://www.w3.org/TR/wai-aria-1.2/#alert) |
| 오류 뒤 초점 이동 | 빈 칸이 있으면 비어 있는 첫 칸으로, 계정이 틀리면 아이디 칸으로 초점을 옮깁니다(`script.js`). | 해당 없음 |
| 자동 완성 | 아이디에 `autocomplete="username"`, 비밀번호에 `autocomplete="current-password"`를 지정했습니다(`index.html`). | [HTML 자동 완성](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill) |
| 초점 표시 | 입력란, 버튼, 링크의 `:focus-visible`에 3px 윤곽선을 그립니다(`style.css`). | [:focus-visible](https://www.w3.org/TR/selectors-4/#the-focus-visible-pseudo) |
| 조작 크기 | 입력란과 로그인 버튼의 높이가 48px이고 눈 모양 버튼은 48×48px입니다(`style.css`). 개발 에이전트는 ‘48px 터치 영역’을 직접 넣었다고 보고했습니다. | 해당 없음 |
| 기본 언어 | 두 화면 모두 `<html lang="ko">`입니다. | [HTML lang 속성](https://html.spec.whatwg.org/multipage/dom.html#attr-lang) |

### 요청서와 다르게 판단한 부분

- 계정이 틀리면 두 입력란을 모두 오류로 표시(빨간 테두리, `aria-invalid`)하고, 문구는 비밀번호 칸 아래에 한 번만 보여 줍니다. 개발 에이전트는 어느 쪽이 틀렸는지 알리지 않으려는 판단이라고 보고했습니다. 요청서는 해당 입력란의 테두리와 그 아래 문구를 요구했습니다.
- 입력란 위에 제목을 두지 않는 시안은 지켰고, 보조기술용 숨김 레이블을 더했습니다.
- 요청서에 없는 환영 화면의 제목(‘reader01님, 환영합니다’), 페이지 제목(‘환영합니다 - 한국 웹 접근성 플레이그라운드’), 설명 문장을 정했습니다.
- 로그인 상태 검사는 넣지 않았습니다. 개발 에이전트는 `welcome.html`에 직접 접속해도 열린다고 보고했습니다.

보조 링크의 13px, `#aaaaaa`는 요청서대로 두었습니다. 개발 에이전트는 흰 배경에서 명암비가 낮아 읽기 어렵다고 보고했지만 색을 바꾸지 않았습니다.

## 검증 결과

Playwright 1.66 스크립트가 실행한 헤드리스 Chrome 158.0.8127.37(창 크기 1280×900)에 KWCAG 검사 0.1.17 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 주입해 검사했습니다. 확장의 사이드 패널 화면은 쓰지 않았습니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 마우스와 키보드 조작은 사람이 아니라 스크립트가 보냈습니다. 규칙 수는 ‘위반 / 판정 보류 / 통과’ 순서이고, 요소 수가 아니라 규칙 종류 수입니다.

### 브라우저에서 관찰한 결과

- 빈 값으로 ‘로그인’을 누르면 로그인 화면에 머물렀고 ‘아이디를 입력해 주세요.’와 ‘비밀번호를 입력해 주세요.’가 나타났습니다. 초점은 아이디 칸으로 갔고 `aria-invalid`가 붙은 요소는 2개였습니다.
- 아이디 `reader01`과 틀린 비밀번호로 제출하면 로그인 화면에 머물렀고 ‘아이디 또는 비밀번호가 올바르지 않습니다.’ 한 문장이 나타났습니다. 초점은 아이디 칸으로 갔고 `aria-invalid`가 붙은 요소는 2개였습니다.
- 아이디와 비밀번호를 모두 틀린 값으로 넣은 별도 확인에서는 두 칸의 테두리 색이 `rgb(211, 47, 47)`이었습니다. 아이디 칸의 `aria-describedby`가 가리키는 요소에는 글자가 없었고, 비밀번호 칸은 오류 문구를 가리켰습니다.
- 올바른 비밀번호를 넣고 Enter를 누르면 `welcome.html`로 이동했고 제목 ‘reader01님, 환영합니다’가 보였습니다. 이동 직후 초점은 `body`에 있었습니다. ‘로그아웃’을 누르면 `index.html`로 돌아왔습니다.
- `welcome.html`을 주소로 직접 열면 환영 화면이 그대로 열렸습니다.
- 레이블 ‘아이디’, ‘비밀번호’는 화면에서 숨겨져 있었고 placeholder만 보였습니다. 아이디 칸에 글자를 입력한 뒤에도 레이블은 숨김 상태였습니다.

### 코드에서 확인한 사실

- 보조 링크는 `#aaaaaa`, 13px이고 밑줄이 없습니다(`text-decoration:none`). 구분점 `·`은 `aria-hidden="true"`인 `span`이고 색이 같습니다.
- 계정이 틀리면 아이디 칸에 빨간 테두리와 `aria-invalid="true"`만 붙이고, 아이디 칸 아래 문구 요소는 비워 둡니다.
- 계정 불일치 오류가 난 뒤 비밀번호 칸만 고치면 비밀번호 칸의 오류만 지우고, 아이디 칸의 빨간 테두리와 `aria-invalid`는 남깁니다(`script.js`의 `input` 처리).
- 오류 문구 요소는 평소 `hidden` 속성으로 숨깁니다. `role="alert"`는 비밀번호 칸의 문구 요소에만 있습니다.
- 로그인에 성공하면 `sessionStorage`에 `loggedIn` 값을 저장하지만, `welcome.html`은 이 값을 읽지 않고 로그아웃할 때 지우기만 합니다.
- placeholder 글자색은 `#6b6b6b`입니다.

## 미검증 항목

- 스크린 리더 발화: 숨김 레이블, 눈 모양 버튼의 이름과 상태, `role="alert"` 문구를 어떻게 읽는지 확인하지 않았습니다.
- 실제 터치 기기와 Chrome 이외의 브라우저에서는 확인하지 않았습니다.
- 눈 모양 버튼을 눌렀을 때 비밀번호가 보이는지와 `aria-pressed`, 이름이 바뀌는지는 브라우저에서 기록하지 않았습니다.
- 계정 불일치 오류 뒤 입력을 고칠 때 오류 표시가 남는 동작은 코드로만 확인했습니다.
- 빈 값 제출 상태의 320px 화면, 브라우저 자동 완성과 비밀번호 관리자 연동, 화면 확대, 고대비 모드는 확인하지 않았습니다.
