# 도서관 이용 안내 · 접근성 자료 적용 (on) 실행 결과

공통 헤더의 메뉴 10개와 검색, 회원 가입·대출·반납 안내 본문으로 이루어진 이용 안내 페이지입니다. 기본 개발 화면을 복사한 뒤, 국내 접근성 자료(KWCAG 2.2, NIA 제작기법)를 조회해 적용하는 개발 절차를 켜고 같은 요청서 기준으로 개선했습니다.

비교 대상인 기본 개발 화면은 [도서관 이용 안내 · 기본 개발 (off)](/?demo=2026-11-27-library-guide-off)에서 볼 수 있습니다.

## 사용 방법

1. 페이지를 열고 Tab 키를 처음 누르면 왼쪽 위에 ‘본문 바로가기’ 링크가 나타납니다. Enter를 누르면 본문으로 이동합니다.
2. 헤더에는 텍스트 로고 ‘푸른숲도서관’, 검색 입력란과 돋보기 버튼, 메뉴 10개가 있습니다. 로고와 메뉴의 주소는 `#`입니다.
3. 메뉴 글자는 off보다 진한 회색(`#6b6b6b`)입니다. 현재 메뉴 ‘이용 안내’는 초록색 굵은 글씨로 표시됩니다.
4. 검색 양식은 제출해도 아무 동작을 하지 않습니다.
5. 본문은 ‘이용 안내’ 제목 아래 ‘회원 가입’, ‘대출’, ‘반납’ 소제목과 문단으로 이루어지고, 아래에 도서관 주소가 있는 푸터가 있습니다.

## 요청서와 조정한 부분

‘화면 요청서: 도서관 이용 안내’의 전문입니다.

> ### 공통 사항
>
> 가상의 기관 ‘푸른숲도서관’(전시 일정은 ‘푸른숲미술관’)의 화면입니다. HTML, CSS, JavaScript만 쓰고 외부 라이브러리와 CDN은 쓰지 않습니다. 모든 파일은 지정한 데모 폴더 안에 두고, 진입 페이지는 `index.html`입니다. 페이지 제목은 `<화면 이름> - 한국 웹 접근성 플레이그라운드`, 설명(meta description)은 요청서에 적은 문장을 씁니다. 데스크톱과 폭 320px 화면에서 모두 쓸 수 있어야 합니다. 결과 문서는 다른 담당자가 쓰므로 만들지 않습니다.
>
> ### 요청 내용
>
> 설명: 공통 메뉴와 검색이 있는 이용 안내 페이지입니다.
>
> 공통 헤더에 텍스트 로고 ‘푸른숲도서관’, 메뉴 10개(도서관 소개, 이용 안내, 자료 검색, 전자도서관, 프로그램, 열람실, 공지사항, 자주 묻는 질문, 오시는 길, 마이페이지), 검색이 있습니다. 메뉴 주소는 `#`입니다. 본문은 ‘이용 안내’ 제목 아래 ‘회원 가입’, ‘대출’, ‘반납’ 소제목과 소제목마다 두 문단입니다. 아래에 도서관 주소가 있는 푸터를 둡니다.
>
> 디자인 시안: 헤더 검색은 입력란(안내 문구 ‘검색어 입력’)과 돋보기 아이콘 버튼입니다. 메뉴 글자는 15px `#8a8a8a`, 현재 메뉴(이용 안내)는 초록색입니다. 시안에 그려진 요소 외에는 화면에 보이지 않게 해 주세요.

요청자는 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 미리 승인했습니다. 개발 에이전트가 조정한 내용과 보고서에 적은 이유는 다음과 같습니다. 이번 개선에서 바뀐 파일은 `style.css` 하나입니다.

| 요청서 또는 off 화면 | on 화면 | 보고서에 적은 이유 |
|---|---|---|
| 메뉴 글자 15px `#8a8a8a` | 15px `#6b6b6b` | 흰 배경에서 4.5:1에 못 미침(5.4.3). 15px 보통 굵기라 3:1 완화 기준도 해당하지 않음 |
| 안내 문구 ‘검색어 입력’의 색 지정 없음 | `#6b6b6b`과 `opacity: 1`로 지정 | 브라우저 기본 색에 기대지 않기(접근성 개선) |
| 시안에 없는 ‘본문 바로가기’와 숨긴 레이블(off에서 추가) | 그대로 유지 | 반복 영역 건너뛰기(6.4.1)와 레이블 제공(7.3.2)에 필요 |

- 보고서는 6.4.1 본문이 메뉴 건너뛰기 링크를 화면에 보이게 하라고 한다고 적었습니다. 링크를 평소에도 보이게 할지는 요청자가 정할 사항으로 남겼습니다.
- 숨긴 레이블은 보이는 안내 문구와 같은 글자 ‘검색어 입력’입니다.
- 현재 메뉴의 초록 `#1b7a3a`, 로고, 검색 입력란과 돋보기 버튼, 메뉴 15px, 메뉴 주소 `#`은 요청서대로 두었습니다.
- 보고서는 접근성과 무관한 기능 결함을 찾지 못했다고 적었습니다.

## 개발 조건

- 출발점: off 화면을 복사한 뒤 국내 접근성 자료를 조회해 적용하는 절차를 켜고 같은 요청서 기준으로 개선했습니다.
- 충돌 처리: 요청서 시안이 KWCAG 요구사항과 충돌하면 요구사항을 우선하도록 요청자가 미리 승인했습니다.
- 모델과 실행 방식: Claude Sonnet 5.5를 Claude Code 2.1.332에서 헤드리스로 실행했습니다.
- 작업 위치: 저장소 밖의 빈 폴더에서 실행했습니다. 이 저장소의 프로젝트 지침은 읽지 않았습니다.
- 도구: 브라우저 도구와 MCP 서버가 없었습니다. 디자인 검사 플러그인은 껐습니다.
- 셸 명령: 허용한 명령 범위가 좁아 일부 복합 명령이 거부됐습니다. Python 실행이 막혀 명도 대비는 도구로 계산하지 못했습니다.
- 개발 중 확인: 개발 에이전트는 브라우저로 화면을 열지 못했고 코드만 점검했다고 보고했습니다.
- off 파일 보존: on 개발 뒤에도 off 파일이 바뀌지 않았음을 해시로 확인했습니다.
- 재실행: 처음에는 다른 모델(Claude Opus 5.5)로 이 저장소 안에서 off 화면 13개를 만들었습니다. 13개 모두 확장 검사 위반이 0건이었고, 개발 에이전트들은 이 저장소의 프로젝트 지침(AGENTS.md)과 일반 지식에 따라 요청서의 시안을 접근성 기준에 맞춰 바꿨다고 보고했습니다. 프로젝트 지침과 모델의 영향을 줄이려고 모델과 실행 위치를 바꿔 처음부터 다시 만들었고, 이 문서는 다시 만든 결과입니다. 첫 실행에서는 on 화면을 만들지 않았습니다.

## 적용 기준과 참고 자료

근거 구분은 개발 에이전트의 보고서를 따릅니다. 보고서는 읽은 레코드의 KWCAG 본문을 기준으로 판단했다고 적었습니다.

### KWCAG 2.2 요구사항

- 메뉴 글자색을 고쳤습니다. [5.4.3 텍스트 콘텐츠의 명도 대비](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.3.json)
- 문서 맨 앞의 건너뛰기 링크가 본문(`main`)으로 이동합니다. [6.4.1 반복 영역 건너뛰기](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.4.1.json)
- `label for="q"`로 입력란에 레이블을 연결했습니다. [7.3.2 레이블 제공](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-7.3.2.json)
- 보이는 글자가 있는 메뉴와 로고는 이름이 그 글자와 같습니다. 돋보기 버튼은 보이는 글자가 없어 적용 대상이 아니라고 판단했습니다. [6.5.3 레이블과 네임](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.5.3.json)
- 초점 순서가 로고, 검색, 메뉴, 본문입니다. `:focus-visible`로 3px 파란 윤곽선이 보입니다. [6.1.2 초점 이동과 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.2.json)
- 현재 메뉴를 색 외에 굵기와 `aria-current="page"`로도 표시합니다. [5.4.1 색에 무관한 콘텐츠 인식](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.1.json)
- 링크 글자가 목적지를 설명합니다. [6.4.3 적절한 링크 텍스트](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.4.3.json)
- 초점만으로 실행되는 기능과 새 창이 없습니다. [7.2.1 사용자 요구에 따른 실행](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-7.2.1.json)
- 헤더 아래 테두리와 푸터 배경색으로 영역을 구분합니다. [5.4.4 콘텐츠 간의 구분](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.4.4.json)
- `<html lang="ko">`입니다. [7.1.1 기본 언어 표시](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-7.1.1.json)
- 메뉴 링크에 안쪽 여백(상하 6px, 좌우 8px)을 두고 링크 사이에 간격을 두었습니다. 보고서는 이 항목을 본문이 ‘바람직하다’로 쓴 권장 수준으로 구분했습니다. [6.1.3 조작 가능](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.3.json)

보고서는 다음 항목도 읽었고 문제를 찾지 못했다고 적었습니다.

- 돋보기 SVG는 장식으로 처리했고 버튼에 `aria-label="검색"`이 있습니다. [5.1.1 적절한 대체 텍스트 제공](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.1.1.json)
- 문서 순서와 화면 순서가 같습니다. [5.3.2 콘텐츠의 선형구조](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-5.3.2.json)
- 모든 조작 요소가 링크, 입력란, 버튼입니다. [6.1.1 키보드 사용 보장](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.1.1.json)
- 페이지 제목이 요청서 형식과 같습니다. [6.4.2 제목 제공](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-6.4.2.json)
- `id`가 중복되지 않습니다. [8.1.1 마크업 오류 방지](https://kwcag-docs.fe4all.dev/browse#v1/criteria/kwcag-8.1.1.json)

### NIA 제작기법 권장 사항

보고서는 NIA 제작기법을 근거로 적용한 항목을 따로 적지 않았습니다. 5.4.3과 6.5.3의 기본 규칙은 읽었다고 적었습니다. [NIA 1.4.3 기본 규칙](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-1.4.3-s3.json), [NIA 2.5.3 기본 규칙](https://kwcag-docs.fe4all.dev/browse#v1/criteria/nia-2.5.3-s3.json)

### 자료 밖 근거

- `role="search"` 양식, `nav`의 `aria-label`, `aria-current`, 화면에서 숨긴 레이블은 WAI-ARIA와 HTML 표준 지식으로 구현했습니다. [WAI-ARIA 1.2 search 역할](https://www.w3.org/TR/wai-aria-1.2/#search), [WAI-ARIA 1.2 aria-current](https://www.w3.org/TR/wai-aria-1.2/#aria-current), [HTML label 요소](https://html.spec.whatwg.org/multipage/forms.html#the-label-element)
- 명도 대비 수치는 개발 에이전트가 손으로 계산했고 도구로 검증하지 않았습니다.

## 검증 결과

확장 검사는 Playwright MCP 0.0.86이 실행한 Chrome 159.0.8154.6에서 했습니다. KWCAG 검사 0.1.16 확장의 검사 스크립트(axe-core 4.14.1 포함)를 확장과 같은 순서로 페이지에 주입했고, 확장의 사이드 패널 화면은 쓰지 않았습니다. 창 크기는 1280×900입니다. 마크업은 확장의 마크업 검사와 같은 html-validate 10.17.1 규칙으로 검사했습니다. 키보드 조작과 폭 320px 확인도 같은 브라우저에서 했습니다.

| 확인 항목 | 기본 개발 (off) | 접근성 자료 적용 (on) |
|---|---|---|
| 초기 상태 확장 검사(위반 / 판정 보류 / 통과 규칙 수) | 0 / 2 / 27 | 0 / 1 / 28 |
| 위반·판정 보류 규칙 | 판정 보류 `color-contrast` 9개 요소(메뉴 글자), `audit-skip-link` | 판정 보류 `audit-skip-link` |
| 메뉴 글자색(코드) | `#8a8a8a` | `#6b6b6b` |
| 첫 Tab | ‘본문 바로가기’ | 같음 |
| 키보드 조작 | Tab 순서대로 초점 이동, 초점 표시 있음 | off와 같은 순서 |
| 폭 320px 가로 스크롤 | 없음 | 없음 |
| 마크업 오류 | 0건 | 0건 |

### 브라우저에서 관찰한 결과

- 두 화면 모두 첫 Tab에서 ‘본문 바로가기’가 초점을 받았고, Tab 순서가 같았습니다.
- 두 화면의 차이는 메뉴 글자 대비였습니다. off에서 판정 보류였던 `color-contrast`가 on에서는 판정 보류로 나오지 않았습니다.
- 두 화면 모두 초점을 받은 요소마다 윤곽선 또는 그림자 초점 표시가 있었습니다.

### 코드에서 확인한 사실

- off와 on의 `index.html`은 같습니다.
- `style.css`에서 메뉴 글자색이 `#6b6b6b`으로 바뀌었고, 검색 입력란 안내 문구에 `color: #6b6b6b`과 `opacity: 1`이 추가됐습니다.
- ‘본문 바로가기’ 링크는 여전히 초점을 받을 때만 화면에 나타납니다.

## 미검증 항목

- 스크린 리더 발화: 검색 입력란을 ‘검색어 입력’으로 읽는지, 현재 메뉴 표시를 읽는지 확인하지 않았습니다.
- ‘본문 바로가기’를 Enter로 눌렀을 때 초점이 본문으로 옮겨지는지는 브라우저에서 확인하지 않았습니다.
- 바뀐 메뉴 글자와 안내 문구의 명도 대비 측정값은 기록하지 않았습니다.
- 실제 터치 기기, Chrome 외 브라우저, 화면 확대 상태는 확인하지 않았습니다.
- 개발 중 읽지 못한 자료: 보고서는 읽지 못한 주소가 없고 KWCAG 레코드 16개를 읽었다고 적었습니다. 기본 규칙은 5.4.3과 6.5.3만 읽었고 사례 레코드는 읽지 않았습니다. 그래서 건너뛰기 링크를 항상 보이게 할지에 대한 사례 해석은 확인하지 못했습니다. 보고서는 기본 규칙과 사례를 일부만 읽은 이유를 적지 않았습니다. 개발 중에는 여러 레코드를 한 번에 내려받거나 읽는 복합 명령 일부가 셸 명령 제한으로 거부됐습니다.
